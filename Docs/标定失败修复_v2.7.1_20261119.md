# 标定失败修复 + 液位慢跟踪（v2.7.1-B3）

- 日期：2026-11-19
- 固件：`SENSOR-NODE v2.7.1-B3`
- 构建：`text 84564 / data 480 / bss 11440`，0 error / 0 warning
- 基于：`v2.7.0-B3`

---

## 1. 现场日志暴露的真实原因

上电日志确认固件是 v2.7.0-B3：

```
# [BOOT] SENSOR-NODE v2.7.0-B3
# AUTOCAL state=DRY reason=empty
# AUTOCAL state=SETTLE reason=water
# BASELINE SLOT DRAIN ec0=319.9mV
# AUTOCAL state=SETTLE reason=calib_recover
# BASELINE SLOT RECOVER ec0=391.2mV
# AUTOCAL state=SETTLE reason=calib_full
# AUTOCAL state=DONE reason=water_unconfirmed   ← FULL 段失败
```

也就是说：

- DRAIN 槽采到 **319.9 mV**；
- RECOVER 槽采到 **391.2 mV**；
- **FULL 段没有采到**，63 s 后因失水 `water_unconfirmed` 结束。

但 v2.7.0 的代码在 FULL 失败后仍把 `g_cal_multi_slot` 留在 `true`，导致：

```
app_baseline_task() 一直 return
→ 运行时不再选槽
→ 用户手工 W 得到 346 mV 单基线
→ 346 同时用于 DRAIN≈346 和 RECOVER≈418 两个平台
→ dEC 在 0 附近来回跨阈值 → CLEAR↔UNCERT 横跳
```

日志里 `NOBASE` 持续 587 行，之后才出现 346 mV 单基线，正是这个过程。

**所以不是阈值太紧，而是 FULL 失败把槽选择锁死了。**

---

## 2. v2.7.1 修复

### ① 任何 DONE 都恢复槽选择

`app_autocal_enter(APP_AC_DONE, …)` 现在强制：

```c
g_cal_multi_slot = false;
```

成功、部分成功、失败、超时，都会恢复 `app_baseline_task()`。

同时在 DONE 时打印三条槽：

```
# SLOTS DRAIN=319.9 RECOVER=391.2 FULL=INVALID
```

### ② FULL 段不再拖死整个标定

- FULL 段最多等 **15 s**；
- 等不到满水/流动 → 保留 DRAIN/RECOVER 两槽，DONE；
- 失水 → 直接 DONE，保留前两槽；
- 串口原因：
  - `full_timeout`
  - `full_no_water`

### ③ 液位慢跟踪

标定和运行之间液位会漂：

```
标定 DRAIN=319.9 / RECOVER=391.2
运行 DRAIN=346   / RECOVER=418
```

固定槽会偏 26 mV。新增 `app_baseline_trim_task()`：

```
条件：
  regime=MEASURE
  非屏蔽窗
  gate.stable
  |dNTU| ≤ 5%
  d1 ≤ |dEC| ≤ 45 mV

动作：
  active EC0 以 4 mV/s 拉向当前 EC
```

- 清水液位漂移：慢慢跟上，dEC 回到 0；
- 肥皂：dNTU 会升过 5%，跟踪立即停止；
- 不修改阈值，不把肥皂放过。

### ④ 槽距离上限 45 → 30 mV

槽与当前 EC 相差 >30 mV 时不再强行选槽，避免用错槽。

---

## 3. 对当前数据的预期

标定只得到 319.9 / 391.2，运行平台 346 / 418：

1. 部分标定 DONE 后，`g_cal_multi_slot=false`；
2. 运行时选 DRAIN 槽（319.9）或 RECOVER 槽（391.2）；
3. 清洁稳定后，EC0 以 4 mV/s 追到 346 / 418；
4. dEC 回到 0，CLEAR 稳定；
5. 若 dNTU 升高（肥皂），停止跟踪并判 L2。

---

## 4. 验证

烧录后重点看：

```
# [BOOT] SENSOR-NODE v2.7.1-B3
# BASELINE SLOT DRAIN ec0=…
# BASELINE SLOT RECOVER ec0=…
# CAL FULL timeout / full_no_water   （若没保持满水）
# SLOTS DRAIN=… RECOVER=… FULL=INVALID
# BASE slot=DRAIN/RECOVER ec0=… ec=…
```

- 清水：应逐步从 `UNCERT` 收敛到 `CLEAR`，不再 2 s 横跳；
- 肥皂：`dNTU` 升高，跟踪停止，应 `SOAP/L2`；
- 若一直 `NO_SLOT`：槽与当前 EC 差 >30 mV，需要重新标定或长按跳过。
