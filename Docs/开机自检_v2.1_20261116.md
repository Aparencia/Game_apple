## 1. 为什么能自动、为什么不会重演“回收空气”

旧固件的问题是在**空气里采“水中基线”**：空气 58 mV 被当成 EC0，于是空腔 `ΔEC≈0` → 判清水 → 回收空气。

v2.1 把标定拆成两件物理上可以自动完成的事：

| 步骤 | 采什么 | 为什么安全 |
|---|---|---|
| ① 默认干态 | 先用现场实测默认值（EC_DRY=60 mV、AO_DRY=2337 mV） | 只用于“电极有没有被水淹到”的绝对门限；**没有水中基线时工况仍是 FAULT/DRY，阀恒排空** |
| ② 自动干态 | 上电后 10 s 采空腔均值（EC/AO） | 空腔在空气里采“空气参考”本来就是正确做法；它只用于浸没判据 |
| ③ 等水 | 监视 EC，直到 `EC ≥ EC_DRY + 80 mV` 并连续 800 ms | 没水就永远不采水中基线；空腔/水位低于电极都会停在 DRY 排空 |
| ④ 自动湿态 | 确认浸没后采 2 s 水中基线，过 CV/量程/差值校验 | 这时电极确实在水里；校验失败最多重试 3 次，仍失败保持 FAULT/排空 |

**结构性保证**：`decision` 只有在 `REGIME_MEASURE` 且 `level==L0` 时才输出 `RECOV`，而 `MEASURE` 的必要条件之一是“基线有效”。自检全程没有合法基线 → 不可能回收。

> **上电时腔里已经有水怎么办？** 此时无法实测干态，自检会用两道证据确认“腔里是水体而不是一层水膜”：
> `EC ≥ EC_DRY + 80 mV` **且** `浊度 AO ≥ AO_DRY + 80 mV`
> （本装置实测：清水 EC≈348 mV、AO≈2639 mV；空腔 EC≈23 mV、AO≈2241 mV —— **水 AO 比空气高**）。
> 两条都满足才自动采湿态；只满足一条（例如电极只是被淋湿，AO 仍是空气值）就停在
> `Auto fail / Send W in clean water`，等人工 `W`。

## 2. 上电后会看到什么（串口 + OLED）

### 2.1 空腔上电

```
# AUTOCAL enabled: dry(10s) -> wait water -> wet baseline (no input needed)
# AUTOCAL state=DRY reason=empty
# DRY start (auto): chamber MUST be EMPTY, capture 10000ms (200 samples)
# DRY OK ec_dry=…mV ao_dry=…mV cv=…% n=200
# AUTOCAL state=WAIT_WATER reason=dry_ok
# GATE … regime=DRY …
```

OLED P1：大字“待机”，第二行 `Auto dry 37/200`（提示 `Keep chamber empty`）→ 采完后
`Auto wait water`（提示 `Pour water over probe`），再之后 `Dry No water`。

### 2.2 注水（淹过电极）

```
# GATE … regime=FAULT reason=NO_BASE …
# AUTOCAL state=SETTLE reason=water
# BASELINE start n=40
# BASELINE OK ec0=…mV dry=…mV ratio=…
# AUTOCAL state=DONE reason=base_ok
# GATE … regime=LOCKOUT → DRY → SETTLE → MEASURE
```

注水后约 **1 s 开始采基线、2 s 采完、再 4~6 s 进入 MEASURE**（LOCKOUT 3 s + DRY 0.5 s + SETTLE 4~6 s）。
OLED 自检阶段显示 `Auto water ok` / `Auto calib`，完成后恢复正常水质页。

### 2.3 上电时腔里已经有水

自检先用默认干态判“已浸没”，但因为干态没实测，**不会直接采湿态**：
先尝试干态采集（会被“腔非空”拒绝），随后用 `EC ≥ EC_DRY+80 mV` + `AO ≥ AO_DRY+80 mV`
两道证据确认水体（本装置水 AO 高于空气，方向与常见模块相反）：

- 两条都满足 → 自动采湿态（`reason=chamber_wet_confirm`）；
- 任一不满足 → `# AUTOCAL state=DONE reason=water_unconfirmed`，OLED 显示
  `Auto fail` + `Send W in clean water`，阀保持排空，等人工 `W`；之后每 5 min 会自动再试一次。

> v2.3 起不再要求“EC0≥400 mV”，现场 348 mV 的清水也能在“上电已有水”时自动标定。

### 2.4 自检失败

| 串口 | 含义 | 行为 |
|---|---|---|
| `# AUTOCAL state=RETRY reason=base_retry` | 湿态校验失败（水没淹到/水在晃/EC0 超 1600） | 8 s 后重试，最多 3 次 |
| `# AUTOCAL state=DONE reason=base_fail` | 3 次都失败 | 保持 FAULT/排空；OLED `Auto fail` + `Send W in clean water`；每 5 min 再试 |
| `# AUTOCAL state=DONE reason=wet_timeout` | 采集超时（主循环被拖慢/传感器异常） | 同上 |
| `# AUTOCAL state=DONE reason=water_unconfirmed` | 上电已有水，但 EC/AO 两道证据不足 | 同上；确认是干净水后手动 `W` |
| `# AUTOCAL state=WAIT_WATER reason=dry_default` | 干态采集失败但读数一直是“干”的 | 用默认干态继续等水 |

### 2.5 串口 `# TIP` 摘要（v2.1.1，每 2 s 一行）

CSV 是 17 列数字，现场不容易一眼看懂；`# TIP` 用一句话给出“现在什么工况、下一步做什么”：

```
# TIP t=123456ms | regime=DRY state=WAIT level=L1 permit=0 | EC=57.3mV g=0.000 dEC=0.0mV dNTU=0.0% T=29.1C | autocal=Auto wait water | no water at electrode: pour water over the probe
# TIP t=125456ms | regime=MEASURE state=CLEAR level=L0 permit=1 | EC=1492.3mV g=1.001 dEC=2.0mV dNTU=2.1% T=29.1C | autocal=DONE | clean water: RECOVER
```

- 以 `#` 开头，和 CSV 交替输出，PC 脚本可直接忽略；
- 字段：`regime / state / level / permit / EC(mV25) / g / dEC / dNTU% / 水温 / 自检阶段 / 下一步提示`；
- 提示语覆盖：没水、自检中、未标定、传感器故障、稳定期、换向屏蔽、清水回收、拿不准排空、脏水排空。

## 3. 参数（`app_main.c` 顶部集中可调）

| 宏 | 默认 | 说明 |
|---|---|---|
| `APP_AUTOCAL_ENABLE` | 1 | 0=关闭自检，回到手动 D/W |
| `APP_AUTOCAL_DRY_MS` | 10000 | 自检干态采集时长（手动 `D` 仍是 60 s） |
| `APP_AUTOCAL_WATER_MS` | 800 | 检测到浸没后稳定多久再采湿态 |
| `APP_AUTOCAL_RETRY_MS` | 8000 | 湿态失败重试间隔 |
| `APP_AUTOCAL_WET_TRIES` | 3 | 湿态最多尝试次数 |
| `APP_AUTOCAL_WET_TIMEOUT` | 8000 | 单次湿态采集兜底超时（标称 2 s） |
| `APP_AUTOCAL_FAIL_RETRY_MS` | 300000 | 自检失败后的低频重试间隔（5 min） |
| `APP_EC_DRY_DEFAULT_MV` | 60 | 默认干态 EC（现场实测 23~58 mV） |
| `APP_AO_DRY_DEFAULT_MV` | 2337 | 默认干态 AO（现场空气实测约 2241~2337 mV） |
| `ec_wet_delta_mv` | 80 | EC ≥ EC_DRY + 80 mV 才算有水（v2.3） |
| `ao_water_delta_mv` | +80 | 水 AO ≥ AO_DRY + 80 mV；本机水 AO 高于空气，方向相反时设负值 |
| `ec0_default_min_mv` | 150 | 默认干态时水中基线下限（v2.3 由 400 下调） |
| `settle_ms` | 4000 | 入水稳定期 |
| `settle_min_ms` | 1500 | 自适应提前的最早时间（v2.4） |
| `settle_stable_ms` | 500 | 连续稳定多久可提前进 MEASURE |
| `settle_timeout_ms` | 6000 | SETTLE 兜底，避免水流不停时永远停在待机 |

同时把基线量程从 2000 mV 收紧到 **1600 mV**（`ec0_max_mv`，pipeline 与 gate 两处一致）：

- 现场清水约 348 mV，能通过；
- 探头开路伪值约 1649~1650 mV，**会被判 BASE_HIGH 拒绝**（方案 §12 本来就要求排除它，2000 的上限其实没排除）；
- 肥皂水/脏水本底通常更高，也会被拒 → 自检不会把脏水当清水基线。

## 4. 手动覆盖仍然保留

| 命令 | 行为 |
|---|---|
| `D` | 中止自检，手动采 60 s 干态（来源升级为 MEASURED） |
| `W` / `B` | 中止自检，手动采 2 s 湿态 |
| `Z` | 清湿态基线并**停止自检**（不会立刻用水重标，避免把当时脏水存成本底）；需 `W` 或重新上电 |
| `G` / `P` | 查看 `src=DEFAULT/MEASURED`、自检阶段 |
| `V1/V0/VA` | 手动阀（调试） |

## 5. 已知限制（必须写进报告）

1. **没有 Flash 持久化**：每次上电都要重跑自检（约 10 s 干态 + 等水）。真正的“免标定”要等 P2-1 把干态/湿态写进数据 Flash。
2. **自动湿态假设“第一股水是干净水”**：如果上电后先放进脏水/肥皂水，采到的基线就是脏水的。后果是之后更干净的水被判 `TOO_CLEAN` 而排空（**欠回收，不会误回收**）；需要干净水时手动 `W` 重标。
3. **EC0 > 1600 mV 的水会被拒**（含开路伪值）：极硬水/浓皂液可能触发 `BASE_HIGH`，属安全侧；可按现场水样调整 `ec0_max_mv`。
4. **上电时腔里已有水**：因无法实测干态，自动采湿态要求 `EC ≥ EC_DRY+80 mV` **且** `AO ≥ AO_DRY+80 mV` 两道证据；只满足一条会停在 `Auto fail / Send W in clean water`，需要一次人工 `W`（或等 5 min 低频重试/断电重来）。v2.3 起不再要求 EC0≥400 mV，本机 348 mV 的清水可直接自动标定。
5. **浊度在“默认干态”路径参与判据**：用于确认“腔里是水体而不是水膜”；干态实测（MEASURED）后仍以 EC 为主，浊度按 v2 规则参与 L0 否决/L2 充分条件。
6. **自检期间阀恒排空**：这是设计，不是故障。

## 6. 现场验收（5 分钟）

1. **空腔上电**：OLED 出现 `Auto dry n/200`（提示 `Keep chamber empty`）；10 s 后 `Auto wait water`；`# VALVE count` 不增长。
2. **注水淹过电极**：约 1 s 后 `Auto water ok` → `Auto calib`；串口出现 `# BASELINE OK`。
3. **等 4~6 s**：`# GATE regime=MEASURE`，OLED 恢复正常水质页；干净水约 1.2 s 后 `CLEAR/RECOV`。
4. **抽水到电极以下**：≤300 ms 转 `DRY`，阀排空。
5. **拔探头**：`regime=FAULT reason=SENSOR`、`note=SENS`，阀排空。
6. **断电重启**：自检重跑；空腔时不会回收（与第 1 条一致）。
7. **上电时腔里已有水**：若 EC/AO 两道证据都满足，约 1 s 后自动 `BASELINE OK`；否则 OLED 显示 `Auto fail` + `Send W in clean water`，发 `W` 后应正常。
8. **擦干电极但腔里有残水**：不得自动采湿态（应停在 `water_unconfirmed`），阀保持排空。

## 7. 故障排查：还是停在“故障 NO_CAL”？

v2.1 起，只要上电自检跑起来，`NO_CAL` 最多出现 1~2 个 tick（第一帧），随后会变成 `DRY` 或 `AUTO …`。如果一直 `NO_CAL`：

1. 串口有没有 `# AUTOCAL enabled` 这一行？没有 → 烧的还是 v2.0 或更早的固件。
2. 有没有 `# AUTOCAL state=DRY reason=empty`？没有 → 自检没启动（检查 `APP_AUTOCAL_ENABLE`、是否手动按过 D/W 把它取消了）。
3. 有 `# ERR: chamber is NOT empty` → 腔里有残水，排空再上电。
4. 有 `# DRY REJECT` / `# DRY ABORT` → 干态采样不稳或传感器状态不对，发 `G` 看 `src=` 与传感器状态。
5. 屏幕/串口出现 `Auto fail` / `state=DONE reason=water_unconfirmed` → 按一次 `W`（电极须浸没、水须干净）。
6. 一直停在 `DRY`/待机、但腔里有清水 → 看 `G` 的 `src=`、`ec_dry`、`ec0`：v2.3 要求 `ec0 ≥ ec_dry+80 mV`；若 `ec_dry` 被残水抬得过高，擦干电极后重新上电/按 D。
7. 什么都不打印 → 串口命令/日志通道问题（先发 `H`）。
