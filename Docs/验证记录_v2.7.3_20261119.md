# v2.7.3-B3 现场清水验证记录（2026-11-19）

## 1. 标定结果

```
# BASELINE SLOT DRAIN   ec0=343.5mV
# BASELINE SLOT RECOVER ec0=406.5mV
# SLOTS DRAIN=343.5 RECOVER=406.5 FULL=INVALID
# AUTOCAL state=DONE reason=full_timeout
```

- 两槽都成功；
- FULL 仍 INVALID：满水 EC 没有超过 `max(343.5,406.5)+10=416.5 mV`，
  说明没有独立 FULL 平台，15 s 超时后保留两槽是正确行为。

运行时的槽选择：

```
# BASE slot=DRAIN   ec0=343.5mV ec=340.0mV
# BASE slot=RECOVER ec0=406.5mV ec=407.7mV
# BASE slot=DRAIN   ec0=343.5mV ec=324.0mV
```

两槽都真正被激活，DRAIN/RECOVER 不再共用 346 单基线。

---

## 2. 稳定性

从 52.4 s 到 68.6 s：

```
CLEAR / L0 / RECOV / OK   连续 14.6 s
EC 388.8~410.0 mV
dEC -11.0~+1.1 mV
```

没有再出现之前 2 s 周期的 `CLEAR↔UNCERT` 横跳。

68.8 s 后水开始排空：

```
dNTU 从 +1% 快速抬到 +47%
→ SOAP/L2/DRAIN
→ WAIT/DRY
```

这是失水时浊度探头离开水面的瞬态，不是稳定清水误判；随后进入 DRY。

---

## 3. 仍存在但不影响本次结论的现象

1. **启动段 NOBASE**  
   DRAIN/RECOVER 采完后，FULL 段还要等最多 15 s，期间 `g_cal_multi_slot=true`，
   运行时不选槽，所以日志前段是 NOBASE。FULL 超时 DONE 后立即恢复选槽。
   如果现场觉得 15 s 太长，可改成 5~8 s；不影响稳态。

2. **FULL 槽 INVALID**  
   当前水路没有高于 RECOVER 的满水平台；两槽已覆盖 343.5/406.5。
   若以后要 FULL，需在标定第三段保持进水，使 EC ≥ 416.5 mV。

3. **失水尾部 SOAP**  
   dNTU 在探头脱水瞬间会冲高，先 L2 再 DRY；动作仍是 DRAIN，安全。
   如果不想留这条 SOAP，可在 gate 里把“快速失水”优先于浊度判据。

---

## 4. 结论

- 本次没有再出现清水重复横跳；
- 两槽各自 dEC≈0，说明 B3 的“槽选择 + 双通道”路径生效；
- **不需要放宽 d1/d2**；之前横跳是槽没激活/第二槽丢失，不是阈值太紧。
