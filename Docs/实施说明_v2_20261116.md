## 1. 一句话结论

把“事件闩锁 + 30 s 超时”整体换成 **`validity 工况机 → decision 分类 → 每 tick 重算的回收许可`** 三层结构：
**空腔与“水位低于电极”不再判清、不再回收；换向扰动不再买到 30 s 许可；清水在浸没且稳定后能正常回收。**

代码已用工程自带 ARM GCC 13.2 构建通过（0 error / 0 warning），**尚未做硬件在环与台架验证**（见 §7）。

## 3. 行为对照（现场四个原始问题）

| 现场现象（旧固件） | 旧原因 | v2 行为 |
|---|---|---|
| 待机时“回收-排空”阶段性跳跃，30 s 一周期 | 单点/速率抢先 → `auto_start` 开事件 → 30 s 超时关 → 关闭动作又触发 | 无事件、无超时；`PERMIT` 每 50 ms 重算，谓词变假当 tick 就排空；换向 400 ms 内冻结判别 |
| 只在开机进待机，检测过就回不去 | “事件”是有记忆的状态，只能靠超时退出 | `DRY` 是普通工况：失浸没 300 ms 即回 `DRY`，随时可回 |
| 全是清水时：TDS 碰到水判“污水”、碰到空气判“清水” | 基线在空气里采（EC0≈58 mV），水/空气的方向被颠倒 | 基线必须 `W` 在水中采；空腔用 `D` 的干态指纹识别 → `DRY`；水中 ΔEC≈0 → `L0`（需 3 块） |
| 液体流速/装置位置影响 | 腔体交换时间 τ 远大于算法时间常数 | 软件侧已按 4 s 稳定期 + 400 ms 屏蔽降敏；**τ 属结构项，软件不能替代**（诊断报告 P0-0） |

新增的传感器异常处理：

| 情况 | v2 判定 |
|---|---|
| 电极脱水（探头插着、水位低于电极） | `EC < 3×EC_DRY` → 不浸没 → `DRY` → DRAIN |
| 探头开路/断线（~1650 mV 伪值） | 基线量程上限 1600 mV → `BASE_HIGH` → `FAULT` → DRAIN |
| 基线未标定 | `FAULT` → DRAIN，提示先 `D`/`W`（v2.1 自检会自动做） |
| 浊度失效（AO≈0 / 高轨） | `VAL_SENSOR_OK=0` → `FAULT` → DRAIN（不静默忽略） |

## 5. 与方案 v2 的差异（都是刻意取舍）

1. **`BLANKING` 不进 `PERMIT`，改为“冻结判别”。**
   方案 §7.1 写的是 `PERMIT = ... && !BLANKING`。直接照做会形成正反馈：
   `回收 → 阀换向 → 屏蔽 → 许可撤销 → 排空 → 再换向 → 再屏蔽 …`。
   实现：屏蔽窗内不更新候选等级、不跑速率抢先，已采纳的等级与许可保持不变；
   屏蔽窗内 `stable` 按“稳定”参与工况迁移（位图仍报真实值），
   避免换向瞬态（实测 ±35~38 mV/s > 30 mV/s 门限）把工况打回 SETTLE、形成 6 s 极限环。

2. **`PERMIT` 用“工况级的浸没”，不用瞬时 `gate.immersed`。**
   谓词实现为 `PERMIT = (level == L0)`：`L0` 只可能在 `REGIME_MEASURE` 里产生，
   而进入/离开 MEASURE 已经要求“浸没 500 ms / 失浸没 300 ms”去抖。
   若再乘瞬时的 `immersed`（直接比未平滑的 `tds_mv25`），单点抖动会让许可翻转，
   `min_dwell=500 ms` 会把它拖成约 1 Hz 的换向往返。
   代价：真正失浸没后许可最多多保持 300 ms（阀本身还有 500 ms 驻留）。

3. **“无基线但已确认没水”归 `DRY` 而不是 `FAULT`。**
   方案 §5 的迁移表是 `any → FAULT: !BASELINE_OK`，但 §13 P0-1 要求“空腔上电 → DRY”。
   实现：传感器正常 + 有干态指纹 + 未浸没 → `DRY`；没有干态指纹且没有基线 → `FAULT`。

4. **基线 CV 校验加绝对 σ 兜底。**
   纯水 EC0 可能只有几十 mV，1 % 相对判据低于噪声下限；判据改为 `CV ≤ 1 % 或 σ ≤ 3 mV`。

5. **`R/E` 保留但只做日志分段。** `# EVENT` 照旧打印，不再影响工况与阀。

6. **W 强制要求先做 D。** 否则先 W 且电极露空会把“空气 58 mV”存成 EC0；
   `gate` 层的 `baseline_ok` 也强制要求 `dry_valid`（纵深防御）。

7. **短块投票按 75 % 折算，且至少 4 个样本。**
   满块仍是 8 点 6 票；短块（主循环被 printf 拖到 100 ms）按实际样本 75 % 向上取整；
   少于 4 个样本的块直接作废，防止“1 个采样决定整块”。

8. **v2.1 开机自检**：自动干态（默认值起步）→ 等水 → 自动湿态，见独立文档。

9. **v2.2 阈值按 EC0 比例化 + L0→L1 去抖**（现场三份日志驱动）：
   - `d1/d2` 增加 `6%/9%×EC0` 下限（348 mV → 20.9/31.3 mV），因为清水漂移是 EC0 的 5%，固定 8 mV 只有 2.3%；
   - `L0→L1` 需连续 2 块（0.8 s），`L0→L2` 仍立即——清水的水力漂移只持续 0.4~0.6 s；
   - NTU 阈值下调为 `4%/8%`（清水 −1.6%、肥皂 +10.9%）。
   详见 `Docs/清水抖动分析与阈值修订_20261116.md`。

10. **v2.3 自检识别修复**（现场“自检后清水仍待机”）：
    - 浸没/基线由 `3×EC_DRY` 改为 `EC_DRY + 80 mV`（低电导清水 + 残水抬高干态时不再误判没水）；
    - 默认干态基线下限 `400 → 150 mV`（现场清水 348 才能过）；
    - 自动采湿态改为“EC 差值 + AO 高于空腔”双证据（本机水 AO 2639 > 空气 2241）；
    - `SETTLE` 增加 6 s 兜底（流动水 `stable` 不成立时也能进 MEASURE）；
    - OLED 状态行改 ≤16 字符短句（8x16 字体每行 16 字符，旧串被截断）。
    详见 `Docs/自检识别修复_v2.3_20261117.md`。

11. **v2.4 进水识别加速 + OLED 大小写**：
    - `SETTLE→MEASURE` 自适应：连续稳定 500 ms、不早于 1.5 s、且 `dEC≤0` 时提前进入；
      进水数据可从 8.6 s 提前到约 6.1~6.3 s；`dEC>0` 仍等 4 s/6 s；
    - OLED 英文改“首字母大写、其余小写”，代码/单位（L1、EC0、mV、NO_BASE 等）保持大写。
    - **v2.4.1**：稳定带由 30 mV/s / 5%/s 抬到 **80 mV/s / 20%/s**。洗手仿真发现肥皂水
      （EC ~50 mV/s、NTU ~16%/s）会把工况踢回 SETTLE，导致肥皂期间 OLED 显示“待机”约 4 s；
      抬高后保持 MEASURE，直接判 `SOAP/L2`。详见 `Docs/洗手情景仿真_v2.4.1_20261117.md`。

12. **v2.4.3 基线质量修订**（现场四组全清水日志）：
    - 实测 `EC0=294.1 mV`、清水 324 mV，`ΔEC=+30 > d2=26.5` → 全判 SOAP；根因是湿态基线在
      进水上升沿采早（800 ms 后就采）；
    - 改为 800 ms 后连续稳定 300 ms 才采、最多等 3 s；采后 `|EC-EC0|>5 mV` 判 `BASE_DRIFT` 重采；
    - 自检/手动基线要求 `AO0-AO_DRY ≥250 mV`（清水≈409、肥皂≈69），挡脏水基线；
    - 运行中 `g>1.08` 且 NTU 干净持续 5 s 打 `# BASE_SUSPECT`；
    - 湿态采基线 OLED 显示“校准 + Auto calib n/40”（v2.4.2）。
    详见 `Docs/基线质量修订_v2.4.3_20261118.md`。

13. **v2.5.0 独立清水标定**：
    - K2 长按 **≥3 s**（原 1.5 s）进入独立标定：作废旧基线 → 等浸没/稳定/AO 清洁 →
      采 2 s → 5 mV 漂移校验 → 成功后生效；OLED 显示“校准 + n/40”；
    - 现场先排空、清水冲 2~3 倍腔体、淹过电极，再长按；
    - 基线仍只在 RAM，掉电丢失；Flash 持久化需要 FSP `r_flash_lp`，当前工程未包含，下一步接入。
    详见 `Docs/独立清水标定_v2.5.0_20261118.md`。

## 6. 命令与 CSV 变化

### 6.1 新增/变更命令

| 命令 | 作用 | 备注 |
|---|---|---|
| 上电自检 | 自动干态 → 等水 → 自动湿态 | v2.1；无需输入 |
| `D` | 手动干态指纹（腔内必须无液体，60 s） | 有“腔非空”校验与墙钟超时 |
| `W` / `B` | 手动水中基线（电极必须浸没，2 s） | 没有干态指纹时拒绝；完成后校验 `EC0 ≥ 3×EC_DRY` |
| `G` | 打印工况（valid 位图 / regime / 浸没 / 稳定 / 屏蔽 / 干态来源） | 现场排查主入口 |
| `Z` | 清水中基线并停止自检 | 需 `W` 或重新上电再标定 |
| `R` / `E` | 事件标记（只影响日志） | 不再有 2 s 强制排空、不再有 30 s 超时 |

### 6.2 CSV（仍 17 列）

- `state`：`WAIT`（DRY/SETTLE/FAULT/LOCKOUT）、`CLEAR`（许可成立）、`UNCERT`、`SOAP`；`FLUSH` 保留枚举但不再输出。
- `level`：`L0/L1/L2`（非 MEASURE 时固定 `L1`）。
- `action`：取**阀实际位置**（AUTO 模式，与 `# VALVE` 一致）；假执行器模式打印 decision 动作。
- `note`：工况码 `OK/DRY/SET/BLK/LOCK/NOBASE/SENS`；MEASURE 且管线正常时沿用 pipeline note。
  **旧脚本若匹配 `NO_BASE`，需改成 `NOBASE`。**

### 6.3 事件行与提示行

```
# GATE t=… valid=0x1F(SNS|BAS|IMM|STA|FLW) regime=MEASURE wet=1 blank=0 reason=MEASURE
# ACTION t=… RECOV valve=RECOVER     ← 行尾多一个 valve=，区分“判别动作”与“阀实际位置”
# TIP t=… | regime=MEASURE state=CLEAR level=L0 permit=1 | EC=1492.3mV g=1.001 dEC=2.0mV dNTU=2.1% T=29.1C | autocal=DONE | clean water: RECOVER
```

`# GATE` 只在 `regime` 或 SNS/BAS/BLK 位变化时打印（`STA`/`IMM` 会随气泡/液面抖）；
`# TIP` 每 2 s 一行，纯提示用（以 `#` 开头，脚本可忽略），不改变 CSV 列数/顺序；
启动时会打印一次输出格式图例（`# serial legend` / `# TIP ...` / `# CSV units ...`）。

| 浊度三态标定 / d1、d2 水中重算 | ❌ 未做（P2） |

> 因此本文件只能证明“代码可构建、逻辑按设计落地”，**不能证明现场行为**。§8 是上板后的验收步骤。

## 8. 上板验收步骤

### A. 空腔上电（P0-1/P0-2 + 自检）

1. 腔体排空、探头露空，上电。
2. 期望：`# AUTOCAL state=DRY`，OLED `AUTO DRY n/200` + `KEEP CHAMBER EMPTY`；**阀不吸合**。
3. 等 5 min：`# STATE` 中**不得出现 `CLEAR`**，`# VALVE count=` 不增长。
4. 10 s 后：`# DRY OK` → `# AUTOCAL state=WAIT_WATER`；OLED `AUTO WAIT WATER` + `POUR WATER OVER PROBE`。

### B. 注水到电极（P1-1/P1-3 + 自检）

1. 注清水至**淹过电极**。
2. 期望：约 1 s 后 `# BASELINE start` → `# BASELINE OK ec0=…`（v2.3 起要求 `ec0 ≥ EC_DRY+80 mV`，不再用 3× 比值）。
3. 期望时序：`FAULT→LOCKOUT(3s)→DRY→SETTLE(1.5~6s，自适应)→MEASURE`，入水 4 s 内不得出现 `RECOV`；
   v2.4 起 `SETTLE` 在稳定 0.5 s 且 `dEC≤0` 时可于 1.5 s 后提前进入 MEASURE；`dEC>0` 仍等 4 s/6 s 兜底。
4. `MEASURE` 后：干净水约 1.2 s 后 `# STATE to=CLEAR`、`# ACTION RECOV`、`# VALVE pos=RECOVER`。
   **v2.2 验收**：清水连续 60 s 内应保持 CLEAR，不再出现约 2 s 周期的 `CLEAR↔UNCERT`，
   `# VALVE count` 不应持续增长。若仍抖动，按 `清水抖动分析与阈值修订` §5 调 `ec_d1_pct`。
5. 记录 `P` 里的 `d1/d2/σ`、`d_ec`、`d_ntu_pct`，回填 §4。

### B2. 上电时腔里已有清水（v2.3 验收）

1. 不排空，腔里保留清水（淹过电极），直接上电。
2. 期望：`AUTO WATER OK` → `AUTO CALIB` → `# BASELINE OK`（ec0≈348、≥150）→ `MEASURE`，
   **不再停在“待机”**。
3. 若 AO 证据不足（水膜/空气/模块方向相反）：OLED `AUTO FAIL` + `SEND W IN CLEAN WATER`，
   手动 `W` 应能建立基线并进入 `MEASURE`。

### C. 水位降到电极以下

1. 从 `CLEAR` 抽水，让液面低于电极但腔里仍有水。
2. 期望：≤300 ms 内 `# GATE regime=DRY`，阀在 500 ms 驻留内排空；**不得**出现 `CLEAR`。

### D. 拔电极 / 断线

1. 在 `MEASURE` 中拔掉 TDS 探头。
2. 期望：`# GATE regime=FAULT reason=SENSOR`、`note=SENS`、阀排空。

### E. 换向屏蔽（S6）

1. 在 `MEASURE` 中用 `V1`/`VA` 反复切换。
2. 期望：`# GATE` 出现 `blank=1` 的 400 ms 窗口；窗口内 `# STATE` 不变化；`count` 不因扰动快速增长。

### F. 断电

1. 断电重启：自检重跑；空腔时阀排空。
2. 没有 Flash 持久化，每次上电都要重新标定（P2-1 之前属预期行为）。

## 9. 风险与取舍

| 风险 | 说明 | 缓解 |
|---|---|---|
| 许可模型“跟手” | 谓词 50 ms 一变，阀可能比旧版动作频繁 | 阀 `min_dwell=500 ms`；单侧迟滞（升慢降快）；实测偏多时先加长 `SETTLE` |
| 失浸没后许可最多多保持 300 ms | `PERMIT` 用工况级浸没 | 阀通常还没过 500 ms 驻留；可把 `dry_debounce_ms` 降到 150 ms |
| 短块投票放宽到 3/4 票 | 主循环被 printf 拖慢时 400 ms 只有 4 个采样 | 仅短块折算；少于 4 样本作废 |
| `WET_RATIO=0.30` 是拍脑袋值 | 不同水质/电极几何最优值不同 | 按验收记录三点的 `g` 回填 |
| 无 Flash 保存 | 每次上电重标（v2.1 自检缓解） | P2-1 数据 Flash |
| 浊度仍未真正参与回收判据 | `d_ntu_pct` 现场只有 1~3 %，远低于 8 %/25 % | P2-2 三点标定后重设；标定前它只能“多排空” |
| UART 仍可能丢帧 | P1-4 未做 | 先用 `# GATE`/`# VALVE` 行定位 |
