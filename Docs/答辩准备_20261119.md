## 3. 故事线（先定叙事，再谈 PPT）

### 3.1 一句话定义（对外口径）

> **本作品是一台"洗手水在线判别与选择性回收装置"：用一路电导率 + 一路浊度，以"相对清水基线的增量"而不是绝对阈值，在线判断洗手水当前是准清水还是含皂液，驱动三通阀把可回用的水切入回收桶、把含皂液的水排入下水道；判不准时默认排空。**

### 3.2 30 秒电梯版（背下来，用于开场和被打断后拉回）

> "洗手水的脏是分段的：刚出来是准清水，搓手中段是皂液水，冲洗末段又接近清水。现在的做法是不加区分全部排掉。我们做的是给它做一次在线化验，再决定去哪：电导率看离子、浊度看悬浮物，都用相对基线的增量，所以换水换地方只要上电自校准 20 秒。判不准就排空——这是我们整套设计的安全底线。"

### 3.3 三分钟版（四段，每段 40 s）

1. **问题**：一次洗手 30 s 内水质三段变化；市售感应龙头只判"有没有手/有没有水"，不判"水干不干净"；全量过滤方案则是"不管脏不脏都处理"，费滤料。
2. **方案**：RA4M2 + TDS + 浊度 + 水温 → 状态机（DRY/SETTLE/MEASURE/FAULT）→ 三级分类 → 三通阀；OLED 现场显示、串口留痕。
3. **证据**：清水连续 14.6 s 稳定 `CLEAR` 不横跳；肥皂水 +39 mV/+10% 判 `SOAP` 并切排空；肥皂冲洗水只升 EC 不升浊度时判 `UNCERT` 排空，不误回收。
4. **边界**：腔体大导致响应慢、肥皂进入后约 1.6 s 内仍可能进回收、基线未掉电保存、浊度未标定、酒精类盲区——都已定位，是下一步而不是"已实现"。

### 3.4 这套叙事对应哪几个采分点

| 采分点 | 对应页 | 一句话 |
|---|---|---|
| 方案比较与论证 | P2/P3 | 与"感应龙头""全量过滤"逐条对比，说明为什么是"判别 + 分流" |
| 理论分析与计算 | P5/P8 | ΔEC 的相对判据、双通道三级分类、块投票的统计意义 |
| 电路与程序设计 | P4/P6 | 外设分配、状态机、失效降级路径 |
| 测试方案与结果 | P9 | 清水/肥皂/失水/断线四类测试 + 已知未测项 |
| 报告规范性 | 全文 | 数据都带条件与出处，不写未验证指标 |

### 每页必须遵守的三条

- **一页一个结论**：标题就是结论句（如"阀位会改变 EC，所以需要三槽基线"），不要写"系统设计"这种空标题。
- **数字带条件**：写"3~4 L/min、25 mL 内杯下 ≤1.2 s"，不要写"≤1.5 s"。
- **没做的不上页**：HC-SR04、Flash 持久化、NTU 标定只出现在 P12。

### 各页细节（做 PPT 时直接抄）

**P2**：时间轴 0–2 s 准清水 / 2–8 s 皂液水 / 8–16 s 冲洗水 / 关水；右下角一行："一次洗手约 30 s，其中可回用时段在仿真中占 52%（**时间占比，不是水量**）"。

**P5**：左边画"同一杯清水、不同日期基线 258 / 305 / 343 / 553 mV"的柱状图；右边写公式 `ΔEC = EC − EC0(当前槽)`、`d1 = max(4σ, 8 mV, 5%×EC0)`、`d2 = max(8σ, 20 mV, 9%×EC0)`。

**P6**：五状态 `FAULT / DRY / SETTLE / MEASURE / LOCKOUT`；三条失效路径画红箭头：断线→FAULT→DRAIN、失浸没 300 ms→DRY→DRAIN、无基线→FAULT→DRAIN。

**P8**：阈值表（EC d1 5%、d2 9%；浊度 d1 7%、d2 9%）；投票时序：400 ms/块、8 点、6 票；L0 需连续 3 块（1.2 s）、L0→L1 需 2 块（0.8 s）、L2 立即；阀最小驻留 500 ms、单次最长 120 s。

**P9**：上半张双曲线图，下半张表：

| 测试 | 操作 | 结果 |
|---|---|---|
| 清水稳定 | 淹过电极、静置 | 连续 14.6 s `CLEAR/L0/RECOVER`，dEC −11.0~+1.1 mV |
| 清水抗噪 | 多批次 | 稳定段 max\|dEC\| 16.1 mV、p95 11.3 mV，门限 27.7 mV |
| 肥皂阶跃 | 加皂液 | +39~42 mV / +10.1~12.8% → `SOAP/L2/DRAIN` |
| 肥皂冲洗水 | 只升 EC 不升浊度 | +25.5~31.5 mV / +0.6~1.0% → `UNCERT/L1/DRAIN`（不误回收） |
| 失水 | 抽干 | 300 ms 内 `DRY`，阀排空 |
| 断线 | 拔探头 | `FAULT`，阀排空，不静默 |

**P11**：六条局限见 §8，每条都配"当前缓解"。

## 5. 现场演示

### 5.1 物理布置（提前 30 min）

1. 桌子铺接水盘/毛巾，桶放桌下或桌侧，**绿桶（回收）与灰桶（排空）贴 A4 大字标签**。
2. 电路板/继电器远离水路，接口朝下；吸水纸垫在阀与板之间。
3. 手机/相机架好，对准 OLED + 阀 + 桶；串口投屏（可选，评委很吃这套）。
4. **水位保命**：按 `Docs/赛前冻结与发货清单_20261116.md` §3 做立管或夹管，保证电极始终浸没；否则演示会退化成"测水位"。

### 5.2 上电与预标定（评委进场前完成）

```
排空腔体 → 上电 → 等 DRY OK / WAIT WATER → 注清水 → BASELINE(SLOT) OK
→ 等 MEASURE → 用清水试跑一轮 CLEAR/RECOVER → 再排空 → 待机
```

- **不要带水冷启动**，也不要当着评委面等三段标定（最多 15 s FULL 超时，看起来像卡住）。
- 提前确认阀方向：`V1`=回收、`V0`=排空、`VA`=自动；方向反了宁可不上台。
- 记下当前的基线值（`# BASE slot=... ec0=...`），问答时可以直接引用。

**上板 6 条验收（跑完再上台，10 分钟）**

| # | 操作 | 通过标准 |
|---|---|---|
| 1 | 空腔上电 5 min | 无 `CLEAR`；阀不吸合；`# VALVE count` 不增长 |
| 2 | 注清水淹过电极 | `BASELINE OK`、ratio≥3；约 2 s 内 `MEASURE`，随后 `CLEAR/RECOVER` |
| 3 | 停水/抽干 | `DRY`，阀排空（做了立管的水路需手动排空） |
| 4 | 拔 TDS 探头 | `FAULT`/`SENS`，阀排空，不静默 |
| 5 | 皂液阶跃 | 记录实际延迟；阀能切 `DRAIN` |
| 6 | 断电重启 | 自检重跑；空腔不回收；阀方向仍正确 |

> 任一条不过：先回退到已通过的 hex，不在答辩前改未验证的代码。

### 5.3 四段脚本（大腔体，每段 30~60 s）

| 时间 | 动作 | 评委看到 | 主讲说 |
|---|---|---|---|
| 0–40 s | 清水流过/注入 | OLED `Clear/L0`，阀 `RECOVER`，绿桶 | "清水段，ΔEC≈0，允许回收" |
| 40–80 s | 加皂液、搅动 | `Soap/L2`，阀 `DRAIN`，灰桶 | "两路同时升高才判 SOAP，单路高只判不确定" |
| 80–120 s | 清水冲洗 | 先 `Uncert` 再 `Clear`，阀回 `RECOVER` | "冲洗水先排后收，宁可少收" |
| 120–150 s | 关水/排空 | `Dry`，阀 `DRAIN` | "失水 300 ms 内回排空" |

> 演示期间同步念串口的 `# STATE` / `# VALVE` 行，让"为什么切"可见；OLED 停在 P1（水质页），需要时切 P2（执行器页）。

### 5.4 三套预案（写在一张卡片上，放口袋）

| 预案 | 触发条件 | 做法 |
|---|---|---|
| **A 实机** | 自检通过、阀方向正确、无漏水 | 按 §5.3 走 |
| **B 视频 + 静态展示** | 自检连续失败 2 次 / 阀方向反 / 漏水 / 串口无输出 | 播 2 min 视频，实物只做 OLED 与阀的手动演示（`V1`/`V0`） |
| **C 只讲数据** | 设备完全不可用 / 场地不给水 | 用 PPT 里的双曲线图 + 日志截图讲，明确说"设备在运输/现场出了 X 问题，数据是本周实测" |

**切换纪律**：A→B 最多尝试 2 分钟，不现场改代码、不现场烧录、不现场拆管。评委更认"知道什么时候停"。

### 5.5 演示禁忌

- 不要用真实洗手（溅水到继电器/板子），用挤水瓶。
- 不要让水在台上流进电源/插排。
- 不要在演示中解释"这个报错是因为……"超过 10 秒，直接切预案。
- 不要承诺"再等 30 秒就好"——大腔体确实慢，但要提前说，不要现场等。

### 6.2 三个"必须带条件"的数字

- **"3.6 s 开水→CLEAR、1.6 s 肥皂→DRAIN、52% 回收时段占比"**：全部来自 **v2.4.1 仿真**，必须说"仿真的 50 ms 步长模型，用于比较版本差异，不是实机统计"。
- **"14.6 s 稳定"**：是**稳态持续时间**，不是"进入时间"。
- **"85 KB / 11.4 KB"**：是 v2.7.6 的构建尺寸，v2.8.0 会更大。

### 6.3 绝对不能说错的三件事

| 不能说 | 改成 |

## 7. 问答

### 7.1 十个必答题（按 30 秒准备，别背长稿）

**Q1 你凭什么判这杯水能回用？**
不是靠绝对水质，是靠"相对本机清水基线的偏离"。两路独立证据：ΔEC 看离子、ΔNTU 看悬浮物；三级分类里，**只有连续 3 个 400 ms 块（1.2 s）都干净才允许回收**，中间态一律排空。实测清水最大偏离 16.1 mV，离门限 27.7 mV 还有余量；肥皂 +39 mV 以上会被拦下。

**Q2 皂液主要成分是非电解质，电导率为什么会有响应？**
洗手液里的阴离子表面活性剂、无机盐、防腐剂提供离子；洗手过程还会带入汗液/皮脂（含 NaCl）。所以响应存在但幅度小（约 5~11%×EC0），这也是我们**用相对增量而不是绝对电导率**的原因。对"只升 EC、不升浊度"的肥皂冲洗水，我们只判 `UNCERT` 排空，不硬标 `SOAP`。

**Q3 为什么不用绝对阈值？**
同一台装置、同一杯清水，不同日期实测基线从 258 mV 变到 553 mV（约 2 倍），绝对阈值不可移植；而且阀位/液位本身会改变 EC（DRAIN 与 RECOVER 差 40 mV 以上）。所以上电自校准 + 三槽基线 + 百分比阈值，换水换地方重标 20~30 s。

**Q4 三槽基线是不是过度设计？**
不是。同一腔体在 DRAIN / RECOVER / 满水流动三个状态有稳定平台差，单基线会把"阀位变化"误判成"水质变化"——v2.6 之前实测出现过整段 `SOAP` 和 1 s 周期横跳。改成三槽后，v2.7.3 现场两槽各自 dEC≈0，连续 14.6 s 稳定。代价是 FULL 槽要维持进水，现场不满足就超时保留两槽。

**Q5 三级分类 + 块投票会不会太慢？**
分类本身很快，慢在"确认"。设计上不对称：**变脏立即（L2 立即、L0→L1 0.8 s），变干净要 1.2 s**，这是安全侧。当前最大延迟是肥皂进入后约 1.6 s 才切 DRAIN（仿真），根因是检测延迟 + 块投票，不是误判；下一步用"双证据立即 L2"可压到约 0.8 s。

**Q6 传感器坏了、没水了怎么办？**
三类失效都有明确出口：探头断线→ADC 贴轨伪值→超出基线量程 50~1600 mV→`FAULT`→排空；浊度贴轨/为 0→`VAL_SENSOR_OK=0`→`FAULT`→排空；失浸没（EC/AO 低于干态指纹差值）持续 300 ms→`DRY`→排空。**没有合法基线就不回收**，上电自检会重跑。

**Q7 回收水会不会污染自来水、被误用？**
物理隔离：回收支路不与自来水管连通，独立回收桶 + 颜色标识（绿/灰），空气隔断防倒吸；用途限定冲厕/拖地/绿化，**不做接触性回用**。我们没有做微生物/COD/余氯检测，所以不声称达到任何回用水标准。

**Q8 换个地方、换种水还准吗？每次上电都要标，实用吗？**
换水主要影响基线绝对值，相对判据不受影响，上电自动三段标定 20~30 s；换地方还要注意水温和电极结垢（会漂移）。实用性质疑我承认：目前基线只在 RAM，掉电要重标——这是下一步接数据 Flash 要解决的，不是已经解决。

**Q9 你的数据可信吗？做了多少次重复？**
分层说：现场日志 3 个批次（11/16 诊断、11/19 清水、11/19 肥皂冲洗水），每批都是连续采集；**阶跃重复次数还不够**，没有做 20 次统计，也没有混淆矩阵；仿真只是 50 ms 步长复刻控制逻辑，用来比较版本差异，不能替代实测。已做的验收：清水稳态 14.6 s 不横跳（验收目标是 60 s，尚未逐次记录）、肥皂阶跃、失水、断线、断电重启。

**Q10 最大的不足是什么？下一步先改哪个？**
三条：① 腔体大，τ 30~200 s，肥皂进入后约 1.6 s 仍可能进回收；② 没有独立"有水"信号，靠 EC 推断（HC-SR04 在研，目前还没拿到有效回波）；③ 基线不持久、浊度未标定、酒精类双盲区。下一步按收益排序：**杯中杯 + 立管（τ 降到 0.5~1.3 s）> 液位门控 > Flash 持久化 > 浊度标定**。
