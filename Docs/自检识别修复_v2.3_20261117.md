> OLED 状态串已改为首字母大写；见 `Docs/进水识别加速与OLED大小写_v2.4_20261117.md`。
> 本文档保留 v2.3 的根因分析与阈值说明。

- 日期：2026-11-17
- 固件：`SENSOR-NODE v2.3.0-AUTO2`
- 构建：`text 77116 / data 480 / bss 11332`，0 error / 0 warning（`_tmp/build_v23_final3.log`）
- 前置：`Docs/开机自检_v2.1_20261116.md`、`Docs/清水抖动分析与阈值修订_20261116.md`

---

## 1. 现象

1. 开机自检跑完后，腔里是清水，但 OLED 一直停在**“待机”**，不进入清水/污水判断。
2. 自检状态行不清晰；8x16 字体一行只能放 16 个字符，原来的
   `SELFCHK WAIT WATER`（18 字符）、`CALIB FAIL: SEND W`（18 字符）会被**截断**；
   现场看到的字既不全，也不容易理解。

---

## 2. 根因（四个叠加）

### 2.1 3×EC_DRY 对这股低电导清水太严

- 现场清水 EC0≈**348 mV**，空腔 EC≈**23 mV**，正常情况下 3×23=69，没问题；
- 但如果腔里有残水/电极湿，空腔读数会被抬到 **100~170 mV**，3× 就是 **300~510 mV**；
- 清水 351 mV 一旦低于 3×EC_DRY，就被判“**没水**”→ 工况一直停在 `DRY` → OLED 待机。

### 2.2 默认干态时水中基线下限 400 mV 把清水拒了

- v2.1 为了防止“水膜当水体”，规定 `dry_source==DEFAULT` 时基线必须 ≥400 mV；
- 现场清水只有 **348 mV**，所以只要自检没测到实测干态（腔里有水/电极湿就会这样），
  即使手动 `W` 也过不了 `baseline_ok`，永远进不了 `MEASURE`。

### 2.3 浊度“有水”确认方向反了

- 本装置实测：**清水 AO≈2639 mV，空腔 AO≈2241 mV** —— 水比空气**高**；
- v2.1 的确认条件却是 `AO ≤ 空腔×98%`（假设水比空气低），在本装置上**永远不成立**；
- 结果：上电时腔里已有水 → 自检走 `chamber_wet_confirm` → `water_unconfirmed` → `AUTO FAIL` → 待机。

### 2.4 SETTLE 要求“稳定”才进 MEASURE

- v2.1 在 `SETTLE→MEASURE` 上加了 `stable` 条件；
- 水一直在流动/气泡多时 `|dEC/dt|` 可能长期 >30 mV/s，4 s 到了也进不去，
  OLED 就一直是 `SETTLE WAIT` / 待机。
- 方案原文只要求“持续 4 s 且保持浸没”，稳定判据是额外加的。

### 2.5 OLED 状态被截断

- 8x16 ASCII 字体是 8 px/字符，128 px 一行 → **最多 16 字符**；
- `SELFCHK DRY 37/200`（19）、`SELFCHK WAIT WATER`（18）、`CALIB FAIL: SEND W`（18）
  都会被截断，现场读到的不是完整句子。

## 3. v2.3.0 修订

| # | 改动 | 说明 |
|---|---|---|
| 1 | 浸没/基线判据由 `3×EC_DRY` 改为 **`EC_DRY + 80 mV`** | 新增 `ec_wet_delta_mv=80`；干态 23→阈值 103，干态 120→阈值 200；清水 351 都能进 |
| 2 | 默认干态基线下限 **400 → 150 mV** | 348 的清水可通过；防“水膜”改由第 3 条的 AO 证据负责 |
| 3 | 自动采湿态要求 **EC 差值 + AO 高于空腔** 双证据 | 新增 `ao_water_delta_mv=+80`（本装置水 AO 高）；水膜/空气过不了 AO 这一条 |
| 4 | `SETTLE→MEASURE` 增加 **6 s 兜底** | 4 s 且稳定 → 正常进入；到 6 s 即使不稳定也进入，避免永远待机；进 MEASURE 后持续不稳定 1 s 仍回 SETTLE |
| 5 | OLED 自检状态改为 **≤16 字符全大写短句**，并增加第二行提示 | 见下表 |

### 3.1 新的 OLED 自检显示

| 阶段 | 第一行（8x16，≤16 字符） | 第二行（6x8，提示） |
|---|---|---|
| 采干态 | `AUTO DRY 37/200` | `KEEP CHAMBER EMPTY` |
| 等水 | `AUTO WAIT WATER` | `POUR WATER OVER PROBE` |
| 检测到水 | `AUTO WATER OK` | `WATER DETECTED` |
| 采湿态 | `AUTO CALIB` | `KEEP STILL` |
| 重试 | `AUTO RETRY 1` | `RETRY SOON` |
| 自检失败 | `AUTO FAIL` | `SEND W IN CLEAN WATER` |

> 全部大写是有意为之：8x16 与 6x8 两套字库对全大写最清晰；原来看起来“首字母大写、其余小写”
> 的观感主要来自**状态串被截断**（后半句没了），现在改成短句后不会再截断。
> 如果现场仍看到混合大小写，请拍一张 OLED 照片，我再按实际字库核对。

### 3.2 新增/变更配置

| 参数 | 默认 | 位置 | 作用 |
|---|---|---|---|
| `ec_wet_delta_mv` | 80 mV | `gate_cfg_t` | EC ≥ EC_DRY + 80 才算有水 |
| `ao_water_delta_mv` | +80 mV | `gate_cfg_t` | 水 AO 至少比空腔高 80 mV（方向相反时设负值） |
| `ec0_default_min_mv` | 150 mV | `gate_cfg_t` | 默认干态时水中基线下限 |
| `settle_timeout_ms` | 6000 ms | `gate_cfg_t` | SETTLE 兜底，避免永远待机 |

## 4. 上电场景预期

### 4.1 空腔上电（正常流程）

```
AUTO DRY 0/200 … 200/200 → AUTO WAIT WATER（待机，阀不动）
注水淹过电极 → AUTO WATER OK → AUTO CALIB → 基线 OK
→ LOCKOUT(3s) → DRY → SETTLE(4~6s) → MEASURE → 清水 CLEAR
```

### 4.2 上电时腔里已经有清水

```
默认干态 60 mV → 检测到 EC=351（≥60+80）→ AUTO WATER OK
→ AO=2639（≥2337+80）→ AUTO CALIB → 基线 351（≥150）
→ LOCKOUT → DRY → SETTLE → MEASURE → 清水 CLEAR
```

即 **v2.3 不再要求“先排空再上电”**；只有 AO 证据不足（水膜/空气/换向批次相反）时才落到
`AUTO FAIL / SEND W IN CLEAN WATER`，此时手动 `W` 仍可用。

## 5. 现场验收

1. 启动行应为 `SENSOR-NODE v2.3.0-AUTO2`；
2. 启动摘要应出现：
   `# gate: wet_ratio=0.3 ec_delta>=80.0mV ao_delta>=80.0mV settle=4.0/6.0s blank=0.4s`；
3. **空腔**：`AUTO DRY n/200` → `AUTO WAIT WATER`，阀不动；
4. **注清水**：`AUTO WATER OK` → `AUTO CALIB` → `# BASELINE OK`；约 4~6 s 后 `regime=MEASURE`；
   干净水应在约 1.2 s 后 `CLEAR`，60 s 内不来回跳；
5. **上电时已有清水**：应直接走 `AUTO WATER OK → CALIB`，不再停在待机；
6. **肥皂水**：应稳定 `SOAP/L2/DRAIN`；
7. 若仍停在 `AUTO FAIL`：串口会打印 `# BASELINE REJECT note=…` 或 `# AUTOCAL state=DONE reason=…`，
   按提示检查（水是否淹过电极、AO 方向是否与本机一致）。

## 6. 已知限制

1. `ao_water_delta_mv=+80` 是按本装置（水 AO 高于空气）定的；换模块/换批次若方向相反，
   把它改成负值（例如 `-80`）即可，不需要改代码。
2. 没有 Flash 持久化：每次上电仍要重新自检（约 10 s 干态 + 等水/湿态）。
3. 400 ms 换向屏蔽仍未覆盖 1.5~2 s 的水力瞬态；本次靠阈值/去抖压住，结构项仍是根治。
4. `ec_dry_ratio` 字段保留但已不参与判据（旧配置兼容用）。
