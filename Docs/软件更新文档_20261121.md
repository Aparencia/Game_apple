## 1. 这份文档怎么读

每一版都按同一个结构写，因为现场问题永远是同一条链路：

> **看到什么（数据）→ 判断为什么（根因）→ 改了什么（参数/代码）→ 结果（回放或现场验证）**

三个提醒：

1. **数据优先于叙述**。本文档里的数值都来自现场 CSV 或日志回放，不是估计值；找不到数据的版本会明确写"文档未给数据"。
2. **不要拿本文档的旧阈值当现在的值**。阈值一直在变（§3 有演化表），当前值以 §7 和源码为准。
3. **改阈值从来不是第一选择**。至少有 5 次现场修复最后证明"不是阈值问题"：v2.7.1 是槽没恢复、v2.7.2 是槽没激活、v2.7.3 是 AO 门槛误杀、v2.7.6/M1e 是 trim 把肥皂学掉、M2f 是槽选错——这些"不是阈值"的结论，比参数值本身更值得记。

## 5. 逐版记录

### v1.2.0（2026-11-13）· 为了能动真的阀

**当时看到的**：演示只靠 LED，装置没有真正的执行机构，"回收/排空"只存在于串口文字里。

**改了什么**：

- P104 → SRD-05VDC-SL-C 单路继电器模块 IN，继电器常开触点驱动 12 V 二位三通电磁阀；
- 新增 `actuator_valve` 模块：驻留防抖 500 ms、单次连续吸合上限 120 s、超时强制释放后冷却 10 s、引脚回读自检、动作计数；
- `APP_USE_VALVE=1` 为默认（真阀）；=0 时 P104 仍锁在排空电平，但只点 LED，保留"假执行器"兼容模式。

**结果**：回路上第一次有了"回收支路断电即关闭"的 fail-safe 结构；主排水路始终连通。

**依据**：`Docs/CHANGELOG.md` v1.2.0（接线与极性的细节在 `docs_sensor/15`）。

---

### v1.3.0（2026-11-13）· 为了现场能一眼看出装置在干什么

**当时看到的**：一个 OLED 屏要同时显示水质判据、执行器状态、参数，挤不下也看不清。

**改了什么**：

- OLED 分三页：P1 水质页（清水/污水/待机/冲洗/故障 + dEC/g/N）、P2 执行器页（大字"回收/排空/手动" + 继电器实际状态/吸合次数/通电时长）、P3 详情页（STATE/LEVEL/阀位置/ΔEC/ΔNTU/水温/EC0/σ/d1/d2）；
- K2 短按切页，长按进清水标定（v2.5 起明确为 ≥3 s）；
- 切页只影响显示，不改变判别/阀/CSV。

**结果**：现场问题第一次可以"看屏描述"，不用连电脑抓串口。

**依据**：`Docs/CHANGELOG.md` v1.3.0（细节在 `docs_sensor/16`）。

### v2.0.0（2026-11-16）· 为了不再"回收空气"

**当时看到的**（38 s 现场日志，186 帧）：

- 186 帧全部是 `CLEAR / L0 / RECOV`，EC 35~58 mV；
- 由 `g` 与 `d_EC` 反解出固件里的基线 **EC0 = 58.0 mV**（σ 仅 0.127 mV），而干态电极实测 35~58 mV（均值 43.7）——**基线是在电极露在空气里时采的**；
- "回收↔排空"跳跃周期 **30100 ms**，与 `event_timeout_ms=30000` 完全吻合；换向时刻精确是上一沿 +500 ms（`APP_VALVE_MIN_DWELL_MS`）。

**当时判断**：

- 判据测的不是"水脏不脏"，而是"**电极有没有被水淹到**"；"没淹到"的两种情况（真没水 / 有水但水位低）固件分不出，一律判清水，而"干净参考零点"恰好就是在那时取的；
- 事件闩锁只有一个 30 s 超时出口；超时释放 → 12 V 线圈反冲 → 3.3 V 轨弹跳 → 变化率抢先（阈值 40 mV/s，实测瞬态 35~40 mV/s）→ 直接判 L2 → 自动开下一个事件 → 自激循环；
- 触发门限正好长在执行器自己的干扰里（全段最大的 4 个速率 4/4 都在吸合沿之后）。

**改了什么**：

- 控制模型整体替换："事件闩锁 + 30 s 超时"→"**工况门控 + 每 tick 重算回收许可**"；
- `validity`(gate) 先判"能不能判"：FAULT / DRY / SETTLE / MEASURE / LOCKOUT；
- `decision` 只在 MEASURE 里分类，`PERMIT = (level == L0)`，谓词一变阀立刻跟随；
- 取消上电自动采基线（那是"把空气当清水本底"的根因），改成显式标定：D（空腔 60 s 干态）→ W（水中 2 s 湿态，带量程/CV/比值校验）；
- CSV 仍 17 列，note 列改成工况码（OK/DRY/SET/BLK/LOCK/NOBASE/SENS），新增 `# GATE` 事件行。

**结果**：结构上保证"没有合法基线 → decision 恒 FAULT/DRY → 阀排空"，空腔/水位低于电极不再回收；换向扰动也不再能买到 30 s 许可。

**依据**：`Docs/现场诊断报告_无水日志_20261116.md`、`Docs/软件层优化方案_v2_20261116.md`、`Docs/实施说明_v2_20261116.md`。

### v2.1.0（2026-11-16）· 为了上电不用敲 D 和 W

**当时看到的**：现场反馈"每次上电都要在串口敲 D/W"不现实——装置是给人用的，不是给调试台用的。

**当时判断**：标定可以拆成两件物理上能自动完成的事：在**空气**里采"空气参考"（安全），在**确认浸没后**采"水中基线"（有证据）。

**改了什么**：

- 上电先落一组默认干态指纹（60 mV / 2337 mV），空腔立即显示 DRY，不再一直 NO_CAL；
- 空腔自动采干态 10 s（比手动 D 的 60 s 短，只用于浸没判据）；
- 等水：`EC ≥ 3×EC_DRY` 且稳定 800 ms → 自动采水中基线 2 s；
- 校验失败最多重试 3 次，仍失败保持 FAULT/排空（绝不带病回收）；
- 手动 D/W/G/Z 仍可随时接管。

**结果**：上电即判别；安全边界是"只自动采空气参考与确认浸没后的湿态"。

**依据**：`Docs/CHANGELOG.md` v2.1.0、`Docs/开机自检_v2.1_20261116.md`。

### v2.1.1（2026-11-16）· 为了看懂那 17 列数字

**当时看到的**：现场盯着 CSV 只有 17 列数字，不知道"现在什么工况、下一步该做什么"。

**改了什么**：新增每 2 s 一行 `# TIP`：

```text
# TIP t=… | regime=MEASURE state=CLEAR level=L0 permit=1 |
  EC=1492mV g=1.001 dEC=+2mV dNTU=+2.1% T=29.1C | autocal=DONE | clean water: RECOVER
```

- 与 CSV 交替输出，以 `#` 开头，脚本可直接忽略；不改变 CSV 列数/顺序；
- BASELINE / DRY 完成行追加 `next: ...`；启动打印一次输出格式图例。

**结果**：日志既能机读也能人读，现场排障时间明显下降。

**依据**：`Docs/CHANGELOG.md` v2.1.1。

### v2.2.0（2026-11-16）· 为了清水不再每 2.2 秒抖一次

**当时看到的**（三份现场日志，同一股清水）：

| 数据 | 空腔 | 清水 | 肥皂水 |
|---|---|---|---|
| EC(mV25) | 23.6 ± 2.8 | 351.1 ± 13.4 | 387.9 ± 3.2 |
| ΔEC | −323.8 | +3.0 ± 6.4（−17.6 ~ +16.0） | +40.4 ± 1.4（+36.9 ~ +44.6） |
| ΔNTU | +13.8% | −1.6 ± 0.7% | +10.9 ± 1.1% |
| 阀动作 | 0 | **25 s 内 19 次换向，count 36→45** | 0 |

现象是 `CLEAR 0.8~3.2 s → UNCERT 1.4~1.6 s → CLEAR …`（周期 ≈2.2 s）。

**当时判断**：

- 把 ΔEC 与阀位对齐：切到 RECOVER 后 ΔEC 均值 **+6.1 mV**，切到 DRAIN 后 **−1.5 mV**——阀换向改变探头周围流场，EC 跟着漂 +6~+16 mV，不是水脏了；
- 固定 `d1 = 8 mV` 只等于 EC0 的 **2.3%**，而漂移是 **5%**；保持 CLEAR 的退出边界 `1.25×d1≈10 mV` 被越过；
- 放大器有两个：400 ms 换向屏蔽只盖住电磁瞬态（实测水力瞬态 1.5~2 s）；L0→L1 立即生效而升级要 1.2 s → 形成弛豫振荡器。

**改了什么**：

1. `d1 = max(4σ, 8 mV, 6%×EC0)`、`d2 = max(8σ, 20 mV, 9%×EC0)`（348 → 20.9 / 31.3 mV）；
2. L0→L1 需连续 2 块（0.8 s），L0→L2 仍立即；
3. NTU 阈值 8%/25% → 4%/8%。

**改了什么**：`ao_clean_delta_mv` 250 → **300 mV**。清水差 ≈500、肥皂差 ≈244，300 能挡住肥皂而不误伤清水。

**结果**：预期第一次上电即 `# AUTOCAL state=DONE reason=base_turbid`、三槽全 INVALID，不写脏基线。

**当时没做**：没有用"EC 高就拒绝"——不同水样 EC 差异很大，绝对 EC 上限判脏不可靠；AO/浊度才是更直接的清水证据。

**依据**：`Docs/肥皂水误标定修复_v2.7.4_20261119.md`；标签 `v2.7.4-B3`。

### v2.7.5-B3（2026-11-19）· 为了承认"只升 EC、不升 NTU"的那类脏水

**当时看到的**：现场确认除最后一次外都是清水，且清水 `AO−AO_DRY≈244`——**说明 v2.7.4 的 300 mV 方向错了**，会把清水基线直接拒掉。最后一次注水（肥皂冲洗水）：基线 RECOVER 553.0，水 EC 580.5~594.7，`dEC +25.5~+31.5 mV`（**+5.4%**），`dNTU +0.6~+1.0%`；旧 `d1 = 6%×553 = 33.2`，+30 < 33.2 → **CLEAR**。

**当时判断**：① AO 门槛退回 250；② 判成清水不是基线错，是 EC 只升 5.4% 刚好落在 6% 门限内，而且**浊度确实没有信号**——泡沫/气泡在液面或附着探头，TS300B 可能读不到浊度，软件不能把肉眼看到的泡沫变成 NTU。

**改了什么**：`ao_clean_delta_mv` 300 → **250 mV**；`ec_d1_pct` 6% → **5%**（`d1 = 27.7 mV`）→ `+30 > 27.7` 进 L1/UNCERT/DRAIN，不回收、也不硬标 SOAP。

**结果**（预期行为）：清水 → CLEAR/L0；这类冲洗水 → UNCERT/L1/DRAIN；真正 EC 与 NTU 同升的肥皂 → SOAP/L2。

**当时没做**：没把 d2 降到 5% 去"标 SOAP"——那样清水因液位/温度造成的 +5% 也会被标脏。

**依据**：`Docs/肥皂冲洗水_EC轻升_v2.7.5_20261119.md`；标签 `v2.7.5-B3`。

### v2.7.6-B3（2026-11-19）· 为了肥皂不被 trim 慢慢"学掉"

**当时看到的**：清水 `|dEC|` 统计：v2.7.3 稳定段最大 4.4 mV（p95 2.8），这次最大 **16.1 mV**（p95 11.3），而 `d1 = 27.7 mV` 还有 11.6 mV 余量——**d1=5% 本身不会让清水横跳**。真正的异常是肥皂冲洗水的 dEC 从 **+30 mV 慢慢降到 +22 mV（约 15 s）**。

**当时判断**：v2.7.1 的慢跟踪 `|dEC| > d1 → 4 mV/s 把 EC0 拉向当前 EC`，把"肥皂造成的偏移"当成"液位漂移"学掉了；dEC 掉回 d1 以下就又 CLEAR。**风险在 trim，不在 d1。**

**改了什么**：trim 触发区间改成 `5 mV ≤ abs(dEC) < d1`；`|dEC| ≥ d1` 不跟踪（保持 L1/DRAIN），`|dEC| < 5 mV` 也不跟踪（已经干净）。

**结果**：清水小漂移仍能跟；肥皂 +30 不会被学成干净；不会出现"先 UNCERT、几秒后又 CLEAR"。

**依据**：`Docs/清水反复风险评估_v2.7.6_20261119.md`；标签 `v2.7.6-B3`。

### v2.8.0-LEVEL-M1 / M1a~M1d（2026-11-19 ~ 11-20）· 为了把"水位"这个变量真正测出来

**为什么做液位**：v2.0 的诊断结论一直没被彻底解决——判据实际测的是"水有没有淹到探头"，而液位会影响 EC 平台、影响标定、影响阀位切换。液位是缺失的那个独立变量。

**M1（驱动接入）**：

- 引脚：TRIG = **P402 / U1-2**（3.3 V GPIO，外部电平转换到 5 V）、ECHO = **P409 / U2-3**（IRQ6，5 V 容忍，串 1 k 直接进）、VCC 5 V / U2-19/20、GND 共地；
- 不用 GPT：Echo 双边沿走 IRQ6，用 **DWT CYCCNT** 测脉宽，非阻塞，每 100 ms 触发一轮；
- 每 1 s 一行 `# LEVEL t=…ms mm=… valid=0/1`，**不改 17 列 CSV**；液位 20~2000 mm 限幅、3 次中值；
- 手工改 FSP 生成文件（`ra_gen/vector_data.*` 加 IRQ6 向量、`IRQCR[6]=0x02` 双边沿、`IELSR[9]`、`NVIC_EnableIRQ(9)`）——这些重新 Generate 会被覆盖。

**M1a**：现场第一次上电日志在 `# LEVEL` 处只打出 `# LE` 就重启。判断是 **IRQ6 状态位没清**、边沿中断反复重入。改动：ISR 末尾 `R_ICU->IELSR_b[9].IR = 0U`。结果：不再重启，但 `# LEVEL` 全 `valid=0`。

**M1b**：加诊断字段 `trig/edge/rise/fall/to/us`。现场数据 `trig=3711 edge=5574 rise=2787 fall=2783 to=962 us=38736`：trig 10/s、edge 20/s、rise≈fall → **触发和双边沿都正常**，问题在"脉宽换算"。`us` 是 28000~70000 的原始周期数。

**M1c**：ISR 里 `cycles / cycles_per_us`（按实际 ICLK 90 MHz）→ 28000~70000 ÷ 90 ≈ **311~778 µs → 5.3~13.3 cm**，量程合理了。

**M1d**：`SystemCoreClock` 不可靠（M1d 现场仍出现 `us=57020`）。改成 `cycles_per_us = (SysTick->LOAD + 1) / 1000`，直接用 1 ms 重装值反推，不再依赖时钟变量；日志加 `c/us=90`、`cpus=90` 便于判读。

**当时没做**：不用 GPT；Echo 不分压（分压会误判）；Trig 不直连 3.3 V（HC-SR04 VIH≈3.5 V，要电平转换）。泡沫造成的超声误判留到 M2 之后再谈。

**依据**：`Docs/HC-SR04接入_M1_20261119.md`；标签 `v2.8.0-LEVEL-M1`、`-M1a`…`-M1d`。

### v2.8.0-LEVEL-M1e（2026-11-20）· 为了弱肥皂不被 trim 吃掉（第二次误判）

**当时看到的**（M1d 现场日志）：

- 标定：DRAIN 301.4 / RECOVER 315.7；
- 第一次肥皂水：EC≈339~341、`dEC≈+21`、dNTU −2.6 → `UNCERT/L1/DRAIN`（对）；
- 同一份稀释第二次：EC 331→329、`dEC +14 → +5`（3 秒内）、`g 1.045 → 1.015`（EC0 被抬高）、dNTU +2~4 → **CLEAR/L0/RECOV**；
- 当时 `d1 = 5%×315.7 ≈ 15.8`，trim 区间是 `5 ≤ dEC < 15.8`——**+14 正好落进去**，每 50 ms 把 EC0 拉 0.2 mV，14→5 就 CLEAR 了。

**当时判断**：① 不是超声判错——那时超声只输出 `# LEVEL`，**没接入判定**；② 直接原因是**弱肥皂偏移被 trim 学掉**。

**改了什么**：`ec_d1_pct` 5% → **4%**（`d1 ≈ 12.6`，+14 > 12.6 → L1）；trim 上限收到 **0.7×d1 ≈ 8.8**（+14 不进 trim，第一次 +21 也不进）。

**结果**（预期表）：清水 −7~+5 → CLEAR；两次肥皂稀释 +21 / +14 → UNCERT/L1/DRAIN；典型肥皂 → SOAP/L2。注意这两次 NTU 都没明显上升，所以不会标 SOAP，但至少不回收。

**当时没做**：没把 d2 降到 4~5% 去标 SOAP（清水误判风险）；没让超声立刻参与判定——推迟到 M2。

**依据**：`Docs/第二次肥皂水误判_M1e_20261120.md`；标签 `v2.8.0-LEVEL-M1e`。

### v2.8.0-LEVEL-M2（2026-11-20）· 为了液位变化时别拿旧状态做决定

**当时看到的**：同一份肥皂水，前半段 `UNCERT/L1/DRAIN`、后半段 `CLEAR/L0/RECOV`；液位 **100 → 65 → 32 → 60 → 114 → 100 mm** 明显变化，超声 `valid=1`、读数正常。后半段 CLEAR 的两个因素：液位变化改变了 EC 平台，而决策还在用旧槽；`ec_hyst_ratio=25%` 把 L0 保持上限抬到 `1.25×d1≈15.9 mV`，`dEC +14~+16` 就留在保持区内。

**改了什么**：

- 新增 `app_level_task()`：`abs(rate) > 5 mm/s` → `level_hold=true`（稳定计时清零）；`1 < abs(rate) ≤ 5 mm/s` 过渡带保持 hold；`abs(rate) ≤ 1 mm/s` 持续 1 s → 释放；液位无效或 `<10 mm` → 释放并回退 v2.7.6 逻辑；
- `level_hold=true` 时禁止基线 trim；
- `ec_hyst_ratio` 25% → **10%**（保持上限 1.10×d1 ≈ 13.9 mV），`dEC +14~+16` 不再留在 CLEAR。

**结果**：弱肥皂稳定段从 CLEAR 变 `UNCERT/L1/DRAIN`；清水稳定时仍 CLEAR。

**M2a ~ M2f 的连续修正**（都是"第一次接进判定"踩的坑）：

| 小版本 | 现象 | 改动 |
|---|---|---|
| M2a | 液位变化时冻结槽切换会插一段 WAIT，状态跳变 | 只冻结基线，不插 WAIT 区间 |
| M2b | 基线无效时仍不选槽 | 即使 hold 也强制选槽 |
| M2c | 标定期 "water_dirty" 与"真有水"分不开 | 用液位确认"腔内有水" |
| M2d | 液位确认把清水 AO 门也绕过了 | 液位只区分 water_dirty，保留清水 AO 门 |
| M2e | 冻结槽切换导致 RECOVER 用 DRAIN 基线（dEC 0→+14~18） | hold 只冻结 trim，不冻结槽切换 |
| M2f | 仍按"最近 EC"选槽，噪声会带错 | 改为**阀位优先**：槽由阀位决定，EC 只做 FULL 判定和数值校验 |

**依据**：`Docs/M2_液位门控_20261120.md`；标签 `v2.8.0-LEVEL-M2`、`-M2a`…`-M2f`。

### v2.8.0-LEVEL-M2g（2026-11-21）· 为了 AO 偏低时标定不要整个失败

**当时看到的**：

  ec=303.3 (ec_dry=60.0)
  ao=2373.0 (ao_dry=2337.0)
  mm=144

AO 只比干态高 36 mV，没过 `AO_DRY+80=2417` → `water_dirty`；超声 `mm=144 valid=1` 完全正常，**不是超声的问题**。

## 6. 贯穿全项目的四个老问题

这四件事几乎每一版都在绕，记录下来比记版本号更有用。

### 6.1 基线取错了地方（v2.0 → v2.1 → v2.3 → v2.4.3 → v2.6 → v2.7.4 → M2g）

最早（v2.0 之前）在**空气**里采"水中基线"：EC0=58 mV，于是空腔 ΔEC≈0 判清水 → 回收空气。
v2.0 改成显式标定；v2.1 拆成"空气参考 + 确认浸没后湿态"；v2.3 修正了"水比空气高"的方向错误；v2.4.3 发现基线采在**进水上升沿**（294 而非 324）；v2.6/v2.7 发现**每个阀位/液位都是一个平台**（258 / 305 / 333）；v2.7.4 发现**肥皂冲洗水能冒充本底**；M2g 则在 AO 偏低时选择"降级继续 + 告警"。

> 一句话：**基线永远是这个项目最容易错的地方**——它错了，后面所有阈值和判断都跟着错。

### 6.2 阀换向的干扰（v2.2 → v2.6 → v2.7 → M2）

- 换向让 EC 漂 +6~+16 mV（5%），比 d1 还大 → v2.2 用百分比阈值 + 两拍去抖压住；
- 水力瞬态持续 1.5~2 s，而屏蔽窗只有 400 ms → v2.6 加到 1500 ms；
- 换向同时改变液位平台 → v2.6/v2.7 按阀位分槽；
- 液位在变时用旧槽 → M2 用液位 hold 冻结 trim、M2f 改阀位优先选槽。

> 结构项（探头位置、流路、消泡）始终是根治手段，软件只是在绕开它。

### 6.3 判据其实一直在测"液位"（v2.0 → v2.8）

v2.0 诊断报告的原话是："这套装置现在测的不是水脏不脏，而是电极有没有被水淹到。"
之后所有阈值修补都在回避这个事实，直到 v2.8 把液位真的测出来（M1），再让液位参与门控（M2）、确认标定水体（M2g）。

> 这也是为什么 M1/M2 的改动量远大于一次阈值调整——它补的是一个**缺失的物理量**。

### 6.4 基线会被"学"掉（v2.7.1 → v2.7.6 → M1e）

为了跟住液位漂移，v2.7.1 引入 4 mV/s 慢跟踪；结果它把肥皂偏移也当漂移学掉（+30 → +22）。
v2.7.6 把跟踪限制在 `5 mV ≤ abs(dEC) < d1`；M1e 又把上限收到 `0.7×d1`，因为 +14 的弱肥皂也落在区间里。

> 教训：**任何"自适应/自学习"都要有明确的禁区**，否则等于给脏水开后门。

## 7. 现在这套系统怎么跑（现状快照）

1. **上电**：P104 第一条外设操作锁排空 → LED/UART/OLED → ADC → DS18B20 自检 → pipeline/decision → 开机自检（空腔 3 s 干态 → 等水 → 湿态 2 s）。
2. **标定**：首轮或长按 K2 ≥3 s → 三段（DRAIN → RECOVER → FULL，FULL 最多等 15 s）→ 每段过 CV/量程/5 mV 漂移/AO 清洁（AO 只在第一段查）→ 三槽写入；中途长按 = 跳过，写默认 348/2659。
3. **判定**：工况门（有水/稳定/可测）→ 槽按**阀位**选；FULL 槽有效且 EC 到 FULL 平台（≥FULL−10 mV）时优先 FULL；阀位槽无效时用 30 mV 内最近有效槽兜底，都没有就保留当前基线走 L1 → EC/NTU 双通道分级（L0 可回收 / L1 排空 / L2 含皂排空）→ `PERMIT = (level == L0)`。
4. **液位**：每 100 ms 一轮；`>5 mm/s` 冻结 trim（不冻结判定）；稳定 1 s 释放；无效则回退纯 EC/NTU。
5. **安全侧**：无合法基线 → FAULT/DRY/排空；阀驻留 500 ms、连续吸合 ≤120 s、超时释放 + 10 s 冷却、引脚回读自检；OLED/CSV/事件行都不作为阀动作的唯一依据。

## 8. 还没做完的事（按优先级）

1. **重构后源码重新编译与回归**：本机无 ARM 工具链，`src/` 重构后还没出过新 hex；
2. **Flash 持久化**：三槽基线仍只在 RAM，掉电即失（FSP `r_flash_lp` 未接入）；
3. **结构/探头**：水力瞬态 1.5~2 s、探头位置对 EC 的影响，软件只能缓解；
4. **NTU 对泡沫不敏感**：肥皂冲洗水常常"只升 EC 不升 NTU"，目前只能判 L1 排空、标不了 SOAP；
5. **FULL 槽经常 INVALID**：需要标定时保持进水，或改机械定液位；
6. **流量计暂缓**：30~120 ml/min 量程太小、旁路分流比不稳定，暂不信流量；
7. **失水尾部瞬态**：探头脱水瞬间 dNTU 冲高，会先 SOAP 再 DRY（动作安全，日志不干净）；
8. **液位自身的局限**：泡沫、水面倾斜、温漂都会影响 HC-SR04，目前只做门控和"有水"确认，不单独作判据。

**标定与验收**：清水冲腔 2~3 次 → 上电自检或长按 K2 ≥3 s → 看 `# BASELINE SLOT DRAIN/RECOVER/FULL` → 放清水应 `CLEAR/L0`；出现 `CAL WARN` 必须人工确认是清水；液位无效时系统应回退 v2.7.6 逻辑仍能判水。

**回滚**：烧 `v2.7.6-B3.hex` 或 `git checkout v2.7.6-B3`；回滚后必须重做两段标定（基线只在 RAM）。

## 附录 B：术语

| 术语 | 含义 |
|---|---|
| EC | 电导率代理量，用 TDS 通道电压（mV）表示，不是标定电导率值 |
| EC0 / NTU0 | 当前基线（清水本底）的 EC / 浊度电压，三槽各一条 |
| dEC / dNTU | EC 相对基线的偏移（mV）/ 浊度相对基线的变化（%） |
| g | `g = EC / EC0`，工况门用 `g ≥ 0.30` 初判有水 |
| σ | 基线期 EC 标准差，阈值按 σ 自适应 |
| d1 / d2 | 分级阈值：d1 可清上限、d2 含皂下限 |
| L0 / L1 / L2 | 判定等级：可回收 / 不确定排空 / 含皂或明显脏排空 |
| regime | 工况：FAULT / DRY / SETTLE / MEASURE / LOCKOUT |
| 槽（slot） | DRAIN / RECOVER / FULL 三条基线，对应阀位与液位平台 |
| trim | 基线慢跟踪（4 mV/s），只在 `5 mV ≤ abs(dEC) < 0.7×d1` 生效 |
| hold | 液位冻结标志，`abs(rate)>5 mm/s` 置位、稳定 1 s 释放，只冻结 trim |
| CAL WARN | M2g 降级标定告警：AO 偏低但液位+EC 已确认有水，继续标定须人工确认清水 |
| fail-safe | 断电/复位/异常时阀回排空，回收支路关闭，主排水路常通 |
