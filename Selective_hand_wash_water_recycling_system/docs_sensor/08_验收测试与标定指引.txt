 文件：08_验收测试与标定指引.txt
 内容：传感器接入后的台架验收 T0~T10、阈值标定方法、故障排查、报告口径
 目标工程：Selective_hand_wash_water_recycling_system（RA4M2_MINI，FSP 6.6.0）

【0】本文怎么用、安全前提
------------------------------------------------------------------------
本文是"上板之后"的验收手册，不是编译教程。编译/接线见 00 文档第 3~5 节。
三条安全前提（每次上电前默念）：
    ① 断电接线：插拔杜邦线、改分压、换探头前，先拔 USB/断电；
    ② 先量后猜：怀疑没供电/没跑程序，先用万用表和串口自检区分，不要瞎改代码；
    ③ 一次只改一处：改完立刻复测并记录（调试日志由丙统一记）。
所有"示例值"仅示意；本文引用的实测值只有一处：实验 2（2026-10-21）报告里的
自来水 1490.6 mV、空气 1649.1 mV、高浓度皂液水 2356.3 mV、自来水段单点噪声 0.32%
——引用时必须注明"实验 2 实测，本台架需复测"。
⚠ 报告口径（红线）：浊度只写"相对变化/相对值"，不写 NTU；TDS 只写 mV/Δ/σ 倍数，
  不写"绝对 ppm 达标"；不声称"识别出污染物种类"。


【1】测试环境与工具
------------------------------------------------------------------------
硬件：RA4M2_MINI + TDS 模块及探针 + DS18B20 防水探头 + 浊度模块（4 针 G/A/D/V）
      + 4 线探头 + 分压电阻（1k+2k+0.1µF）+ Type-C 数据线 + PC（SSCOM/串口助手）。
水样：自来水（本底）、洗手液水（0.5 / 1.0 / 2.0 mL/L，用注射器配）、冲洗后的低浓度水、
      清水/浑水（浊度方向确认，用少量泥土/粉笔灰）；温度计（对照 DS18B20）。
工具：万用表、量杯、秒表（手机即可）、纸巾/干布（漏水应急）。
记录：每步一张记录表（本文末尾有空白表头可直接抄）。


【2】上板前检查（断电！用万用表，逐项打勾）
------------------------------------------------------------------------
□ 3V3：U1-12 对 GND = 3.25~3.35 V（上电后测）
□ TDS AOUT 对 GND：0~2.4 V（通电、探头入水；若 >3.0 V 禁止接 P014）
□ 浊度分压节点对 GND：≤3.2 V（模块 5V 供电、探头入水/浑水各测一次；1k+2k 时 3.0~3.13V）
□ 分压电阻实测：R1≈1.0kΩ、R2≈2.0kΩ（5% 误差内；用 1% 电阻更好）
□ DS18B20：VDD=3.3V、GND 通、DQ 对 3.3V 约 4.7kΩ（上拉）
□ 所有 GND 共地通（蜂鸣档）；5V 外设只从 VIN 取电
□ 开发板无割线/焊接痕迹（借的板子，赛后收回）
□ P104（若接阀）有 10kΩ 下拉，阀断电=排空口通


【3】T0 上电自检
------------------------------------------------------------------------
操作：接好线 → 上电 → 观察 LED1 与串口。
通过标准：
    ① LED1 上电快闪 3 下（说明程序在跑，与串口无关）；
    ② 串口出现：
         # [BOOT] SENSOR-NODE v1.1 build <日期> <时间>
         # board: RA4M2_MINI (R7FA4M2AD3CFL) | tick base: SysTick 1 ms
         # display: OLED OK (SSD1306 128x64, I2C0 @0x3C)   （OLED 不可用时为 WARN 行）
       以及帮助文本、CSV 表头（# 开头）；
    ③ 之后每 200 ms 一行 CSV，t_ms 递增、无乱码。
不通过处理：
    - 无 BOOT 行但 LED 闪：串口选错 COM/波特率非 115200/串口助手没重开 → 重开；
    - LED 不闪：没烧录 / BOOT 开关在 ON / 程序停在调试断点 → 重新烧录/复位；
    - 乱码：波特率/时钟问题 → 确认 115200、12MHz 晶振。
记录：T0 通过 □  实测串口首行：____________________________


【4】T1 串口命令链路
------------------------------------------------------------------------
操作：串口助手（勾选发送新行）依次发 H、P。
通过标准：
    H → 打印命令帮助（H/M/R/E/B/T/C/P/V1/V0/VA 都有说明）；
    P → 打印：版本、引脚、基线状态、当前阈值 d1/d2、传感器状态（TDS/浊度/水温来源）、
        事件状态（active/inactive）、手动覆盖状态。
记录：T1 通过 □  备注：____________________________


【5】T2 DS18B20 水温
------------------------------------------------------------------------
5.1 正常读数
操作：探头放进水里 10 s，看 CSV 的 t_Cx100 与 src：
通过标准：
    src=DS，t_Cx100/100 与水温计相差 ≤0.5 ℃（DS18B20 标称 ±0.5℃），2 s 更新一次。
5.2 拔线故障与兜底
操作：运行中拔掉 DS18B20 的 DQ（或 VDD），等 10 s；再发 C。
通过标准：
    ① 串口出现 WARN（连续无效 3 次后停用），src 变 FIX，temp=25.00℃，CSV 继续输出；
    ② 不会出现"0.00℃ 把温补放大"的旧 bug（实验 2 踩坑：DQ 被拉死时暂存器全 0、
       CRC 恰为 0，会误判 0.00℃——本驱动已用"全 0/全 FF 判无效"挡掉）；
    ③ 插回后发 C → 出现 found 提示，src 恢复 DS。
5.3 手输温度
操作：发 T24.5。
通过标准：src 变 MAN、t_C=24.50；再发 T 越界值（如 T99）→ 提示 bad temperature。
记录：T2 通过 □  实测水温=____℃  DS 读数=____℃  src=____


【6】T3 TDS 通道
------------------------------------------------------------------------
6.1 通道合理性
操作：探头悬空（空气）→ 插入自来水 → 插入清水/皂液水，各稳定 10 s。看字段 tds_adc/tds_mv。
通过标准（方向与量级判据，具体数值以台架实测为准）：
    ① 悬空时 tds_mv 是一个中间值（开路伪值，实验 2 约 1649 mV），**不是 0**；
    ② 入水后 tds_mv 明显变化并稳定（实验 2：自来水约 1491 mV）；
    ③ 皂液水（高浓度）tds_mv 上升（实验 2：约 2356 mV，正相）；
    ④ note 不为 TDS_RAIL（若 RAIL：AOUT 接错/过压/分压问题，立即断电检查）。
6.2 贴轨/饱和保护
操作：把 AOUT 临时接 3.3V（模拟过压），看 note；恢复接线。
通过标准：note=TDS_RAIL，decision 动作保持 DRAIN（安全侧），串口有 WARN。
6.3 接触不良自检
操作：轻轻晃动 AOUT 杜邦线。
通过标准：读数不应跳变；若读数卡在固定值且入水不变 → 接线不良（实验 2 踩坑：
          AOUT 接触不良时空气读数约 2979 mV 且入水不变）。
记录：T3 通过 □  空气____mV 自来水____mV 皂液水____mV  note=____


【7】T4 浊度通道与方向确认
------------------------------------------------------------------------
7.1 分压链路核对
操作：探头先放清水，再放浑水，记录 ntu_node_mv（分压节点）与 P 命令里的 ao_mv 换算。
通过标准：
    ① ntu_node_mv 与万用表实测分压节点电压一致（误差 ≤3%）；
    ② ao_mv = node_mv × (R1+R2)/R2 ≈ node_mv × 1.5（1k/2k 时）；
    ③ note 不为 NTU_RAIL；节点电压 ≤3.2 V（1k+2k 时约 3.0~3.13V）。
    ④ 模块 D（DO）端子悬空未接板（5V 输出，接 3.3V 引脚会超压）；探头 4 线按丝印对插。
7.2 方向确认（必做，不同批次可能反相）
操作：清水稳定 10 s → 浑水稳定 10 s → 记录 ntu_node_mv 变化方向。
判断：
    清水电压高、浑水电压低 → 默认配置正确（ntu_clear_high=true）；
    清水电压低、浑水电压高 → 反相批次：把代码里 pipeline 配置的 ntu_clear_high
    改为 false 后重新编译（改 app_main.c 里 pipeline_cfg_t 初始化那一行）。
验证：改完后清水 → 浑水时 ntu_dpctx10 应为正（>0 表示更脏），浑水 → 清水回落到 0 附近。
7.3 无 NTU 标定声明核对
通过标准：不得出现把浊度换算成 NTU 的数值/结论，报告里不写 NTU；CSV 里的
          ntu_adc / ntu_node_mv / ntu_dpctx10 只是"相对通道/相对变化"字段
          （字段名 ntu_ 仅作通道标识），不是 NTU 读数。
记录：T4 通过 □  清水节点____mV 浑水节点____mV 方向=____  ntu_clear_high=____


【8】T5 基线自校准（关键步骤）
------------------------------------------------------------------------
操作：
    ① 把 TDS 探头与 DS18B20 一起放进"本底水"（自来水），探头不碰杯壁/杯底；
    ② 发 B（或上电时已自动采基线——注意上电时探头必须已在水里，否则重采）；
    ③ 观察 "# BASELINE start n=20" → 约 1 s 后 "# BASELINE OK ..."。
通过标准：
    a) 打印 ec0（mV25）、ntu0（AO mV）、sigma_ec、sigma_ntu；
    b) sigma_ec 应明显小于后续皂液引起的 ΔEC（工程判据：ΔEC/σ ≥3 才算看得见，
       见项目设想 6.3 实验 1 的通过标准）；
    c) 静止水中连续 3 分钟，ec0/ntu0 漂移 ≤1%（漂移大=气泡/探头松动/温度变化）；
    d) note=OK，没有 NO_BASE。
⚠ 若上电时探头在空气里，基线是开路伪值 → 必须把探头放进水后按 B 重采。
记录：T5 通过 □  ec0=____mV  ntu0=____mV  σ_ec=____mV  σ_ntu=____mV
      3 min 漂移=____%


【9】T6 判据响应小实验（受控梯度；决定阈值怎么标定）
------------------------------------------------------------------------
目的：回答两件事——① TDS 对"真实洗手水浓度"有没有可辨响应；② 浊度是否补得上。
样品（每杯 300 mL，同一次实验内比较；用同一只杯子/同一水深，换样前用纯净水冲探头并甩干）：
    ① 自来水（本底，先测 EC0）
    ② 洗手液 0.5 mL/L
    ③ 洗手液 1.0 mL/L
    ④ 洗手液 2.0 mL/L
    ⑤ 真实模拟样：按实际洗手流程搓 30 s 后收集的皂液水（可选）
操作（每样重复 3 轮，轮间重新按 B 校准本底）：
    探头入样 → 等 20 s 稳定（实验 2 实测入水约 3.8 s 进 ±1% 带，取 20 s 更稳）→
    记录 30 s 的 CSV（约 150 行）→ 发 M 打标记 → 换样。
记录表（每次实验填一行，ΔEC 用 05 文档的 tds_dmvx10/10）：
    样品 | 浓度 | 水温 | 均值 mV25 | σ(mV) | ΔEC(mV) | g | Δ/σ | ΔNTU% | 判定
通过标准（工程判据，来自项目设想 6.3）：
    ① 单调性：随浓度升高，ΔEC 是否单调上升（单调=判据有物理依据，答辩能讲原理）；
    ② 分离余量：ΔEC(1.0 mL/L) ÷ σ ≥ 3（≥3 才认为判据成立；<3 必须扩大维度/降级，
       见项目设想第 7 节降级 A/A+）；
    ③ 浊度：至少有一档浓度/真实样出现 ΔNTU% 明显变化（用于双判据）。
    ④ 若 ΔEC 很小（只有几 mV）且与 σ 同量级：如实记录 → 阈值保持保守默认/转为辅判据，
       报告写"受控实验结论"，不许编造。
记录：T6 完成 □  实验日期____  结论：____________________________


【10】T7 状态机与假执行器（闭环链路）
------------------------------------------------------------------------
10.1 演示脚本（每次 1 轮，做 10 轮）
    ① 探头在本底水里，按 B 校准；
    ② 发 R：应看到 # EVENT start=MANUAL，state=FLUSH、action=DRAIN（LED 5 Hz 快闪）；
    ③ 约 2 s 后自动结束 FLUSH：若 ΔEC 小 → CLEAR（LED 常亮、RECOV）；
    ④ 把探头移入 1.0 mL/L 洗手液水：ΔEC 上升/变化率超限 → SOAP（LED 灭、DRAIN）；
       记录"从探头入皂液水到 STATE 变化"的延迟（看 CSV 的 t_ms 差，或用秒表/录屏逐帧）；
    ⑤ 移回自来水：ΔEC 回落 → CLEAR（恢复 RECOV）；
    ⑥ 发 E：# EVENT end=MANUAL → WAIT（DRAIN，LED 1 Hz 慢闪）。
10.2 通过标准
    a) 10 轮中，状态迁移每次都能在串口日志里看到，且无"阈值附近反复跳变"（迟滞生效）；
    b) 判定延迟：从"ΔEC 越过阈值"到 STATE/ACTION 变化 ≤400 ms（200 ms 块 + 打印周期余量）；
       变化率抢先触发的延迟应更短（≤250 ms）；记录 10 次均值+极差；
    c) 无基线/故障时始终 DRAIN（安全侧）；R/E 与超时都能回 WAIT。
10.3 记录表
    轮次 | 清水→CLEAR(t_ms差) | 入皂液→SOAP(t_ms差) | 回清水→CLEAR(t_ms差) | 有无抖动 | 备注
记录：T7 通过 □  平均判定延迟=____ms  最大=____ms  抖动次数=____


【11】T8 故障与 fail-safe
------------------------------------------------------------------------
逐项做（每项只做一次，做完恢复）：
    a) 拔掉 TDS AOUT：应出现 RAIL/异常 → action=DRAIN；恢复后读数正常；
    b) 拔掉 DS18B20：连续 3 次无效后停用、回退 25℃，CSV 不断流；发 C 可恢复；
    c) 把 P013 分压节点短到 GND / 断开分压：note 出现 NTU_RAIL 或异常 → DRAIN；
    d) 复位重启（运行在 CLEAR 时按复位）：上电后必须先是 WAIT/DRAIN（LED 1 Hz 慢闪、不常亮），
       绝不允许上电直接进入 RECOVER；
    e) 若已接阀（APP_USE_VALVE=1）：运行中拔 12V/断电 → 阀应回排空口；
       拔掉 ADC 后阀保持排空。
通过标准：以上 5 项动作方向全部正确、串口有对应 WARN/ERR、无复位/死机。
记录：T8 通过 □  异常项：____________________________


【12】T9 稳定性与重复性（30 min）
------------------------------------------------------------------------
操作：探头静止在本底水中，连续记录 30 min CSV（不发任何命令）；
通过标准：
    ① 无死机/复位/串口断流；
    ② 基线漂移（首尾 30 s 均值差）≤2%；σ_ec 无趋势性增大（电极污染/气泡早期信号）；
    ③ 时间轴无跳变：t_ms 与墙钟偏差 ≤1%（SysTick 时基，1-Wire 关中断丢 tick <0.3%）。
记录：T9 通过 □  30min 漂移=____%  σ_ec 首/尾=____/____mV


【13】T10 板载 OLED 状态页（现场指示，不是数据来源）
------------------------------------------------------------------------
前提：已按 00 文档 4.3 在 RASC 加好 I2C0（g_i2c_master0：P407=SDA / P408=SCL、
      0x3C、400 kHz），并装好 oledfont.h/oled.h/oled.c/display.h/display.c；
      OLED 是板载 0.96" SSD1306 128x64（模块自带 4.7 kΩ 上拉），不需要任何外部接线。
⚠ 红线：OLED 只是现场指示器，不是数据来源、不是安全执行路径；数据留痕以串口 CSV 为准。

13.1 上电页面链（开机页 → 基线页 → 待机页）
操作：断电重启，眼睛看 OLED、同时看串口。
通过标准：
    ① 上电 OLED 亮，显示开机页 5 行：
         "RA4M2 WATER JUDGE" / "OLED OK"（8x16）/ "SSD1306 128x64" /
         "I2C0 0x3C 400kHz" / "SENSOR-NODE v1.1"；
    ② 保持约 800 ms（DISPLAY_BOOT_HOLD_MS）后切状态页：基线采集中 → 大字"待机"、
       第二行 "BASELINE  n/20"、第三行 "hold probe in water"；采满 20 点后 → 待机页
       "WAIT   EV:OFF"；
    ③ 串口出现 "# display: OLED OK (SSD1306 128x64, I2C0 @0x3C)"。
    ⚠ 上电时 TDS 探头必须已在本底水里，否则基线页采到的是空气伪值（见 T5）。

13.2 大字与两行状态串（逐状态核对）
操作：按 T7 的演示脚本走一轮 R →（清水）→（入皂液）→（回清水）→ E，逐状态看 OLED。
通过标准（大字 32x32 在 y=8，第二行 8x16 在 y=40，第三行 6x8 在 y=56）：
    ① WAIT  ：大字"待机"；第二行 "WAIT   EV:OFF"（无事件恒排空）；
    ② FLUSH ：大字"冲洗"；第二行 "FLUSH  DRAIN"；
    ③ CLEAR ：大字"清水"（正显）；第二行 "CLEAR  RECOVER"；
    ④ UNCERTAIN：大字"污水"（反显=白底黑字）；第二行 "L1 UNCERTAIN"；
    ⑤ SOAP  ：大字"污水"（反显）；第二行 "L2 SOAP  DRAIN"；
       （④⑤ 大字相同，只有第二行状态串不同，用来区分 L1/L2）
    ⑥ 正常态第三行数值示例 "dEC+12mV g1.008 N+5"（dEC 为 mV 有符号、g 三位小数、
       N 为方向归一化浊度相对 %）；状态/大字变化立即刷新，数值最快 200 ms 刷一次。

13.3 基线进度页 / 无基线页 / 故障页
通过标准：
    ① 发 B（或 K2 长按）→ 大字"待机"、第二行 "BASELINE  8/20"、第三行
       "hold probe in water"；采满后自动回正常页；
    ② 无基线（NO_BASE）→ 大字"故障"、第二行 "L1 NO_BASELINE"、
       第三行 "send B in water"；
    ③ 传感器故障 → 大字"故障"、第二行 "L1 SENSOR_FAULT"、第三行
       "note=ADC_TIMEOUT"（或 note=TDS_RAIL 等 p_out->note，截断到 20 字符）。

13.4 故障注入（显示不是安全路径；板载 OLED 焊死，禁止拔线/拆焊/短接）
操作（二选一，验完必须改回 0x3C）：
    A) 代码法（最快）：把 src/oled.h 的 OLED_I2C_ADDR 临时改成 0x3D → 重新编译烧录；
    B) RASC 法：把 4.3 的 Slave Address 改成 0x3D → Generate → 重新编译烧录。
    原理：屏幕不应答 → I2C 传输失败 → display_task 连续失败，模拟"屏丢失/坏屏"。
通过标准：
    ① 上电串口先打印 "# WARN: OLED not usable -> UART only (display is NOT safety path)"，
       随后只打印一次 "# WARN: OLED lost at t=... ms -> UART only"（连续 3 帧失败才报），
       OLED 黑屏/不刷新；
    ② CSV 继续输出，state/level/action 不变，LED 照常；期间照样能完整走一次 R/E 演示；
    ③ OLED 失效不影响判别、CSV、LED 与阀（显示不是安全执行路径）；
    ④ 改回 0x3C 并重新编译烧录后 OLED 恢复正常。
    ⚠ 不要用"拔杜邦线"或"短接 P407/P408 到地"的方式做这个实验：OLED 是板载焊死的，
      短接可能损伤 I2C 引脚/屏幕；也不要在运行中热插拔板载器件。

13.5 字库、可读性与记录
通过标准：
    ① 5 个 32x32 汉字（清水/污水/待机/冲洗/故障）清晰、无缺笔画、无乱码；
       无花屏/残影；反显"污水"是白底黑字，与正显的"清水"一眼可分；
    ② 字库只有 9 个汉字（不能显示任意中文），这是设计约束，不是"缺字 bug"；
    ③ 刷新 ≤2 Hz（状态变化立即 + 数值最快 200 ms + 1 s 心跳），不闪烁、不撕裂。

【14】阈值标定方法（用 T6/T7 数据，不拍脑袋）
------------------------------------------------------------------------
标定原则：阈值只能建立在"本队实测数据"上（项目设想 6.4 纪律）；换水样/季节/地点要复测。
14.1 先算噪声 σ
    用 T5/T6 自来水段 30 s 数据：σ_ec = std(tds_mv25)、σ_ntu = std(ntu_node_mv 换算的相对量)。
    若 σ_ec 明显大于实验 2 的 0.32%（说明气泡/流动/接触噪声大）→ 先修流动池/固定探头，
    而不是把阈值放大到"永远判不清"。
14.2 再按噪声倍数设 d1/d2（推荐区间）
    d1(EC) = max(4σ_ec, 8 mV)     —— 低于它才算"干净到可回收"
    d2(EC) = max(8σ_ec, 20 mV)    —— 高于它才算"明显含皂液特征"
    若 T6 显示真实洗手水 ΔEC 只有 3~5σ：把 d2 收到 5σ 左右，但必须用 T7 验证不误触发；
    若 ΔEC 与 σ 分不开（<3σ）→ 按项目设想第 7 节走降级 A/A+，并在报告如实写。
    浊度：d1=8%、d2=25%（相对基线 AO 电压）；有 T6 数据后按实际响应调整。
14.3 变化率阈值
    用 T7 记录的"入皂液瞬间"数据：取 ΔEC 从 X 到 Y 的斜率（CSV 的 ec_ratex10/10），
    以"正常清水波动 P99"与"皂液到来最小斜率"之间取中值；默认 40 mV/s + 跳变≥5 mV。
14.4 改在哪里
    app_main.c 顶部集中配置：pipeline_cfg_t（滤波/基线/分压参数）、decision_cfg_t
    （d1/d2/σ 倍数/迟滞/变化率/块消抖/超时）。改完重新编译，按 T7 复测 10 轮。
14.5 记录（标定台账，答辩要用）
    日期 | 水样/地点 | σ_ec | d1 | d2 | 变化率阈值 | T7 误动作次数 | 判定延迟 | 修改人
⚠ 阈值目标：宁可"多排空"不可"错回收"（安全侧）；报告里写清"本阈值仅在本台架/本水样成立"。

【17】CSV 快速分析示例（可选，PC 端 python；仅本文件提供参考）
------------------------------------------------------------------------
说明：PC 上把串口日志存成 UTF-8 txt（保留 # 注释行）。下面脚本按状态分组统计，
      输出每段的 μ、σ、ΔEC 均值与 Δ/σ，用于填 T5/T6/T7 的记录表。
```python
# analyze_sensor_csv.py（放在日志同目录运行：python analyze_sensor_csv.py 日志.txt）
import sys, statistics
rows = []
for line in open(sys.argv[1], encoding="utf-8", errors="ignore"):
    line = line.strip()
    if not line or line.startswith("#"):
        continue
    p = line.split(",")
    if len(p) < 17:
        continue
    rows.append({"t": int(p[0]), "mv25": int(p[5]) / 10.0, "dmv": int(p[7]) / 10.0,
                 "g": int(p[8]) / 1000.0, "dntu": int(p[11]) / 10.0,
                 "state": p[13], "level": p[14], "action": p[15]})
# 按 state 分段（简单做法：连续相同 state 视为一段）
segs, cur = [], []
for r in rows:
    if cur and r["state"] != cur[-1]["state"]:
        segs.append(cur); cur = []
    cur.append(r)
if cur: segs.append(cur)
for s in segs:
    mv = [r["mv25"] for r in s]; d = [r["dmv"] for r in s]
    mu = statistics.mean(mv); sd = statistics.pstdev(mv) if len(mv) > 1 else 0.0
    dm = statistics.mean(d); dd = statistics.pstdev(d) if len(d) > 1 else 0.0
    print(f"{s[0]['state']:6s} n={len(s):4d}  mv25={mu:8.1f}  sigma={sd:5.2f}  "
          f"dmv={dm:7.1f}  d/sigma={(abs(dm)/sd if sd > 0 else 0):5.1f}  "
          f"dntu%={statistics.mean([r['dntu'] for r in s]):6.1f}")
```
⚠ 该脚本只做分段统计，不做任何"水质达标"判断；报告里引用的是本台架相对值。
