## 0. 先把“设想需求”分成四类

设想文档里混着“必须做到”“必须测出”“有余力再做”“已被实现推翻”四种东西。不分开，就会把加分项当成硬指标，或者把红线当成可选项。

| 类别 | 含义 | 典型条款 | 对后续的含义 |
|---|---|---|---|
| **H 硬需求 / 红线** | 不满足就不算达到设想，或违反即丢分 | 在线判别+分流；三级判定+默认排空；相对基线+上电自校准；最初 1~2 s 不参与基线；≤1.5 s / ≤100 mL；三条安全件；非饮用回用；不编造指标；传感器 ≤3.0 V | **必须逐条闭环**，每条都要有验收证据 |
| **M 量化验收** | 设想明确要求“用数据回答” | ΔEC/σ ≥3；20 次延迟均值+极差；误分水量；清水 60 s 稳定；回收水量/回收率；功耗；四类污染源响应表 | **必须先测**，否则“达到设想”无法证明 |
| **O 可选增强** | 设想自己标注“时间有余再加 / P2 / P3” | 截留腔批式；阻抗 C；ORP；流量计；TSN；ADC 窗口比较/自诊断；DAC 4~20 mA；低功耗；CTSU | **H/M 达标后再做**；不做也不影响“达到设想” |
| **X 例外 / 修正** | 设想里写错、或已被现场证明不可行 | 用 TSN 测水温；读静水本底；普通压力传感器测液位 | **不要照字面实现**；改成等价方案并在报告里说明 |

> **关键区分**：达到设想 ≠ 逐字实现设想。技术上站不住的条款，用等价方案达成，比硬做更像工程。

## 2. 当前最大的三个“设想落差”

### 2.1 落差一：设想的“验收口径”没跑，只有“实现口径”

设想的第一优先级是**实验 1（ΔEC/σ ≥3）**，其次是实验 3/6（延迟、误分水量、定时器对照）。当前项目直接进入了实现和现场调参，导致：

- 没有 ΔEC/σ 余量表 → 无法回答“你凭什么判”；
- 没有 20 次延迟/极差 → 无法回答“≤1.5 s 怎么算的”；
- 没有误分水量 → 无法回答“漏了多少水”；
- 没有定时器对照 → 无法回答“这不就是定时器吗”。

**这不是“再补几个实验”的问题，而是“达到设想”与“做了一个能跑的装置”之间的分界线。** 阶段 A 必须先补这一课。

### 2.2 落差二：H3/H4 被“三段标定”带偏了

设想要的是：**上电自动建立基线、换水不用改阈值、最初 1~2 s 不污染基线**。
当前实现变成了：**上电先测干态 → 等水 → 采湿态 → 三槽标定 → 人工确认 RECOVER**。它解决了现场“阀位平台不同”的问题，但代价是：

- 必须擦干电极才能上电（H3′ 未达成）；
- 湿态基线在浸没后约 0.8 s 就可能开始采，正好落在设想要求“排空、不参与基线”的窗口内（H4 未达成）；
- 三槽/trim 又引入了新的耦合（07:39 日志）。

**达到设想的路径**不是继续加标定闸门，而是：
1. 基线持久化，正常上电只加载；
2. 首次/换水时走**服务模式**标定（可人工确认、可断开回收支路）；
3. 每个用水事件开头 **2 s 强制 DRAIN、禁止写基线**；
4. 基线只在“稳定且有独立有水信号”时更新，`trim` 保持关闭。

### 2.3 落差三：H5/H6 的瓶颈被误判成“阈值”

设想的 1.5 s 预算拆得很清楚：

| 环节 | 设想预算 | 当前 | 差距 |
|---|---|---|---|
| 采样与滤波 | ≤100 ms | 50 ms + EMA | 达成 |
| 触发判定 | ≤300 ms | 速率抢先存在，但只正向/2 tick/受 1.5 s blank 限制 | 部分 |
| 消抖确认 | ≤200 ms | 400 ms 块 / 8 采 / 6 票；L0 要 3 块 = 1.2 s | **未达成** |
| 阀动作 | ≤100 ms | 直动阀；切 DRAIN 不等 dwell | 基本达成 |
| 物理延迟 | τ + 管延迟 | 大腔体 τ 30~200 s；无轴向缓冲 | **未达成** |

所以先改**块长/确认逻辑/blank**，再评估**轴向缓冲（25~50 mL）**，最后才考虑**结构/批式**。继续调 d1/d2 不会把 1.2 s 的 3 块确认变成 0.2 s。

**阶段 B 的退出条件**：H3′/H4/H5/H6/H7 五条硬需求都有实测证据；若仍达不到 H5/H6，明确写出“软件已到极限，需要结构/批式”，进入阶段 C。

### 阶段 C　结构/批式（只在 B 仍达不到时做，3~4 周）

| # | 工作包 | 说明 | 验收 |
|---|---|---|---|
| C1 | 轴向缓冲 / 小腔体 | 先试 25~50 mL 轴向缓冲（0.5~1 m、8 mm 内径）或内杯+立管；测 τ 与误分水量 | 误分水量 ≤100 mL；τ 下降可测 |
| C2 | 截留腔 + 批式 | 100~200 mL、1~3 s/批；溢流旁通、超时冲洗、每批排空不存水；液位用浮球/光电/称重 | 批间隔/容积实测；不积水、不发臭 |
| C3 | 复测 | 重跑 A2/B3/B4 | NFR-1/NFR-2 达标 |

> 注意：C 是**为了达标而做的结构**，不是“把设想里的截留腔补上”。如果 B 已经达标，C 可以不做；如果做，按设想的三条附加要求（溢流/超时/不存水）一起做。

## 5. 与上一份《后续优化方向》的关系

上一份文档是**架构视角**（持久化、结构、安全、性能）；这一份是**设想验收视角**。两者不冲突，映射如下：

| 上一份的动作 | 在本路线里的位置 | 说明 |
|---|---|---|
| 基线持久化 | 阶段 B2 | 为了 H3′（上电不用擦干） |
| 内杯+立管+浮球 | 阶段 C1/C2 | **只在 H5/H6 仍不达标时做**，不是默认第一步 |
| 硬件 IWDT/保险丝 | 阶段 B5 | 为了 H7 与失效安全 |
| 流量计/阀位反馈 | 阶段 B4（若提前）/ D1 | 为了 M5（回收率）与 H7（卡阀） |
| 速率抢先/阈值改造 | 阶段 B3 | 为了 H5/H6 |
| NTU 标定/阻抗/ORP | 阶段 D | 可选增强，不是达标前提 |

**一句话区别**：上一份回答“系统怎么变强”；这一份回答“怎么证明它达到了当初的设想”。如果只做一份，先做这一份的阶段 A——它决定后面要不要动结构。

## 6. 今天与赛后第一周

1. **今天不改代码**；先保演示与版本一致（见 `快速启动卡_现场版.md` / `04_今晚清单与明天流程.md`）。
2. **赛后第一周只做阶段 A**：实验 1/3/5/6 + 安全件核对 + 功耗/成本。不需要新硬件，一个厨房秤、量杯、秒表、串口日志就够。
3. **阶段 A 的产出直接决定路线**：
   - 若 ΔEC/σ ≥3 且延迟/水量已达标 → 设想的核心已经成立，补文档与 20 次统计即可；
   - 若 ΔEC/σ <3 → 走设想的降级 A（现有多维判据已部分在做），不要硬撑单判据；
   - 若延迟/水量不达标 → 先阶段 B3（块长/blank/速率），再阶段 C1（轴向缓冲/结构）；
   - 若安全件有缺 → 先补安全件，再谈性能。
4. **不要先做**：截留腔、阻抗、ORP、CTSU、低功耗。它们会让“还没证明核心”的问题变得更难回答。
