# RECOVER 槽被 AO 门槛误杀修复（v2.7.3-B3）

- 日期：2026-11-19
- 固件：`SENSOR-NODE v2.7.3-B3`
- 构建：`text 84684 / data 480 / bss 11440`，0 error / 0 warning
- 基于：`v2.7.2-B3`

---

## 1. v2.7.2 日志

```
# BASELINE SLOT DRAIN ec0=349.4mV
# AUTOCAL state=SETTLE reason=calib_recover
# SLOTS DRAIN=349.4 RECOVER=INVALID FULL=INVALID
# AUTOCAL state=DONE reason=base_turbid
# BASE slot=DRAIN ec0=349.4mV ec=350.7mV
```

DRAIN 槽成功后，切 RECOVER 仅 **0.8 s** 就以 `base_turbid` 结束，RECOVER 槽没有采到。

运行时：

```
DRAIN   EC≈350 → dEC≈0    → 本应 CLEAR
RECOVER EC≈410 → dEC≈+60  （仍用 DRAIN 基线）
```

于是阀在 DRAIN/RECOVER 之间反复切，状态 CLEAR↔UNCERT。

---

## 2. 根因

`APP_AC_SETTLE` 对每一段都做 AO 清洁检查：

```c
AO < ao_dry + ao_clean_delta(250mV) → base_turbid
```

但同一腔水切到 RECOVER 后：

- 液位/光学路径变化；
- AO 会短时偏低；
- 第一段 DRAIN 已经确认水是干净的，第二段不应再用 AO 复检。

结果把 RECOVER 槽直接丢掉。

---

## 3. 修复

### ① AO 清洁门槛只在第一段 DRAIN 检查

```c
else if ((0U == g_cal_stage)
         && (AO < ao_dry + ao_clean_delta))
```

- 第 0 段 DRAIN：仍防脏水/肥皂当本底；
- 第 1 段 RECOVER、第 2 段 FULL：只要求 `allow_wet`（浸没/水体确认），
  不再因 AO 短时偏低丢掉整个槽。

### ② 没有足够近的槽时，不再作废基线

```c
if (best_d > 30 mV) {
    return;   // 保留当前基线，EC 单独高走 L1
}
```

以前会 `NO_SLOT` 作废，导致 NOBASE 反复出现；现在保留基线，双通道判 L1/排空，不会 NOBASE。

---

## 4. 预期

烧录 v2.7.3 后：

```
# BASELINE SLOT DRAIN   ec0≈349
# BASELINE SLOT RECOVER ec0≈410~418
# SLOTS DRAIN=349 RECOVER=410 FULL=INVALID
# BASE slot=DRAIN ec0=349 ec=350
# BASE slot=RECOVER ec0=410 ec=410
```

两个平台各自 dEC≈0，应稳定 CLEAR。

FULL 仍可能 INVALID：若满水 EC 不超过 `max(DRAIN,RECOVER)+10`，说明没有独立 FULL 平台，两槽已足够；15 s 超时后正常结束。
