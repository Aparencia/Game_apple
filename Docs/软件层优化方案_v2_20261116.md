## 1. 情景整理：一台装置，七种工况

| # | 工况 | 电极 | TDS 读数 | 现在固件 | 现固件后果 | 应该 |
|---|---|---|---|---|---|---|
| S0 | **腔内无液体**（本次日志） | 露空 | 43.7 mV（EC0=58） | ΔEC≈0 → L0 **CLEAR** → **RECOV** | 回收空气：阀 96.7% 吸合、继电器长期通电 | 判"无液体"，DRAIN，不回收 |
| S1 | **有水，水位低于电极** | 露空 | 同一区间 | 同上 → **CLEAR/RECOV** | **回收水**——可能是脏水，进回收箱 | 同上，DRAIN；这是最危险的组合 |
| S2 | 水位淹到电极，清水，静置 | 浸没 | 数百~1500 mV | ΔEC ≫ d2 → **L2 SOAP** → DRAIN | 清水被排掉，**永远回收不到东西** | 采过水中基线后应判 L0 → RECOV |
| S3 | 水位淹到电极，清水，流动/带气泡 | 时湿时干 | 抖动 | L0↔L2 乱跳，30 s 一周期 | 阀反复换向、回收/排空交替 | 只在"浸没 + 稳定"时判，其余 DRAIN |
| S4 | 水位淹到电极，脏水/皂液 | 浸没 | 更高 | ΔEC > d2 → L2 → DRAIN | 方向对（歪打正着） | L2 → DRAIN（**唯一现在做对的**） |
| S5a | **电极脱水**（探头还插着，只是没水） | 露空 | ~58 mV，远低于水中基线 | 大**负**偏离 → **L0 CLEAR** | 脱水时仍回收；且固件把"最安全的样子"给了它 | L1/DRAIN |
| S5b | 探头**开路/断线**、模块未供电、贴轨 | — | 1649 mV（开路伪值）或 0/4095 | 大正偏离 → L2；贴轨 → L1 | 方向碰巧安全，但**原因是错的**（报"脏"而不是"故障"） | L1/DRAIN + 显式故障码 |
| S5c | 基线未标定 / 已漂移 | — | — | `NO_BASE` → L1 | 正确（但上电自动标定把它掩盖了） | `REGIME_FAULT` + 提示 |
| S6 | 换向瞬间（电磁 + 水力扰动） | 扰动 | ±35~38 mV/s | 单点"速率抢先"判 L2 → `auto_start` → **白送 30 s 回收** | 超时→释放→再触发，30 s 自激 | 换向后 400 ms 屏蔽，速率门限 ≥3× 瞬态 |

**这张表就是全部问题**：S0/S1 与 S2 的方向完全相反，而固件没有任何"现在是哪种工况"的概念；S6 又让一次扰动买到 30 秒回收权。

## 2. 归纳：三个根因 → 三条软件对策

| 根因 | 现象 | 软件对策 |
|---|---|---|
| **R1 参考系错**：基线在"电极露空"时采，且与 TDS/浊度共用同一次 1 s 采样 | S0/S1/S2 全反 | **C1 基线管理**：显式采集 + 区间/稳定性校验 + 干/湿双指纹 + 掉电保存 |
| **R2 缺"工况"维度**：判据里只有"EC 比基线高多少"，没有"现在能不能判" | S0/S1/S3/S5 | **C2 工况机**：validity 位图 → regime；非测量工况一律 DRAIN，且不许上报 L0 |
| **R3 把"事件"当"许可"**：单点即可开、只有超时能关、关的动作本身又触发开 | S3/S6 | **C3 回收许可**：把闩锁换成**每个 tick 重算的谓词**，事件只做日志分段 |

> 三者是链式的：R1 让判据失去意义 → R2 让错误判据在错误时机生效 → R3 把一次错误放大成 30 秒的持续动作。

## 3. 总体架构：四层，单向依赖

```
      ┌─────────────────────────── 每 50 ms tick ───────────────────────────┐
 ADC ─┤ pipeline_sample()                                                   │
      │   ├─ 中值 → 换算 → EMA → 基线/特征（现有）                          │
      │   └─ 新增：pipeline_blank(now) 供换向屏蔽                          │
      ├───────────────────────────────────────────────────────────────────┤
      │ gate_update()        ← 新增 validity.c                             │
      │   L0 有效性位图  →  L1 工况 regime                                 │
      ├───────────────────────────────────────────────────────────────────┤
      │ decision_update()    ← 只在 REGIME_MEASURE 里做水质分类            │
      │   L2 水质  →  L3 回收许可（谓词，不是闩锁）                        │
      ├───────────────────────────────────────────────────────────────────┤
      │ app_valve_apply()  阀门 / LED / OLED / 日志 / CSV                  │
      └───────────────────────────────────────────────────────────────────┘
```

原则：**下游只能看上游的结论，不能反推**。`decision` 不再关心"事件"，`gate` 不再关心"脏不脏"。

## 4. L0 有效性位图（新增 `validity.h` / `validity.c`）

```c
typedef enum {
    VAL_SENSOR_OK   = 1u << 0,  /* 两路 ADC 无超时、无贴轨、status==OK */
    VAL_BASELINE_OK = 1u << 1,  /* 基线已标定、未过期、未被判漂移 */
    VAL_IMMERSED    = 1u << 2,  /* 电极被水淹到（见 §6.1） */
    VAL_STABLE      = 1u << 3,  /* 特征量在稳定带内（见 §6.2） */
    VAL_BLANKING    = 1u << 4,  /* 换向后 400 ms 屏蔽窗内 */
    VAL_FLOW        = 1u << 5,  /* 有流量/液位信号（可选，没有就置 1） */
} validity_bit_t;
```

约束：位图**只描述"能不能判"，不描述"判什么"**。任何一位为 0 的时候，都不允许输出 L0。

## 5. L1 工况机（regime）

```c
typedef enum {
    REGIME_FAULT  = 0,  /* 传感器故障 / 基线无效 → DRAIN，报故障 */
    REGIME_DRY,         /* 未浸没（无液体 或 水位低于电极）→ DRAIN */
    REGIME_SETTLE,      /* 刚浸没，等响应稳定（4 s）→ DRAIN */
    REGIME_MEASURE,     /* 浸没 + 稳定 + 基线有效 → 允许判水质 */
    REGIME_LOCKOUT,     /* 预留：故障恢复后的观察期 */
} regime_t;
```

状态迁移（全部带方向性去抖）：

| 迁移 | 条件 | 去抖 |
|---|---|---|
| any → FAULT | `!SENSOR_OK` 或 `!BASELINE_OK` | 立即（不等） |
| FAULT → DRY | 传感器恢复且基线有效 | 1 s 连续 |
| DRY → SETTLE | `IMMERSED` 上升沿 | 连续 500 ms |
| SETTLE → MEASURE | 持续 4000 ms 且 `IMMERSED` 保持 | 到时即迁 |
| MEASURE → DRY | `IMMERSED` 丢失 | **连续 300 ms**（安全侧要快） |
| MEASURE → SETTLE | `STABLE` 丢失（气泡/扰动） | 连续 1 s |
| any → LOCKOUT | 从 FAULT 恢复 | 3 s 观察期 |

**关键**：`REGIME_DRY` 与 `REGIME_SETTLE` 下 `action` 恒为 DRAIN，`level` 恒为 L1（未知）。**"没浸没"不再等价于"清水"**。

## 6. L2 水质判据（只在 `REGIME_MEASURE` 里运行）

### 6.1 浸没判据（`IMMERSED`）

比值法（与电极几何无关），**前提是 EC0 取自水中**：

```
g = EC / EC0
IMMERSED = (g >= WET_RATIO) && (EC >= EC_DRY * 3)
WET_RATIO ≈ 0.30
```

- `EC_DRY` = 干态指纹（本次实测 58 mV25），由标定命令记录；
- 双条件是为了防"清水读数过低"或"基线被写坏"；
- 浊度单独判：`AO <= AO_DRY * 0.98`（空气≈满量程，清水会低一点）——**仅当标定过才启用**，否则不参与。

### 6.2 稳定判据（`STABLE`）

```
STABLE = (|rate_ec| < RATE_STABLE_MV_S) && (|rate_ntu| < RATE_STABLE_PCT_S)
RATE_STABLE_MV_S  ≈ 30 mV/s（约等于干态噪声 3σ）
RATE_STABLE_PCT_S ≈ 5 %/s
```

### 6.3 双侧门限（修 R1 最直接的一刀）

```c
/* 原：只看正向
   if (d_ec > e2) L2;  if (d_ec < e1 && d_ntu < e1n) L0; */
if ((d_ec >  e2_ec) || (d_ntu >  e2_ntu))          return L2;  /* 明显变脏 */
if ((d_ec < -e2_ec) || (d_ntu < -e2_ntu))          return L1;  /* 明显变"太干净"→可疑 */
if ((d_ec <  e1_ec) && (d_ntu < e1_ntu))           return L0;
return L1;
```

**为什么负偏离要拦**：**电极脱水**（水位降到电极以下）、气泡贴附、读数被拉低都会让 EC 掉一大截，而"掉下去"在旧代码里是最安全的样子——这正是 S1/S5a 的漏洞。（注意方向：**拔掉探头是开路，读数反而升到 ~1650 mV**，会误报"脏"；真正危险的是"探头插着但没水"这种 58 mV 的负偏离。）

### 6.4 速率抢先的四个约束

| 约束 | 值 | 作用 |
|---|---|---|
| 方向 | 只认 `rate > +TH` | 变干净不是"变脏" |
| 幅度 | `TH = 120 mV/s`（≈3× 实测瞬态 38） | 远离执行器自身干扰 |
| 持续 | 连续 **2 个 tick** 成立 | 排除单点毛刺 |
| 屏蔽 | 换向后 **400 ms** 内禁用 | 切除 S6 |

### 6.5 块投票

| 参数 | 现值 | 建议 | 理由 |
|---|---|---|---|
| `block_ms` | 200 | **400** | 与 5 Hz CSV、4 s 稳定期匹配 |
| `block_samples` | 4 | **8** | 400 ms / 50 ms |
| `block_agree` | 3 | **6** | 8 中 6，抗气泡 |
| 状态升级 | 1 个块 | **连续 3 个块**（1.2 s） | 防抖 |
| 状态降级（→DRAIN） | 1 个块 | **立即**（安全侧快） | 单侧迟滞 |

## 7. L3 回收许可：用谓词替换闩锁（本方案的核心）

### 7.1 现状 vs 建议

| | 现状（闩锁） | 建议（许可） |
|---|---|---|
| 回收条件 | 事件已开启 且 当前块 = L0 | `PERMIT = IMMERSED && regime==MEASURE && level==L0 && !BLANKING` |
| 开启 | 单点 L2（含速率抢先）即可 `auto_start` | 无"开启"动作，每 tick 重算 |
| 关闭 | **只有 30 s 超时** | 谓词为假的那一 tick 就关（≤50 ms） |
| 超时 | 强制 DRAIN，但超时动作本身又触发重开 | **不存在**（谓词模型里没有"超时"这个概念） |
| `auto_start` | 必需 | **删除** |
| `lockout` | 需要（补丁式） | **不需要** |
| 事件 | 控制信号 | **只做日志分段**（`wet` 上升沿 → `# EVENT start`） |

### 7.2 代码骨架

```c
void decision_update(decision_t *d, const sensor_pipeline_t *pipe, uint32_t now_ms)
{
    const pipeline_out_t *o = pipeline_get_out(pipe);
    gate_out_t g;

    gate_update(&d->gate, o, app_valve_age_ms(now_ms), now_ms);   /* L0+L1 */
    d->out.valid_bits = g.bits;
    d->out.regime     = g.regime;

    if (REGIME_MEASURE != g.regime) {
        /* 非测量工况：没有许可，强制排空，level 上报"未知" */
        decision_apply_output(d, DEC_STATE_WAIT, DEC_LEVEL_L1, DEC_ACTION_DRAIN,
                              gate_reason(g.regime), now_ms);
        d->permit = false;
        return;
    }

    cand   = decision_classify(o, ...);                 /* 只在这是合法的 */
    level  = decision_block_update(d, cand, now_ms);    /* 单侧迟滞 */
    d->permit = (DEC_LEVEL_L0 == level) && g.immersed && !g.blanking;

    decision_apply_output(d,
        d->permit ? DEC_STATE_CLEAR : decision_state_from_level(level),
        level,
        d->permit ? DEC_ACTION_RECOVER : DEC_ACTION_DRAIN,
        reason, now_ms);
}
```

### 7.3 为什么这样能解掉第 2、3 条

- **不再有"事件"这个可停留的状态** → 没有"只在开机进待机"的问题（待机就是 `REGIME_DRY`，随时会回来）；
- **不再有 30 s 计时** → 超时、重开、自激整条链路消失；
- **一次瞬态最多影响 50 ms**，而不再是 30 s；
- `max_on`（120 s 连续吸合）恢复成真正生效的硬件保护，而不是被 30 s 周期喂饱。

### 7.4 事件仍保留，但只用于日志

```c
/* app_main：只做数据分段，不参与控制 */
bool wet_now = (REGIME_MEASURE == d->out.regime) || (REGIME_SETTLE == d->out.regime);
if (wet_now != g_prev_wet) {
    printf("# EVENT t=%lu %s\r\n", now_ms, wet_now ? "start=WET" : "end=DRY");
    g_prev_wet = wet_now;
}
```

## 8. 基线管理（C1）

### 8.1 采集流程

| 步骤 | 动作 | 校验 |
|---|---|---|
| 1 | 排空腔体，按 `D` | 记 `EC_DRY`、`AO_DRY`（60 s 均值，要求 CV ≤ 5 %） |
| 2 | 注满清水（**必须淹到电极**），按 `W` | 记 `EC0`、`NTU0`；要求 **EC0 ≥ 3×EC_DRY**、`CV ≤ 1 %`、采集 ≥ 2 s（40 点） |
| 3 | 自动校验通过 | 置 `VAL_BASELINE_OK`，打印 `# BASE OK ec0=… dry=… ratio=…` |
| 4 | 校验失败 | **不写基线**，保持 `DRY`（fail-safe），打印失败原因 |

### 8.2 三条硬约束

1. **取消上电自动采集**（`app_main.c:1776`）——这是 S0/S1 的直接成因；
2. 基线必须与"干态指纹"成对保存，`WET_RATIO` 才有意义；
3. **掉电保存**（RA4M2 数据 Flash，FSP `r_flash_lp` 或 `r_dflash`）：
   - 否则每次上电都要人工注水标定，不现实；
   - 保存 `{magic, version, EC0, EC_DRY, AO0, AO_DRY, crc}`；
   - 上电读到有效记录 → 直接 `BASELINE_OK`；读不到 → `REGIME_FAULT` + 提示按 `W`。

### 8.3 漂移监控

```
每 10 min：若持续 IMMERSED 且 |g-1| > 0.5 → 置 VAL_BASELINE_WARN（仅告警，不改变判据）
若 g < WET_RATIO 持续 5 min（疑似长期无水）→ 不动作，只记日志
```

## 9. 浊度通道策略

现状：浊度在判据里（L0 的必要条件 + L2 的充分条件 + 速率抢先），但本次 186 帧 `d_ntu_pct` 只有 1.0~2.8 %，离 8 %/25 % 很远 → **实际没参与**。且它与 TDS 共享同一次干态基线 → **冗余失效**。

建议角色调整：

| 用途 | 保留？ | 说明 |
|---|---|---|
| L2 充分条件（变脏） | ✅ 保留 | 方向天然正确 |
| L0 必要条件 | ⚠️ 改为"**只能否决**" | 现在 `d_ntu < 8%` 是 AND 条件，浊度一旦漂移就永久不回收；且它拦不住空腔 |
| 速率抢先 | ⚠️ 降级 | 50 %/s 太大，先改成 150 %/s 或仅记录 |
| 浸没判据 | ✅ 新增 | `AO < AO_DRY`，**这是浊度唯一能帮上忙的地方** |

失效处理：`NTU` 无效时**不允许静默忽略**（那等于偷偷降低安全性），必须在 `note` 里标 `NTU_NA`，并在验收测试里明确"NTU_NA 时是否允许回收"——建议**不允许**（保持 fail-safe），直到标定证明它可靠。

## 10. 时序与滤波：让算法时间常数 ≲ 物理时间常数

| 环节 | 现值 | 建议 | 依据 |
|---|---|---|---|
| 采样 tick | 50 ms | 50 ms | 不变 |
| ADC 中值 | 5 | 5 | 不变 |
| EMA α | 0.30 | **0.15** | 配合 4 s 稳定期 |
| 基线点数 | 20（1 s） | **40（2 s）** | 降 σ |
| 稳定期 | 2000（只手动 R） | **4000（所有工况）** | 你们报告实测 3.8 s 才进 ±1 % |
| 块长 | 200 ms | **400 ms** | 与 5 Hz 输出匹配 |
| 换向屏蔽 | 无 | **400 ms** | 切除 S6 |
| 腔体交换时间 τ=V/Q | 数十秒 | **< 1 s**（结构改动） | 见诊断报告 P0-0 |

> 最后一行是结构项，但它决定了上面所有参数的天花板：τ 不降下来，调算法只是在猜 1 分钟前的水。

## 11. 可观测性：先让日志别再丢帧

本次日志最关键的 600~800 ms（正好是超时+换向）**全部丢失**，导致触发原因只能推断。

| 改动 | 做法 |
|---|---|
| UART 非阻塞 | `_write` 写入 1 KB TX 环形缓冲，立即返回；满则丢字符并置计数（不再自旋等待） |
| 事件行降级 | 连续多行事件改为"每 tick 最多打 1 行"，其余排队 |
| CSV 兼容 | **保持 17 列**；`note` 改造成工况码：`OK` / `DRY` / `SET` / `BLK` / `NOBASE` / `SENS` / `NTU_NA` |
| 新增事件行 | `# GATE t=… valid=0x%02X regime=%s wet=%u reason=%s`（只在变化时打） |
| 新增命令 | `D` 记干态指纹 / `W` 记湿态基线 / `G` 打 gate 状态 / `Z` 清基线 |

## 13. 实施路线（每步都有可验收的判据）

### P0 —— 让装置"不再自激、不再回收空气"

| 步 | 改动 | 验收 |
|---|---|---|
| P0-1 | 删上电自动采基线；加 `D`/`W` 命令与校验 | 空腔上电 → `DRY`，阀不吸合 |
| P0-2 | 新增 `validity/gate`，接入 `decision_update` | 空腔 5 min：`# STATE` 里不出现 CLEAR |
| P0-3 | 回收许可替换事件闩锁（删 `auto_start` / `EVENT_TIMEOUT`） | 空腔不再出现 30 s 周期；`count` 不增长 |
| P0-4 | 换向 400 ms 屏蔽 + 速率门限 120 + 持续 2 tick | 换向不再引起 `# STATE` 变化 |

### P1 —— 让判据在"有水"时可用

| 步 | 改动 | 验收 |
|---|---|---|
| P1-1 | 双侧门限（负偏离 → L1） | 拔电极/开路 → L1/DRAIN，不判 L0 |
| P1-2 | 块 400 ms / 8 点 / 6 票 + 升 3 块降 1 块 | 清水 60 s 无抖动 |
| P1-3 | 稳定期 4 s；`STABLE` 失效回落 SETTLE | 入水 4 s 内不给 RECOV |
| P1-4 | UART TX 环形缓冲 + note 工况码 | 换向前后不丢帧 |

### P2 —— 让判据"有依据"

| 步 | 改动 | 验收 |
|---|---|---|
| P2-1 | 数据 Flash 保存基线 | 断电重启后免标定，`BASELINE_OK` 保持 |
| P2-2 | 浊度三态标定 + 角色调整 | `d_ntu` 能从清水/皂液分开，否则降级 |
| P2-3 | 可选：流量计/液位开关接入 `VAL_FLOW` | 事件边界自动、`SETTLE` 由流量触发 |

## 15. 风险与取舍

| 风险 | 说明 | 缓解 |
|---|---|---|
| 许可模型"太灵敏" | 谓词每 50 ms 重算，可能频繁换向 | 保留 `min_dwell=500 ms`；`level` 单侧迟滞（升慢降快） |
| `WET_RATIO=0.3` 拍脑袋 | 不同水质/电极几何下最优值不同 | P0-0 后实测：空腔/清水/皂液三点的 `g` |
| 数据 Flash 写入寿命 | 频繁标定会磨损 | 只在 `D`/`W` 命令时写，加变更检测 |
| 删掉事件闩锁后"演示效果"变弱 | 没有"洗手事件"的概念，答辩时不好讲故事 | 事件仍作为**日志分段**保留（§7.4），只是不控制阀 |
| 浊度降级后少一路判据 | 冗余变少 | 但现有浊度本就未参与（1~3 % vs 8 %），降级不损失真实能力 |

## 16. 一页速查：改前 / 改后

| 问题 | 改前 | 改后 |
|---|---|---|
| 无液体 | CLEAR/RECOV（回收空气） | `DRY` → DRAIN |
| 有水但水位低 | CLEAR/RECOV（回收脏水） | `DRY` → DRAIN |
| 清水淹到电极 | L2/DRAIN（永远不回收） | `MEASURE` + L0 → RECOV |
| 脏水 | L2/DRAIN ✅ | L2/DRAIN ✅ |
| 换向扰动 | 单点 L2 → 30 s 回收 | 400 ms 屏蔽 + 许可即时撤销 |
| 待机 | 只在开机出现 | `DRY` 常态，随时可回 |
| 传感器：电极脱水 | L0/CLEAR（回收） | L1/DRAIN |
| 传感器：探头开路/断线 | L2（误报为"脏"） | L1/DRAIN + 故障码 |
| 基线 | 上电自动、干态、无校验 | 显式、水中、区间+CV、掉电保存 |
