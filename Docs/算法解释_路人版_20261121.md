## 0. 30 秒版

洗手水不是"要么干净、要么脏"，而是**前段接近清水、中段是肥皂水、末段又变清**。现在公共洗手台只有两种做法：感应龙头只认"有没有手"，一律排掉；全量过滤不认水质，一律处理，费滤料。

这台机器只做一件事：**每秒看 20 次，判断这一小股水该进"回收桶"还是"下水道"。**

它靠两个便宜的传感器：一个测水有多"导电"（溶进水里的离子），一个测水有多"浑"（泡沫和悬浮颗粒）。

三条原则：

1. **不跟标准值比，跟自己的清水比。** 上电先给自己标定一份"清水长什么样"，之后只看差值。
2. **先确认"现在能不能判"，再判"脏不脏"。** 没水、没淹到探头、刚进水还在晃、没有标定——都不许判，一律排空。
3. **拿不准就排空。** 只有一种情况会回收：水淹过电极、数据稳定、两个传感器都在清水范围内，并且连续确认了 1.2 秒。

一句话：**它不是"测出脏就排"，而是"先证明自己能判，再用相对清水的差值判；判不了就排"。**

```
洗手水 ──▶ ① 三个感官（EC / 浊度 / 水温）
           ② 现在能判吗？（工况门控）
           ③ 脏不脏？（三档判级）
           ④ 稳不稳？（投票 + 防抖）
              │
              ├── 全部通过 ─────▶ 三通阀 ──▶ 绿桶（回收）
              └── 任何一步"不知道" ─▶ 三通阀 ──▶ 灰桶（排空）
```

## 1. 先搞清楚：一次洗手，水是"三段"的

| 阶段 | 水里有什么 | 理想去向 |
|---|---|---|
| 前段（刚开水 1～2 秒） | 管道里存着的滞留水，接近清水 | 可回收 |
| 中段（搓手、打肥皂） | 皂液、皮脂、汗、泡沫、少量颗粒 | 必须排空 |
| 末段（冲干净） | 泡沫被带走，又接近清水 | 可回收 |

为什么要分段？因为**回收肥皂水的代价很高**：皂液带着离子和表面活性剂，回用会发泡、结垢、滋生细菌，还会让下一次冲洗更脏。而**全量排掉清水的代价是浪费**——一次洗手有相当一部分水本来可以再用。

所以真正的问题不是"怎么把脏水洗干净"，而是"**这一杯水该不该洗**"。这台机器回答的就是后者。

装置长这样：水先流进一个小腔体，传感器就泡在里面；出口是一个三通阀，一路通回收桶（绿），一路通下水道（灰）。**阀断电会自动回到排空位**——这是硬件的兜底。

## 2. 机器只有三个感官

| 感官 | 它测什么 | 生活里的比喻 | 读数单位 |
|---|---|---|---|
| **电导率（EC）** | 溶于水的离子多少。皂液、汗、皮脂、牙膏都会让水更"导电" | 尝一口汤有多咸 | 毫伏（mV） |
| **浊度** | 悬浮的泡沫、颗粒有多少。水越浑，光越透不过去 | 看一碗汤有多浑 | 毫伏（mV），判据用"相对清水涨了百分之几" |
| **水温** | 同样一杯水，热水比冷水更导电（大约每升 1 ℃ 高 2%） | 天热糖化得快 | ℃ |

（这一版还接了一路超声波测液位，属于"加分项"，第 10 节会说它为什么不是必需的。）

**最重要的一点：机器读的是电压，不是浓度。**

它不会说"这水含盐 300 ppm"，只会说"这水比刚才标定的清水，导电多了 33 毫伏"。后面所有的判断，用的都是这种"差了多少"，而不是"绝对值是多少"。

> 为什么？第 3.1 节会讲一个很硬的现场证据。

## 3. 第一步：拿什么当"清水"？——基线

### 3.1 为什么不能用固定的标准值

现场实测：**同一杯清水，不同日期上电，基线从 258 毫伏漂到 553 毫伏，差了一倍。**

原因很多：水温、电极表面的状态、水质本身、模块批次、供电电压。这意味着——**任何写死的绝对值阈值，换一个城市、换一天就废了。**

（这也是为什么市面上的"水质检测笔"换个杯子就要重新校准。）

### 3.2 做法：上电先给清水"拍张照"

| 什么时候 | 机器做什么 | 得到什么 |
|---|---|---|
| 上电、腔里没水 | 采 2 秒 | **干指纹**：空腔时的读数（实测约 44～58 毫伏） |
| 水淹过电极后 | 采 2 秒（40 个点） | **基线**：清水时的平均读数 EC0，以及它的"抖动" σ |

之后每一刻都算两个差值：

```
ΔEC  = 现在的读数 − 清水基线 EC0        （单位：毫伏）
ΔNTU = 浊度偏离清水的程度                 （已统一方向：> 0 恒表示"更脏"）
```

温度先折算到 25 ℃ 再比（25 ℃ 是电导率的国际参考温度），否则夏天和冬天的读数没法放在一起看。

> **比喻**：量身高之前，先在墙上画一道线。线画在 1 米还是 1.1 米不重要，重要的是"现在比这道线高多少"。

### 3.3 为什么要存三份"清水样本"（三槽）

同一个腔体，**阀在排空位和阀在回收位，读数是不同的**——因为水路变了，电极周围的水流也变了。实测：

| 槽 | 什么时候用 | 实测 EC0 |
|---|---|---|
| DRAIN | 阀在排空位、水静止 | 258 mV |
| RECOVER | 阀在回收位、水静止 | 305 mV |
| FULL | 正在进水、腔体满、水在流动 | 333 mV |

相邻两槽差 **28～47 毫伏**，比"脏了"的门槛（约 14 毫伏）还大。

**如果只存一条基线，阀一换向，读数就会跳 30 毫伏——机器会以为"水突然变脏了"，然后关阀；关阀又跳回去，又以为变干净了。** 这就是现场出现过的"周期性抖动"。

所以标定时记三条，运行时按阀的位置和液位自动切到对应的那一条。

### 3.4 基线也要"体检"

不是采到什么就信什么。一份基线要同时满足：

| 检查 | 门槛 | 挡住的是什么 |
|---|---|---|
| 量程合理 | 50 ～ 1600 mV | 太低＝没供电或探头悬空；太高＝探头开路的伪值（约 1650 mV） |
| 确实在水里 | EC0 ≥ 干指纹 + 80 mV | 防止"在空气里采基线" |
| 采的时候够稳 | 2 秒内抖动 ≤ 1%，或 ≤ 3 mV | 防止在水流乱窜、气泡翻滚时采基线 |

任何一条不过，基线作废，**机器进入"不许回收"的状态**。

> 这条规则是用事故换来的：早期版本在空气里采了基线，于是"空气"成了"清水"，机器对着空腔回收空气，日志还显示一切正常。

## 4. 第二步：先问"现在能不能判"——工况门控

### 4.1 为什么这是整套算法最重要的一层

现场最危险的不是"阈值不准"，而是"**判据在错误的时机生效**"。真实踩过的坑：

| 现场现象 | 根因 |
|---|---|
| 对着空腔回收"空气" | 空腔读数 43.7 mV，**比清水还"干净"**，旧逻辑判"可回收" |
| 有水、但水没淹到电极，照样回收 | 那种状态的读数跟空腔同一个区间 |
| 探头被拔掉，机器报"水很脏" | 开路伪值约 1650 mV，被当成"脏"而不是"坏" |
| 阀一换向，就被判"肥皂来了" | 换向瞬间的水力扰动，变化率 35～38 mV/s |

这些都不是"阈值调得不好"，而是**根本没有"现在是什么状况"这个概念**。

于是这一版把算法拆成两层：

- 第一层（工况）回答：**现在这批数据能不能用？**
- 第二层（判级）回答：**能用的话，水脏不脏？**

**只有第一层说"能判"，第二层才有资格开口。**

### 4.2 五个工况，像红绿灯的状态机

| 工况 | 含义 | 阀 | 生活里的比喻 |
|---|---|---|---|
| **FAULT** | 传感器坏 / 没标定 / 数据不可信 | 排空 | 体温计没电了，先别下诊断 |
| **DRY** | 确认没水（或水没淹到电极） | 排空 | 杯子是空的 |
| **SETTLE** | 刚进水，水还在晃、探头还在响应 | 排空 | 刚倒进热水，等温度计稳定 |
| **MEASURE** | 淹到 + 稳定 + 有基线 | **允许判水质** | 一切就绪，可以读数了 |
| **LOCKOUT** | 故障刚恢复，观察 3 秒 | 排空 | 退烧了再观察一天 |

状态会自己流转：

```
  FAULT ──(故障消失 1 s)──▶ LOCKOUT ──(3 s)──▶ DRY
                                                │
                                   淹到并持续 500 ms
                                                ▼
                                             SETTLE
                                                │
                              稳定（1～4 s，最多 6 s）
                                                ▼
                                            MEASURE
                                                │
                                     失水持续 300 ms
                                                ▼
                                         回到 DRY（排空）
```

注意两处**故意的不对称**：

- **进水要等 500 毫秒才认**（防水花溅一下就以为淹到了）；
- **失水只要 300 毫秒就翻脸**（安全侧：宁可早排，不可晚排）。

### 4.3 怎么判断"水真的淹到探头了"

不是"腔里有水"，而是"电极被水没过了"：

```
浸没 = (当前 EC ≥ 干指纹 + 80 mV)  且  (当前 EC / 清水基线 ≥ 0.30)
```

用"比干态高 80 毫伏"这种**差值**，而不是"是不是空腔的 3 倍"——因为电极上挂着一层水膜时，固定倍数会误判。

### 4.4 换向之后的 400 毫秒"免打扰"

阀一动作，水路扰动，读数会剧烈跳一下。这 400 毫秒里：

- **冻结判断**：不算新账、不投票、不判速率；
- **但已经生效的决定不撤销**。

第二条很关键。如果"换向→进入免打扰→撤销许可→关阀→又换向"，就会变成永动机。所以规则是：**换台的时候先别打分，但已经打出的分不改。**

## 5. 第三步：脏到什么程度算脏？——三档判级

### 5.1 两条线

机器先算两条门槛（单位：毫伏）：

```
下界 d1 = max( 4 × 抖动σ , 8 mV , 清水值 × 4% )
上界 d2 = max( 8 × 抖动σ , 20 mV , 清水值 × 9% )
```

现场清水 348 mV 时：**d1 ≈ 14 mV，d2 ≈ 31 mV**。

浊度没有标定，所以只按"相对清水的百分比"设门槛：**下界 7%，上界 9%**。

三个候选为什么要取最大？

| 候选 | 作用 |
|---|---|
| 4σ / 8σ | 机器本身越"吵"，门槛就自动抬高。抖动 3 mV 却把门槛设 2 mV，等于天天误报 |
| 8 mV / 20 mV 绝对下限 | 万一抖动被算成 0，门槛不能退化成 0 |
| 4% / 9% 百分比 | 清水本身浓度高时（比如 553 mV），同样的百分比对应更大的绝对差 |

### 5.2 三档结论：绿灯、黄灯、红灯

| 情况 | 结论 | 阀 |
|---|---|---|
| 两路都在 d1 以内 | **L0 绿灯** | 回收 |
| 浊度超过 d2（9%），或（EC 超过 d2 **且**浊度也接近 d2，即 ≥ 8.1%） | **L2 红灯** | 立即排空 |
| 任一路比清水**低**超过 d2（比如 −31 mV） | **L1 黄灯** | 排空 |
| EC 超过 d2，但浊度没跟上 | **L1 黄灯** | 排空 |
| 其余（落在两条线之间） | **L1 黄灯** | 排空 |

**绿灯是唯一会开阀的一档。黄灯和红灯的结果都是排空**——区别只在于"我们有多确定"，以及日志里怎么记。

### 5.3 算一遍（假设清水基线 300 mV，抖动 1.5 mV）

```
d1 = max(4×1.5, 8, 4%×300=12) = 12 mV
d2 = max(8×1.5, 20, 9%×300=27) = 27 mV

读到 298 mV → ΔEC = −2  → 没到任何门槛 → 绿灯（还要看浊度）
读到 314 mV → ΔEC = +14 → 过了 d1(12)、没到 d2(27) → 黄灯
读到 333 mV → ΔEC = +33 → 过了 d2(27)，且浊度 +8.3% → 红灯
读到 250 mV → ΔEC = −50 → 比清水低太多 → 黄灯（可能探头离水了）
```

### 5.4 为什么"太干净"也要拦

旧版本只拦"变脏"。结果"探头插着、但水没淹到"（EC 掉到 43～58 mV）成了**全场最安全的样子**，直接被判成绿灯回收。

现在负方向也拦：比清水低超过 d2，同样可疑——可能是电极脱水、气泡包住探头、或者水位在下降。

### 5.5 为什么 EC 单独高，不判肥皂

现场有一批"皂液冲洗水"：EC 涨了 +22 mV（+7%），但浊度只涨了 +4%。

**证据不足。** 所以判黄灯排空，而不是硬判红灯。

这体现了一条原则：**"不确定"和"确定脏"在动作上一样（都排空），但在态度上必须分开**——不能为了"看起来聪明"把不确定说成确定。

### 5.6 迟滞：出门比进门难

| 当前状态 | 门槛怎么变 | 效果 |
|---|---|---|
| 已经在绿灯 | 下界放宽 10%（EC）/ 25%（浊度） | 要脏到约 +15 mV 才掉出去，不在门槛上抖 |
| 已经在红灯 | 上界收紧 10% / 25% | 肥皂水刚被冲淡一点，仍然算红灯 |

> **比喻**：空调的"开机温度"和"关机温度"不能是同一个，否则会频繁启停。

### 5.7 四个区间（只看 EC，浊度在带内时）

| ΔEC 落在哪 | 判定 | 意思 |
|---|---|---|
| 低于 −31 mV | 黄灯 | 比清水还干净太多，也可疑（探头可能离水了） |
| −31 ～ +14 mV | **绿灯** | 正常波动，可以回收 |
| +14 ～ +31 mV | 黄灯 | 脏了一点，但证据不足 |
| 高于 +31 mV | 红灯（还要浊度同证） | 明显变脏 |

注意绿区是**偏斜**的：往下很宽（要到 −31 才可疑），往上很窄（+14 就可疑）。

这就是"回收要保守"的形状。

## 6. 第四步：一瞬间的数字可信吗？——六道保险

传感器会骗人：气泡、水花、电磁干扰、继电器动作，任何一个都能让某一瞬间的读数离谱。六道保险依次过滤：

| # | 保险 | 怎么做 | 防的是什么 |
|---|---|---|---|
| 1 | **取中值** | 每 50 ms 采 5 次，取中间那个 | 单点毛刺、电火花 |
| 2 | **平滑** | 新读数只占 15%，旧值占 85%（时间常数约 0.3 s） | 让曲线别像心电图 |
| 3 | **投票** | 400 ms 一块，8 个采样，**6 票同意**才采纳 | 一两个采样点的气泡、瞬间泡沫 |
| 4 | **不对称迟滞** | 变脏/拿不准**立即**生效；变干净要连续 **3 块（1.2 s）**；从绿灯掉出来要 2 块（0.8 s） | "假干净"比"假脏"危险得多 |
| 5 | **速率抢先** | EC 每秒涨 120 mV 以上（且已涨 5 mV）连续 2 个 tick，或浊度每秒涨 15% 以上 → 不等投票，立刻排空 | 肥皂水冲进来的"前沿" |
| 6 | **肥皂锁存** | 一旦判过红灯，接下来 **45 秒**一律排空 | 肥皂被冲淡到传感器看不见的尾水 |

几个细节值得单独说：

- **120 mV/s 这个数，是实测换向瞬态的 3 倍**（现场 38 mV/s）。门槛设低了，阀自己换个向就会触发；设高了，真肥皂进来又反应不过来。
- **投票不够怎么办？** 宁可按"拿不准"处理（黄灯排空）。但如果主循环被串口打印拖慢，400 ms 里只采到 4～5 个点，门槛会按"实际点数的 75%"折算；少于 4 个点，这一块直接作废。**否则会出现"水明明是干净的，就是不回收，日志只有 UNCERTAIN"的幽灵故障。**
- **肥皂锁存是唯一带记忆的规则**，而且失水 2 秒后自动清除——不会让下一个人的清水继承上一个人的判定。

## 7. 第五步：谁最终开阀？——许可每 50 ms 重算

### 7.1 旧设计错在哪

旧版本把"回收"做成一个**事件**：判到一次绿灯，就开一张"30 秒的通行证"，期间不管水多脏都回收；30 秒到了关闭，而"关闭"这个动作本身又会重新触发一次判断——于是现场看到稳定的 **30 秒一个周期**。

只要"开启"和"关闭"不是同一个判断的两面，就一定会出现"**一次扰动，买到 30 秒许可**"。

### 7.2 新设计：没有通行证，只有举手

```
每 50 ms 算一次：   许可 = （当前等级 == 绿灯）

是 → 回收（继续）
否 → 立刻排空
```

没有"开始"这个动作，也就没有"超时"这个概念。一次误判最多影响几十毫秒，而不是 30 秒。

### 7.3 执行层还有三道保险

| 保险 | 数值 | 作用 |
|---|---|---|
| 阀最小驻留 | 500 ms | 不让继电器"哒哒哒"地抖 |
| 单次最长吸合 | 120 s | 阀的连续工作制，超时强制释放并冷却 10 s |
| **断电回排空位** | 硬件 | 掉电、看门狗复位，阀自动回到排空 |

最后一条是**硬件的兜底**：软件再怎么错，断电时水也只会往下水道走。

## 8. 把一次洗手完整走一遍

| 时刻 | 发生了什么 | 机器状态 | 阀 |
|---|---|---|---|
| 0 s | 上电，腔里没水，还没标定 | FAULT → DRY | 排空 |
| 0～2 s | 空腔自检（2 秒），把干指纹从默认值换成实测值 | DRY | 排空 |
| 2 s | 开始放水，EC 往上爬 | DRY | 排空 |
| 水淹过电极 | EC ≥ 干指纹 + 80 mV，且持续 500 ms | SETTLE | 排空 |
| +1～4 s | 等水稳下来（液位稳定时只要 1 s） | SETTLE | 排空 |
| 稳定后 | 第一次允许判水质 | MEASURE | 排空（还没攒够票） |
| 清水连续 3 块 | ΔEC ≈ −13～0 mV，ΔNTU ≈ −1.6～−0.7% | **CLEAR** | **回收** |
| 搓肥皂 | ΔEC +33 mV、ΔNTU +8.3%（越过 8.1% 的联合门槛） | SOAP（红灯） | 立即排空 |
| — | 同时启动 45 秒锁存 | SOAP | 排空 |
| 冲干净、读数回到清水区间 | 锁存还没过 | SOAP | 排空 |
| 手离开、水排空 | EC 回到干态并持续 300 ms | DRY | 排空 |
| DRY 持续 2 s | 清掉锁存 | DRY | 排空 |
| 下一个人 | 从 DRY 重新开始 | — | — |

**异常情况会怎样：**

| 异常 | 反应时间 | 结果 |
|---|---|---|
| 拔掉 TDS 探头 | 3 个 tick（150 ms） | FAULT → 排空 |
| 探头插回 | 故障消失 1 s + 观察 3 s | LOCKOUT → DRY |
| 水位掉到电极以下 | 300 ms | DRY → 排空 |
| 主循环卡死 | 3 s | 软件看门狗复位 → 阀断电回排空 |
| 浊度模块断电 | 立即 | FAULT → 排空 |

## 9. 三条铁律（也是三句话总结）

1. **不知道，就排空。**
   任何一步算不出来——没传感器、没基线、没淹到、数据在跳、投票不通过——结果都是排空，不是"放行"。

2. **只跟自己比，不跟标准比。**
   绝对阈值换一个地方就废；上电自标定、三槽基线、温度折算，都是为了"在哪都能用"。

3. **宁可少回收，不可回收脏水。**
   所以"变干净"要等 1.2 秒，"变脏"立刻生效；所以绿灯只有一档，黄灯红灯都排空。

补充第四条（工程习惯）：**每个结论都带原因码**——`CLEAN` / `UNCERTAIN` / `SOAP_HIGH` / `RATE_JUMP` / `BLOCK_SPLIT` / `BLANK` / `SOAP_LATCH` / `TOO_CLEAN`。现场出问题，看串口就知道机器"为什么"这么判，而不是只能猜。

## 10. 这套算法做不到什么（老实说）

| 局限 | 原因 | 现在的应对 |
|---|---|---|
| 反应有延迟 | 腔体约 0.6 L，水要流一段才到探头；肥皂进入后约 1.6 s 内可能有一小股进回收 | 下一代把腔体缩到 25～45 mL，把时间常数压到 1 秒级 |
| 酒精免洗凝胶看不见 | 两个通道对纯酒精都不响应 | 属于原理盲区，明确写进说明 |
| 浊度没有标定 | 没有标准液，模块批次差异大 | 只说"相对清水的百分比"，不说 NTU 绝对值 |
| 基线掉电就丢 | 存在内存里，没做持久化 | 上电重新标定；标定时需人工确认一次"这是清水" |
| 超声液位在泡沫下会失效 | 泡沫吸收回波 | 设计成"液位无效就退回 EC + 浊度判据"，不阻塞回收 |
| 只认"离子 + 悬浮物" | 传感器的物理原理决定的 | 其他类型污染不在能力范围内，不声称 |

第 4 条里那个"人工确认"值得多解释一句：**标定回收支路时，机器会把"这确实是清水"的判断权交给现场的人。** 60 秒内没有确认，就只保留排空位那一条基线，**自动回收被禁止**（只能用调试命令手动开阀）。这是故意的——机器不确定的时候，让人来负责。

## 11. 数字速查

| 数字 | 含义 | 为什么是这个数 |
|---|---|---|
| 50 ms | 心跳，每秒 20 次 | 够快，又不会把单片机压垮 |
| 5 次 | 每 tick 每通道采样次数 | 取中值去毛刺 |
| 0.15 | 平滑系数 | 时间常数约 0.3 s，能跟得上洗手节奏 |
| 2 s / 40 点 | 采基线时长 | 够长能平均噪声，够短不让人等 |
| 3 槽 | DRAIN / RECOVER / FULL | 阀位会改变读数 28～47 mV |
| 80 mV | 浸没门槛（比干态高多少） | 空腔 44～58 mV，清水 258 mV 以上 |
| 500 ms | 浸没去抖 | 防水花溅一下 |
| 4 s / 1.5 s / 6 s | 稳定期 / 最早 / 兜底 | 实测进水 3.8 s 才稳到 ±1% |
| 300 ms | 失水判定 | 安全侧要快 |
| 400 ms | 换向免打扰 | 扰动一般持续 0.4～0.6 s |
| 8 点 / 6 票 | 块投票 | 8 中 6 = 75%，能扛住两个点的气泡 |
| 3 块 / 1.2 s | 升级到绿灯 | "变干净"必须连续确认 |
| 2 块 / 0.8 s | 掉出绿灯 | 清水的水力漂移只持续 0.4～0.6 s |
| 120 mV/s | EC 速率抢先 | 约 3 倍于实测换向瞬态（38 mV/s） |
| 15 %/s | 浊度速率抢先 | 肥皂前沿约 16 %/s |
| 45 s | 肥皂锁存 | 覆盖一次洗手的稀释尾水 |
| 500 ms | 阀最小驻留 | 保护继电器 |
| 120 s | 阀最长吸合 | 阀的连续工作制 |
| 4% / 9% | d1 / d2（相对清水） | 最弱的肥皂只高 4～5%：d1 要比它低才抓得住，d2 要比它高才不会误判成红灯 |
| 7% / 9% | 浊度 d1 / d2 | 清水稳定段最高 7.6%，肥皂 ≥ 8.6%；进门 7%，已在门内放宽到 8.75% |

> **4% 这么低，清水抖一下会不会误判？**
> 会触发黄灯，但不会开阀（黄灯本来就是排空）。而且清水的短时漂移（阀换向带来的那一下）被"400 ms 免打扰 + 连续 2 块确认"吃掉了，不需要靠抬高门槛来吸收。**用时间去过滤，而不是把门槛抬到看不见问题。**

## 12. 常见误解

**Q1：是不是测出 TDS（溶解性总固体）超标就排？**
不是。机器不判断"达标"，只看"比刚才的清水脏了多少"。它甚至不输出一个"水质分数"。

**Q2：为什么水明明很干净，它还排空？**
可能的原因有六种：①没标定或基线失效 ②水没淹到探头 ③刚进水还没稳 ④刚换向的 400 ms 内 ⑤肥皂锁存还没过 ⑥这一块投票没通过。每一种在日志里都有原因码。

**Q3：为什么不直接测 pH、用摄像头、或者上 AI？**
成本、防水、隐私、浑水对成像的干扰，都是问题。两个模拟传感器加一块几十元的单片机就能跑，而且**每个结论都能解释**——这在现场排障时比"模型说它脏"有用得多。

**Q4：黄灯和红灯都排空，那分三档有什么意义？**
三点：①区分"确定脏"和"不确定"，便于复盘和调参；②红灯会触发 45 秒锁存，黄灯不会；③逼着设计者承认"证据不足"，而不是把不确定硬说成确定。

**Q5：为什么不做成"判一次管 30 秒"？**
那正是旧版本的 bug（第 7.1 节）。"一次扰动买到 30 秒许可"是这类系统最典型的失效方式。

**Q6：45 秒是拍脑袋定的吗？**
是按"从打肥皂到冲净"的时间估的工程参数，不是浓度测量。现场可调；失水 2 秒会自动清掉，避免影响下一个人。

## 13. 给工程师：这些规则在哪段代码里

| 层 | 文件 | 关键函数 |
|---|---|---|
| 采样与特征 | `sensor_pipeline.c` | `pipeline_sample`、`pipeline_features_update`、`pipeline_rate_update`、`pipeline_baseline_finish` |
| 工况门控 | `validity.c` | `gate_update`（位图 + regime 状态机） |
| 判级与许可 | `decision.c` | `decision_classify`、`decision_block_update`、`decision_update` |
| 执行器 | `actuator_valve.c` | `valve_request`、`valve_task` |
| 参数集中处 | `app_main.c` 顶部 | `APP_*` 宏、`g_app_pipeline_cfg`、`g_app_decision_cfg` |
| 观测 | 串口 | CSV 17 列 + `# ` 开头的事件行 |

分层是单向的，下游不许反推上游：

```
sensor_pipeline（采什么） → validity（能不能判） → decision（脏不脏） → app（开不开阀）
```

**改阈值之前先读这张表**，因为很多参数是互相咬合的（例如把 d1 调高，升级到绿灯就要更久；把投票门槛调低，气泡就会开始骗人）。

## 附：名词对照

| 名词 | 大白话 |
|---|---|
| EC / 电导率 | 水有多"导电"，反映溶了多少离子 |
| TDS | 溶解性总固体，常由电导率换算；本机只把它当参考，不参与判级 |
| ppm | 百万分之一，常用来表示溶解物浓度 |
| mV / 毫伏 | 电压单位，千分之一伏。这里就是传感器的读数 |
| mV25 | 按 25 ℃ 折算后的电压，用来消除水温影响 |
| NTU | 浊度的标准单位。本机浊度没标定，所以只说"相对百分比"，不报 NTU |
| σ（西格玛） | 读数的"抖动幅度"，越大说明噪声越大 |
| 基线 / 本底 | 清水时的读数，相当于"墙上的那道线" |
| 槽（slot） | 一条基线。这里存了三条，对应三种阀位/流动状态 |
| 干指纹 | 空腔时的读数，用来判断"水有没有淹到探头" |
| EMA | 一种平滑算法，让新读数只占一小部分权重 |
| 投票块 | 400 ms 内 8 个采样投一次票，6 票才算数 |
| 迟滞 | 进门和出门用不同的门槛，防止在边界上抖 |
| 屏蔽窗 | 换向后的 400 ms，冻结判断但不撤销已生效的决定 |
| 许可（permit） | 每 50 ms 重算一次的"现在能不能回收" |
| L0 / L1 / L2 | 绿灯 / 黄灯 / 红灯 |
| DRY / SETTLE / MEASURE | 没水 / 等稳定 / 正式测量 |
| FAULT / LOCKOUT | 故障 / 故障恢复后的观察期 |
| 锁存（latch） | 记住"刚判过肥皂"，一段时间内强制排空 |
| 失效安全（fail-safe） | 出问题时默认走安全的那一边（这里是排空） |
