【这个文件解决什么问题】
浊度是本项目的辅助判据（电导率判据不够或要"双判据融合"时使用）。TS-300B 是
5 V 模块，模拟输出 0~4.5 V，而本板 ADC 的模拟输入绝对最大 3.6 V、参考电压
3.3 V，所以绝不能直连。本驱动只做三件事：① 把 ADC 码换算成分压节点的真实
电压；② 按分压比还原模块 AO 引脚的电压；③ 做 rail / low 合理性检查，
告诉上层"这个读数能不能信"。方向归一化与相对基线的变化由 sensor_pipeline
统一计算——本驱动刻意不输出任何"浊度值"，更不换算 NTU。

【接线（断电接线；先接分压再通电）】
TS-300B VCC -> U2-19/20（VIN，≈4.5~4.7 V；5 V 外设与板同开同关）
TS-300B GND -> GND（共地）
TS-300B AO  -> 1 kΩ 串联电阻 -> 节点 -> P013 / AN11（U1-5）
               节点再经 2 kΩ 对地，节点对地并 0.1 µF 滤波
分压后节点电压 = AO × R2/(R1+R2) = AO × 2/3 ≤ 3.0 V，进 ADC 安全；
分压后源阻抗 = 1k∥2k ≈ 667 Ω ≤ 1 kΩ（数据手册对 ADC 源阻抗的要求）。
上电顺序硬规则：先开板、后开外设；断电先关外设、后关板（5 V 外设从 VIN 取电，
板子断电时其输出/分压节点都可能高于 3.6 V，绝对最大不允许）。

【原理】
TS-300B（与 DFRobot SEN0189 同类）用光路测水中悬浮颗粒，输出与浊度相关的
模拟电压。模块输出方向因批次而异：常见是"清水电压高、越浑越低"，
也有反相批次。本驱动不做方向判断也不做 NTU 换算，只把 AO 电压还原出来，
方向由配置项 ntu_clear_high 在流水线里做归一化（先做一次清水/浑水对照，
以实测为准）。接口契约要求：本工程字段只叫"相对浊度变化"，禁止写 NTU、
禁止对标国标限值。

【关键公式】
① ADC→节点电压：node_mv = raw × 3300 / 4095（12 位、四舍五入）
② 分压还原：node = AO × R2/(R1+R2)  =>  AO = node × (R1+R2)/R2
   默认 1 kΩ + 2 kΩ → 系数 1.5，结果四舍五入到 1 mV。
③ 合理性：
   - raw ≤ 3（节点≈0 V → AO≈0 V）：模块未供电/断线/探头未接嫌疑 → RANGE；
   - raw ≥ 4040（节点≈3.26 V → AO≈4.89 V）：分压比接错或 5 V 串进 ADC → RANGE。
   两条都说明"读数不可信"，返回 SENSOR_ERR_RANGE，上层按安全侧处理（排空）。

【参数（集中在 sensor_ts300b.h 宏与 ts300b_cfg_t）】
- TS300B_VREF_MV_DEFAULT=3300、TS300B_ADC_FULL_SCALE=4095：与 TDS 同一组 ADC 参数。
- TS300B_RAIL_ADC=4040、TS300B_LOW_ADC=3：rail/low 判定门限，来源见上。
- div_r1_ohm=1000、div_r2_ohm=2000：默认分压电阻。金属膜 5% 最坏可到 ≈3.10 V
  （仍 <3.3 V 但余量小），优先用 1% 电阻；焊好后用 4.5 V 试验电压实测分压比，
  偏差 >5% 就按实测值改配置，不要照抄默认值。
- 若实测 AO 满量程是 5.0 V（个别批次/供电偏高）：改 1 kΩ + 1.5 kΩ
  （节点 ≤3.0 V、源阻抗 600 Ω）。永远先量再算。
- clear_high：清水电压高为 true（默认）；反相批次改 false。
  注意：本驱动只保存它，方向归一化在 sensor_pipeline 里做（见 sensor_pipeline.h）。

【注意事项】
1) 绝对禁止 5 V 直连 ADC，也禁止用 10k+20k 这类高阻分压：源阻抗 6.7 kΩ 会让
   12 位 ADC 采样不准。1k+2k 是算出来的，不是随便选的。
2) 0.1 µF 与 667 Ω 组成 τ≈67 µs（fc≈2.4 kHz），对 <500 ms 的浊度响应无影响。
3) 泡沫、气泡、探头位置都会让读数波动（肥皂水段尤其明显）：采样时撇去泡沫、
   缓慢搅动、固定探头深度；短时尖峰靠中值 + EMA 抑制。
4) 模块到货先做两件事：空载量 AO 满量程；清水/浑水各放一次确认方向。
5) 驱动层不打印、不控阀、不输出 NTU；状态码由 app 统一打印。
6) 单实例模块：ts300b_init() 保存配置到文件内 static，可重复调用。
7) 本模块是可选项，未接模块时读数会落在 low 区，上层应把浊度判据降级或忽略，
   不影响 TDS 主判据（具体降级策略由 app/decision 决定，见 00 文档）。

/* ===== FILE: src/sensor_ts300b.h ===== */
/*
 * sensor_ts300b.h —— TS-300B 模拟浊度模块（与 DFRobot SEN0189 同类）
 * ---------------------------------------------------------------------------
 * 模块电气事实（硬件方案 §4.3）：
 *   - 5 V 供电（本项目从 VIN ≈4.5~4.7 V 取电，与板同开同关）；
 *   - 模拟输出 0~4.5 V，**必须经 1kΩ 串 + 2kΩ 对地分压（≤3.0 V）**再进 P013/AN11；
 *   - 分压后源阻抗 1k∥2k ≈ 667 Ω ≤ 1 kΩ（ADC 源阻抗要求）；
 *   - 无 NTU 标定：本工程只输出"相对浊度变化"，禁止写 NTU / 禁止对标国标限值；
 *   - ⚠ 输出方向以实测为准：常见批次是"清水电压高、越浑越低"（clear_high=true），
 *     也有反相批次（clear_high=false）。做一次清水/浑水对照即可确定。
 *
 * 本驱动只负责：ADC 码 → 分压节点 mV → 还原模块 AO 电压 mV → 合理性检查。
 * "方向归一化 / 相对基线偏离" 由 sensor_pipeline 统一计算（见 sensor_pipeline.h）。
 */
#ifndef SENSOR_TS300B_H
#define SENSOR_TS300B_H

#include "sensor_common.h"

#ifdef __cplusplus
extern "C" {
#endif

#define TS300B_VREF_MV_DEFAULT  3300U   /* ADC 参考电压 */
#define TS300B_ADC_FULL_SCALE   4095U   /* 12 位 ADC 满量程 */
#define TS300B_RAIL_ADC         4040U   /* ≥4040（节点≈3.26 V → AO≈4.89 V）：分压/接线异常 */
#define TS300B_LOW_ADC          3U      /* ≤3（节点≈0 V → AO≈0 V）：断线/模块未供电嫌疑 */

/* 配置（单实例；ts300b_init 时拷贝进模块内部 static） */
typedef struct st_ts300b_cfg
{
    float div_r1_ohm;   /* 串联电阻 R1（默认 1000 Ω） */
    float div_r2_ohm;   /* 对地电阻 R2（默认 2000 Ω） */
    bool  clear_high;   /* true=清水时 AO 电压高（默认）；反相批次改 false */
} ts300b_cfg_t;

/* 一次转换结果 */
typedef struct st_ts300b_reading
{
    uint16_t raw_adc;     /* 中值后的 ADC 码 */
    uint32_t node_mv;     /* 分压节点电压 mV（真正进 ADC 的电压） */
    uint32_t ao_mv;       /* 还原到模块 AO 引脚的电压 mV = node_mv*(R1+R2)/R2 */
    sensor_status_t status;
} ts300b_reading_t;

/* 初始化（p_cfg 为 NULL 时用默认值：1k/2k、clear_high=true）。 */
void ts300b_init(const ts300b_cfg_t *p_cfg);

/* 核心转换：ADC 码 → 结果。p_out 必须非 NULL。
 * 返回 SENSOR_OK / SENSOR_ERR_PARAM / SENSOR_ERR_RANGE（贴轨/疑似断线）。 */
sensor_status_t ts300b_convert(uint16_t raw_adc, ts300b_reading_t *p_out);

#ifdef __cplusplus
}
#endif
#endif /* SENSOR_TS300B_H */
/* ===== FILE: src/sensor_ts300b.c ===== */
/*
 * sensor_ts300b.c —— TS-300B 模拟浊度模块驱动实现
 * ---------------------------------------------------------------------------
 *  本文件解决什么问题
 *  ---------------------------------------------------------------------------
 *  TS-300B 是 5 V 模块（模拟输出 0~4.5 V），而本板 ADC 的模拟输入绝对最大
 *  只有 3.6 V、参考电压 3.3 V，所以 AO 必须经"1 kΩ 串 + 2 kΩ 对地"分压后
 *  才能进 P013/AN11。本驱动只做三件事：
 *    ① ADC 码 → 分压节点真实电压（毫伏）；
 *    ② 按分压比还原模块 AO 引脚电压（毫伏）；
 *    ③ rail / low 合理性检查，告诉上层"这个读数能不能信"。
 *  方向归一化（清水/浑水谁电压高）与相对基线的变化由 sensor_pipeline 统一计算；
 *  本驱动刻意不输出任何"浊度值"，更不换算 NTU —— 本工程字段只叫"相对浊度变化"。
 *
 *  接线（断电接线；先接好分压再通电）
 *  ---------------------------------------------------------------------------
 *  TS-300B VCC -> U2-19/20（VIN，≈4.5~4.7 V，5 V 外设与板同开同关）
 *  TS-300B GND -> GND（与开发板共地）
 *  TS-300B AO  -> 1 kΩ 串联电阻 -> 分压节点 -> P013 / AN11（U1-5）
 *                 分压节点再经 2 kΩ 对地；节点对地并 0.1 µF 滤波
 *  节点电压 = AO × R2/(R1+R2) = AO × 2/3 ≤ 3.0 V（ADC 绝对最大 3.6 V，安全）；
 *  分压后源阻抗 = 1 kΩ ∥ 2 kΩ ≈ 667 Ω ≤ 1 kΩ（数据手册对 ADC 源阻抗的要求）。
 *  上电顺序硬规则：先开板、后开外设；断电先关外设、后关板。
 *
 *  原理
 *  ---------------------------------------------------------------------------
 *  模块用光路测量水中悬浮颗粒，输出与浊度相关的模拟电压。不同批次方向可能
 *  相反（常见"清水电压高、越浑越低"），所以本工程只做相对变化，并在流水线里
 *  用 ntu_clear_high 做方向归一化——方向必须用一次"清水/浑水对照"实测确定，
 *  不能照抄别人的结论。
 *
 *  关键公式与来源
 *  ---------------------------------------------------------------------------
 *  ① ADC → 节点电压：node_mv = raw × 3300 / 4095（12 位、四舍五入）
 *  ② 分压还原：node = AO × R2/(R1+R2)  =>  AO = node × (R1+R2)/R2
 *     默认 1 kΩ + 2 kΩ → 系数 1.5；四舍五入到 1 mV。
 *  ③ 合理性：
 *     - raw ≤ 3（节点≈0 V → AO≈0 V）：模块未供电 / 断线 / 探头未接 → RANGE；
 *     - raw ≥ 4040（节点≈3.26 V → AO≈4.89 V）：分压比接错、R1 开路、或 5 V
 *       串进 ADC → RANGE。
 *
 *  参数（默认值来源 + 怎么标定）
 *  ---------------------------------------------------------------------------
 *  - div_r1_ohm = 1000、div_r2_ohm = 2000：按数据手册"R2/(R1+R2) ≤ 3.0/Vmax"
 *    与"R1∥R2 ≤ 1 kΩ"两条约束算出来的；金属膜 5% 电阻最坏可到 ≈3.10 V
 *    （仍 <3.3 V 但余量小），优先用 1% 电阻。
 *  - 标定方法：给模块接 4.5 V 试验电压（或让其输出满量程），用万用表量 AO 与
 *    分压节点，反算实际分压比；偏差 >5% 就把实测 R1/R2 填进配置。
 *  - clear_high：清水时 AO 电压高 = true（默认）；反相批次改 false。
 *    本驱动只保存它，方向归一化在 sensor_pipeline 里做。
 *
 *  注意事项
 *  ---------------------------------------------------------------------------
 *  1) 绝对禁止 5 V 直连 ADC；也禁止用 10k+20k 这类高阻分压（源阻抗 6.7 kΩ，
 *     12 位 ADC 采样会不准）。1k+2k 是算出来的，不是随便选的。
 *  2) 0.1 µF 与 667 Ω 组成 τ≈67 µs（fc≈2.4 kHz），对 <500 ms 的浊度响应无影响。
 *  3) 泡沫、气泡、探头位置都会让读数波动（肥皂水段尤其明显）：采样时撇去泡沫、
 *     缓慢搅动、固定探头深度；短时尖峰靠中值与 EMA 抑制。
 *  4) 模块到货先做两件事：空载量 AO 满量程；清水/浑水各放一次确认方向。
 *  5) 本驱动不打印、不控阀、不输出 NTU；只返回状态码与电压。
 *  6) 与 TDS 共用 ADC0 单次扫描组（AN11 + AN12），ADC 的调度归 sensor_pipeline。
 * ---------------------------------------------------------------------------
 */

#include <stddef.h>      /* NULL */
#include "sensor_ts300b.h"

/* 模块内部配置副本（单实例模块，按接口契约用文件内 static 保存）。
 * 初值 = 头文件默认值：1 kΩ + 2 kΩ 分压、清水电压高。
 * 即使调用者忘记 ts300b_init()，换算结果也是"默认硬件接法"下的合理值。 */
static ts300b_cfg_t s_cfg = { 1000.0f, 2000.0f, true };

/**
 * @brief 初始化浊度驱动（保存配置）
 *
 * 作用：保存分压电阻与方向配置，供后续 ts300b_convert 使用。
 * 参数：p_cfg —— 配置指针；NULL 表示全部用默认值（1k/2k、clear_high=true）。
 * 返回：无。
 * 时序：纯赋值，不访问硬件、不阻塞。
 * 注意：① 分压电阻必须为正：R2 = 0 会让还原公式除零，R1 ≤ 0 说明配置写错；
 *          非法值（含 NaN）一律回落到默认 1k/2k。
 *       ② 本驱动不直接操作 ADC；ADC 的打开/扫描由 sensor_pipeline 负责。
 *       ③ clear_high 只被保存、不在本文件使用（方向归一化在 pipeline），
 *          这样"同一份硬件配置"只写一遍，避免两处默认值不一致。
 */
void ts300b_init(const ts300b_cfg_t *p_cfg)
{
    /* 先填默认值，再用调用者的合法值覆盖：p_cfg 为 NULL 时等价于"全默认" */
    s_cfg.div_r1_ohm  = 1000.0f;
    s_cfg.div_r2_ohm  = 2000.0f;
    s_cfg.clear_high  = true;

    if (NULL != p_cfg)
    {
        if (p_cfg->div_r1_ohm > 0.0f)
        {
            s_cfg.div_r1_ohm = p_cfg->div_r1_ohm;
        }
        if (p_cfg->div_r2_ohm > 0.0f)
        {
            s_cfg.div_r2_ohm = p_cfg->div_r2_ohm;
        }
        s_cfg.clear_high = p_cfg->clear_high;
    }
}

/**
 * @brief 核心转换：ADC 码 → 分压节点电压 / 还原 AO 电压 / 合理性状态
 *
 * 作用：一次完成"ADC→节点 mV→AO mV"还原，并检查 rail / low 两种坏线情况。
 * 参数：raw_adc —— 中值后的 ADC 码（12 位，0~4095）；
 *       p_out   —— 输出结构体（必须非 NULL）。
 * 返回：SENSOR_OK          换算完成、数据可用；
 *       SENSOR_ERR_PARAM   p_out 为空；
 *       SENSOR_ERR_RANGE   贴轨或疑似断线（low），读数不可信。
 * 时序：纯计算，几次浮点乘除，微秒级。
 * 注意：① 即使返回 RANGE，p_out 里的 raw_adc/node_mv/ao_mv 也已经填好，
 *          方便上层打印"坏在哪"（如 CSV 的 note=NTU_RAIL）；
 *       ② 本驱动不做方向归一化、不计算相对浊度、不比较阈值——那些都在
 *          sensor_pipeline 里，避免驱动层和判别层的参数各写一份。
 */
sensor_status_t ts300b_convert(uint16_t raw_adc, ts300b_reading_t *p_out)
{
    if (NULL == p_out)
    {
        return SENSOR_ERR_PARAM;
    }

    /* ---- 1) ADC 码 → 分压节点电压（这才是真正进 ADC 的电压） ---- */
    p_out->raw_adc = raw_adc;
    p_out->node_mv = sensor_adc_to_mv(raw_adc, TS300B_ADC_FULL_SCALE,
                                      TS300B_VREF_MV_DEFAULT);

    /* ---- 2) 按分压比还原模块 AO 引脚电压 ----
     * 推导：node = AO × R2/(R1+R2)  =>  AO = node × (R1+R2)/R2。
     * 默认 1k+2k：AO = node × 1.5。用 float 做中间量：
     * node ≤ 3300 mV、系数 ≤ 3（默认 1.5），结果 < 10 V，不会溢出 uint32。
     * 四舍五入到 1 mV：+0.5 后截断。 */
    float ratio = (s_cfg.div_r1_ohm + s_cfg.div_r2_ohm) / s_cfg.div_r2_ohm;
    float ao_mv = ((float) p_out->node_mv) * ratio;

    if (!(ao_mv > 0.0f))
    {
        ao_mv = 0.0f;   /* 理论不会发生（node≥0、ratio>0），防御 NaN */
    }
    p_out->ao_mv = (uint32_t) (ao_mv + 0.5f);

    /* ---- 3) 合理性检查：先判低轨，再判高轨 ----
     * low：ADC ≤ 3（节点≈0 V）。模块正常供电且探头接线正确时不会输出 0 V，
     *      所以更可能是模块没供电、AO 断线、或分压对地短路。
     * rail：ADC ≥ 4040（节点≈3.26 V → AO≈4.89 V），超过模块 0~4.5 V 标称范围：
     *      常见原因是分压比接错（例如漏了 2 kΩ 对地电阻导致 AO 直通）、
     *      R1 开路使节点被拉高、或 5 V 串进了 ADC 引脚（最危险，必须立即断电检查）。
     * 两种情况都返回 SENSOR_ERR_RANGE，上层按安全侧"传感器故障 → 排空"处理。 */
    if (raw_adc <= TS300B_LOW_ADC)
    {
        p_out->status = SENSOR_ERR_RANGE;
        return p_out->status;
    }

    if (raw_adc >= TS300B_RAIL_ADC)
    {
        p_out->status = SENSOR_ERR_RANGE;
        return p_out->status;
    }

    p_out->status = SENSOR_OK;
    return SENSOR_OK;
}
