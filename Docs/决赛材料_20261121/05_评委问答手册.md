# 评委问答手册（更新到 v2.8.0-LEVEL-M2g / 2026-11-21 夜）

> 用法：**不要背长答案**。每题记"一句结论 + 一个数字 + 一个出处"。
> 本手册已把 11/19 版里"液位在研、回波无效"的旧口径**全部替换**为当前事实。
> 红线：**不确定就说"这个我们没测，不编"**，然后给验证方法。

---

## 0. 三条底线口径（先说清楚，后面所有答案都服从它）

1. **判的是"相对本机清水基线的偏离"，不是绝对水质**——只测偏离，不测"是什么"。
2. **判不准就排空**；没有水中基线不回收；断线/失水一律排空。
3. **不声称**达到任何回用水标准、不声称识别污染物种类、不声称回收率。

## 1. 十二道必答题（各 30 秒版）

### Q1　你凭什么判这杯水能回用？

不靠绝对水质，靠**相对本机清水基线的偏离**。两路独立证据：电导增量看离子，浊度增量看悬浮物。

三档判级里，**只有连续 3 个 400 ms 块、也就是 1.2 秒都干净，才允许回收**；中间态一律排空。

实测：清水段电导增量在 −13 到 0 mV，门限 d1≈12 mV（4%×EC0）；典型皂液 +33 mV、浊度 +8%，两路同时越限，判 L2 排空。

### Q2　皂液主要是非电解质，电导率为什么会有响应？

洗手液里的阴离子表面活性剂、无机盐、防腐剂都提供离子；洗手过程还会带入汗液、皮脂（含 NaCl）。所以响应存在，但幅度不大——大约是本机基线的 5%~11%。

**这也正是我们用相对增量、不用绝对电导率的原因。** 对"只升电导、不升浊度"的冲洗水，我们只判 L1 不确定、排空，不硬标成肥皂。

### Q3　为什么不用绝对阈值？

同一台装置、同一杯清水，不同日期实测基线从 **258 mV 漂到 553 mV，差一倍**。绝对阈值换个地方就废。

而且阀位本身会改变电导：排空位、回收位、满水流动三个平台实测 **258 / 305 / 333 mV**，相邻差 28~47 mV。单基线会把"阀换向"误判成"水变脏"。

所以我们做上电自校准 + 分槽基线 + 百分比阈值，换水换地方重标 20~30 秒。

### Q4　三槽基线是不是过度设计？

不是。三个槽对应三个**物理状态**（阀在排空位 / 回收位 / 满水流动），不是拟合水质参数。

v2.6 之前用单基线，现场出现过整段误判 SOAP 和 1 秒周期横跳；改成按阀位选槽后，v2.7.3 现场两槽各自电导增量≈0，连续 14.6 秒稳定。

代价是满水槽要维持进水，现场不满足就 15 秒超时、保留两槽——这也是为什么系统允许只有两槽也能跑。

### Q5　三级分类 + 块投票会不会太慢？

慢在"确认"，不在"分类"。设计上是不对称的：

- **变脏立即**（L2 立即、L0→L1 需 2 块 0.8 秒）；
- **变干净要 1.2 秒**（连续 3 块）。

这是故意的安全侧。当前最大延迟是肥皂进入后约 1.6 秒才切排空，根因是检测延迟加投票，不是误判；下一步用"双证据立即 L2"可以压到约 0.8 秒。

### Q6　传感器坏了、没水了怎么办？

三类失效都有明确出口，且都通向排空：

- 探头断线 → 基线超量程 → `FAULT` → 排空；
- 浊度贴轨或为 0 → 有效性位清零 → `FAULT` → 排空；
- 失浸没（电导低于干态指纹）持续 300 ms → `DRY` → 排空。

**没有合法基线就不回收**；上电自检会重跑。

### Q7　回收水会不会污染自来水、被误用？

物理隔离：回收支路不与自来水管连通，独立回收桶 + 颜色标识（绿=回收、灰=排空），空气隔断防倒吸；用途限定冲厕、拖地、绿化，**不做接触性回用**。

我们没有做微生物、COD、余氯检测，所以**不声称达到任何回用水标准**。

### Q8　换个地方、换种水还准吗？每次上电都要标，实用吗？

换水主要影响基线绝对值，相对判据不受影响；上电自动标定 20~30 秒。

但实用性质疑我承认：**基线目前只在 RAM，掉电要重标**。这是下一步接数据 Flash 要解决的，不是已经解决。

### Q9　你的数据可信吗？做了多少次重复？

分层说：

- **现场日志**：11/16 诊断、11/19 清水、11/19 肥皂冲洗水、11/21 夜间四段，都是连续采集；
- **统计**：清水稳定段 max|ΔEC| 16.1 mV、p95 11.3 mV；
- **缺口**：阶跃重复次数不够，没有 20 次统计、没有混淆矩阵；仿真只是 50 ms 步长复刻控制逻辑，用来比版本差异，**不能替代实测**。

### Q10　最大的不足是什么？下一步先改哪个？

三条：① 腔体大，时间常数 30~200 秒，肥皂进入后约 1.6 秒仍可能漏一点；② 没有独立"有水"信号，靠电导推断（液位已接入但回波不稳）；③ 基线不持久、浊度未标定、酒精类双盲区。

下一步按收益排序：**杯中杯 + 立管（τ 降到 0.5~1.3 s）> 基线持久化 > 浊度标定 > 主路流量计量**。

### Q11　液位传感器现在到底能不能用？

分两层说，别含糊：

- **驱动和门控已经接入**：HC-SR04 用 IRQ6 双沿 + DWT 测脉宽，每 100 ms 一轮，串口输出 `mm / valid`；M2 起参与门控——液位在动时冻结基线微调，液位无效时自动回退到纯电导/浊度判据。
- **回波稳定性还不够**：11/19 曾稳定输出 53~144 mm；但 11/21 夜里的日志 `edge=0`，触发正常、回波没进来，怀疑 Echo 接线、泡沫或探头位置。

所以我们的口径是：**液位是门控的加分项和降级保护，不是唯一判据。** 它失效时系统不会停，只是失去一层保护。

### Q12　如果先放肥皂水再放清水，会怎样？

如果基线在肥皂水里采，会把肥皂当清水——结果是**欠回收**（该收的不收），方向是安全的。

所以标定链路有三道闸：干态指纹、标定期"水确认"（电导和浊度双证据）、标定后 5 mV 漂移校验；现场规程是**先排空、用清水冲 2~3 倍腔体，再标定**。

## 2. 深水区：评委可能追着问的 8 个硬问题

### D1　"你 11/21 这条 SOAP 是不是失水造成的？"（指着曲线问）

**是，也不是。** 失水瞬间浊度探头脱水，`dNTU` 会冲到 30%~60%，系统先判 L2 再进 `DRY`——这条我们在 11/19 的验证记录里就写了。

**动作仍然是排空**，所以不影响安全；影响的是"状态看起来跳了一下"。如果要消掉这条，可以在工况机里让"快速失水"优先于浊度判据，属于下一步的显示优化。

> 数据：11/21 日志里 84.4 s、220.6 s、539.4 s 三处都是这种脱水瞬态。

### D2　"你把 d1 从 5% 降到 4%，清水余量还剩多少？"

诚实答：**在 553 mV 那批水样上，余量从 11.6 mV 降到约 6 mV。**

- 553 mV 时 d1 = 4%×553 ≈ 22.1 mV，而清水最大正偏 16.1 mV，余量 6 mV；
- 但 11/21 这批 EC0≈301 mV，d1≈12 mV，清水正偏最大只有 −0.2 mV（没有正向越限）。

降 d1 的原因很具体：第二次稀释肥皂水 `dEC≈+14 mV`，在 5% 门限（15.8 mV）下会被判 CLEAR，降到 4%（12.6 mV）才拦得住。

**代价是"可能多排一点清水"，方向仍是安全侧**（少收，不会误收）。下一步用双通道联合判据把这个余量补回来。

### D3　"降级标定（CAL WARN）会不会把脏水当基线，然后一直回收脏水？"

会，如果操作者确认错了。这是**人工闸门**，我们不掩饰。

- 正常路径：电导和浊度双证据（AO 高于干态 80 mV）才允许采基线；
- 降级路径：液位确认有水 + 电导已明显高于干态，AO 偏低时也放行，但**打印 `CAL WARN`**，要求人工确认"这是清水"；
- 现场规程：标定前先排空、清水冲 2~3 倍腔体。

下一步是用浊度做标定期的脏水闸门，把人工确认变成自动拒绝。

### D4　"为什么不直接测浊度 NTU / 电导率 μS/cm？"

因为我们没有标定液，也没有恒温条件。**报绝对值就是编数据。**

我们报的是同一台装置、同一批水、相对于本机清水基线的增量（mV 和 %），这个量在"判该不该回收"这个问题上是充分的——因为我们只需要知道"比本机清水脏了多少"，不需要知道"脏到多少 NTU"。

### D5　"52% 是回收率吗？"

**不是。** 那是 v2.4.1 **仿真**里、阀处于回收位的时间占用水时段的比例，**是时间占比，不是水量**。

我们没有流量计，回收水量没有测。这也是下一步要加主路流量计的原因（现有 30~120 mL/min 量程太小、旁路分流比不稳，所以这次没接）。

### D6　"为什么 EC 单独升高不判肥皂？"

因为满水流动会把电导抬高 52 mV（FULL 平台 333 vs DRAIN 258）。如果电导单独越限就判肥皂，满水会被误判。

所以我们的规则是：**浊度单独超 9% → L2；电导超 9% 必须同时浊度超 8.1% 才判 L2；电导单独高只判 L1 不确定、排空。**

代价是"只升电导的弱皂液"标不成 SOAP，只能标 UNCERT——但动作一样是排空。

### D7　"三个人做的？各自做了什么？"

- **硬件/结构**：水路、腔体、电极安装、阀与继电器、供电与防水；
- **固件/算法**：采样链路、工况机、判级、投票、阀控制、OLED/串口；
- **数据/文档**：现场日志分析、阈值回填、验收记录、报告与答辩材料。

答辩分工：主讲、演示、数据/问答各一人；三人都会 30 秒版和前三个必答题。

### D8　"这套东西能落地吗？成本多少？"

**能落地的是"示范点位"，不是量产。**

- 成本：现有器件按赛前预算控制在 **800 元以内**（是预算上限，不是决算）；
- 场景：公共洗手台 + 中水桶，先做一个点位；
- 未验证：长期维护、电极结垢、合规（微生物/COD）、节水量的实际核算。

不承诺量产，也不承诺节水百分比。

### D9　"往届有人做过滤 / 材料路线，你们凭什么比他们好？"

**不比他们好，我们补的是另一个位置。**

公开可查到的先例是第九届水利创新设计大赛的《改性凹凸棒石三级滤层耦合重力驱动的洗手废水再生系统》（河西学院，二等奖）；同类的凹凸棒石过滤专利（CN213468060U）是**纯机械结构，没有电子判别、没有在线监测**。

他们解决"怎么把脏水洗干净"，我们解决"这杯水该不该洗"——前者是材料问题，后者是判别问题。我们不做滤料、不做全量净化，只做"判别 + 分流"这一层。

> 补一句更稳的：**"我们不贬低材料路线，它把水真的洗得更干净；我们只是先把不该洗的那部分挑出去，省掉无效处理的能耗和滤料。"**

### D10　"浑浊的尘土水为什么不回收？技术上不是最好判吗？"

**技术上最好判，但本项目里不值得回收。**

① 回用点是冲厕、拖地、绿化，**不在乎浊度，在乎皂液和油**；② 为它要把浊度升成主判据，等于重做整条标定；③ 最关键——**水浊到需要处理时，人眼比传感器判得准**。

**人眼看得出的脏，不需要我们判；本作品的价值在"人眼看不出的差别"上**，比如皂液、酒精这类透明污染。这也是我们以电导率而不是浊度作主判据的原因。

### D11　"你们能识别出污染物是什么吗？"

**不能，也不声称。我们只测"相对本底的偏离"，不测"是什么"**——这是我们的红线。

按物理化学类型分四类：A 电解型（皂基皂、汗液、锈水）看 ΔEC；C 颗粒型（泥沙、铁锈）看浊度；B 非电解型（酒精免洗凝胶）是**双盲区**；D 化学型（耗余氯）需要 ORP，没做。

所以说"判定为**含皂液特征的偏离**"可以，说"识别出皂液"不行。

### D12　"RA4M2 有硬件窗口比较、ADC 自诊断、片上温度传感器，为什么不用？"

三条都有明确取舍：

- **硬件窗口比较**适合固定阈值；我们的阈值随基线自适应（4% / 9% × EC0），用软件块投票更灵活，也更抗气泡——固定窗口反而会在换水后失效。
- **ADC 自诊断**没做，是欠账，已列入下一步（对应"传感器失效"那一项，目前用超量程与贴轨判据覆盖）。
- **温度**用 DS18B20 测的是**水温**，片内 TSN 测的是**结温**，两者不是同一个量；电导的温度补偿必须用水温，所以这里没有为了"用足外设"而牺牲正确性。

### D13　"你们说 1.5 秒时间预算，做到了吗？"

**端到端约 1.6 秒，略超。** 拆开是：检测延迟 + 1.2 秒投票确认 + 500 毫秒阀驻留。

取舍在 400 毫秒块投票——它是为了抗气泡与水锤，代价是延迟。量级上：单次洗手 10~30 秒、流量 4~8 L/min，**1 秒延迟约等于 70~130 毫升水分错方向**。

下一步做"变化率抢先触发"（先判"变了"再判"变成什么"），首次动作可望压到 0.8 秒量级。

### D14　"题目写的是'清洗尾水'，为什么演示的是洗手水？"

**清洗尾水是上位概念**：洗手、盥洗等轻度清洗排出的水，都还有回用潜力。洗手是其中最典型、也最难判的一种——它同时带入皂液、皮脂和悬浮物；如果洗手水能判，其余场景在**重新标定后**可以迁移。

所以我们只说"洗手场景已实测"，不说"所有清洗尾水已验证"。这两种说法的差别，就是我们的边界。

## 3. 快速问答（一行答法，20 条）

| 问题 | 答法 |
|---|---|
| 和感应水龙头有什么区别？ | 感应龙头判"有没有手"，我们判"水干不干净"；动作从"开关"变成"分流" |
| 和过滤方案比呢？ | 他们"不管脏不脏都处理"，我们"先判该不该处理"，省滤料、省维护 |
| 为什么选 RA4M2？ | 100 MHz Cortex-M33 + 12 位 ADC + 多路 SCI/I²C/GPIO，采集-判别-显示-记录刚好够，不需要 Linux |
| 用了哪些外设？ | ADC12 双通道（EC/浊度）、SCI9 串口、I2C0 OLED、1-Wire 温度、GPIO 阀、IRQ6+DWT 液位 |
| 跑 RTOS 了吗？ | 没有，50 ms 主循环 + 中断；任务都是非阻塞的 |
| 实时性怎么保证？ | 主循环 50 ms；阀在状态迁移后立即动作；液位中断优先级高于主循环 |
| 温度补偿怎么做的？ | DS18B20 测水温，电导折算到 25 °C；不用芯片内部温度（那是结温） |
| 为什么 OLED 用英文？ | 字库限制 + 现场可读性；`Clear/Soap/Uncert/Dry` 与串口状态一一对应 |
| 断电会怎样？ | 阀断电弹簧复位到排空位；上电重跑自检；基线丢失需重标 |
| 阀会不会频繁动作？ | 最小驻留 500 ms、单次最长 120 s；一次洗手仿真 4 次切换 |
| 电极结垢怎么办？ | 可拆洗 + 间歇采样；结垢会让基线漂移，所以有漂移校验和重标流程 |
| 功耗多少？ | 阀靠继电器吸合、保持时持续耗电；**整机功耗未实测，不编数字** |
| 为什么不做 AI？ | 没有 NPU/摄像头接口；两个物理量 + 状态机足够，而且可解释 |
| 创新点三条？ | ①相对基线 + 上电自校准；②分槽基线 + 双通道三级分类；③安全侧失效设计 |
| 回收水放久了会怎样？ | 有生物膜风险，所以只做杂用、演示当场排空，不做跨次储存 |
| 误回收率多少？ | 没有 20 次阶跃统计，不能给准确率；现有证据是清水不误判、皂液冲洗水被 L1 拦下 |
| 为什么不用流量计？ | 现有量程太小、旁路分流比不稳；先做液位，再选 0.1~1 L/min 串主路 |
| 三个人怎么分工？ | 硬件/结构、固件/算法、数据/文档；答辩时主讲/演示/问答各一人 |
| 如果给你一个月？ | 先做杯中杯 + 立管降 τ，再做液位标定，最后 Flash + NTU 标定；不先做 App |
| 你们和往届作品差在哪？ | 往届多是"过滤材料/结构"，我们补的是"在线判别 + 自动分流"的电子空位 |
